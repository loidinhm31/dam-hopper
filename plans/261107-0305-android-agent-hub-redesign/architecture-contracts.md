## C4 Canonical document identity and write authority
Canonical document key is collision-safe tuple `(profileId, normalized endpoint, authenticated account, workspaceId, workspaceEpoch, canonicalPath)` using server-provided identity; route target/access path and tab incarnation remain separate. Do not lowercase/strip leading slash or concatenate client paths to manufacture canonical identity. Same file via workspace/project/worktree aliases reuses one dirty document in the same logical owner; different server/account/epoch never aliases. File content baseline captures exact identity before read publication; preserve dirty buffer/undo on reconnect/retirement but withdraw authority. Rebind same-endpoint/account retained state only after fresh authorized identity; different endpoint/account/epoch cannot silently adopt dirty content. Retain CAS, bounded reads/watchers, OPAQUE fail-closed and media purpose/origin isolation. Missing FileIdentity cannot authorize a new editable baseline under the new flow. Project-only Git remains gated: unmarked workspace folder cannot send Git actions; no implicit project/root fallback.
Implementation ownership/lifetime: P01 additively freezes owner-owned holder lifetime and explicit alias/view leases plus identity-bearing load/save ports; P02 atomically migrates every EditorSession/EditorTabsState/ProjectWorkspaceState/factory/AndroidEditorDocument/Surface caller; P06 exercises shared factories and native lifetime locally; P07 wires existing retained ViewModel owner scope. Alias/tab/workspace close releases only its own references/listeners/exact view, never another alias document. Final dirty alias close uses existing save/discard/cancel guard and stays reachable on busy/cancel/failure; no silent unreachable dirty retention. Retained owner retires token then disposes native document exactly once only when aliases, active view leases, dirty retention and in-flight snapshots/saves are all zero. Retirement fences authority/stale callbacks but retains recoverable dirty/undo in process; no process-death recovery. Reload/discard/tier replacement is one canonical captured-revision/owner transaction, busy during save, with explicit dirty consent then revalidation; atomically publish successor to every alias and rotate all incarnations, failure/staleness preserves original. Single active native view per document; exact widget+lease detach may clean old widget resources only, never unsubscribe successor receipt, overwrite current view state, disable current input or dispose document. Same-content-response identity remains mandatory, no separate stat/read authority or new registry/runtime.

## C6 Terminal lifetime, close and uncertainty
POST create response carries numeric u64 incarnation plus original `X-DamHopper-PTY-Epoch`; Kotlin must decode numeric value exactly, retain originating epoch, and bind against fresh exact inventory before destructive authority adoption. GET `/api/terminal`/`detailed` headers: `X-DamHopper-Termination-Version: 1`, `X-DamHopper-PTY-Epoch` UUID; rows `incarnationExact` decimal string and terminationState. PTY manager epoch UUID, agent-status numeric serverEpoch, and workspace numeric epoch are DIFFERENT types/domains.
End Session/Cancel Restart only POST `/api/terminal/{id}/terminate` with exactly `{version:1,expectedServerEpoch:<lowercase UUID>,expectedIncarnation:<positive decimal u64 string>}`; <=512 bytes. 202 terminationRequested != observed exit; 200 restartCancelled != observed process exit. 409 mismatch/refusal stays on original target, no retarget/retry. Remove active Android legacy DELETE kill/remove callsites, not server routes. Missing protocol disables End, not local Close View. Local Close hides a qualified view only, never kills/evicts remote process; provide explicit reopen from inventory, live/hidden/restartPending count toward workspace-dismiss safety.
Create intent admission/settlement retained by existing owner state, UUID per explicit intent; lifecycle/background/rotation never retries create. Process death cannot erase ambiguous dispatch evidence into permission to replace (persist minimal nonsecret identity/outcome through existing storage port, never terminal output/command/password). Unknown create cannot clear from timeout/list absence/local task cancellation/retirement alone; require exact original success or proof original cannot still succeed. No blind same-ID replay, replacement fallback, TTL or Launch Again recovery button. If server cannot prove noncreation, keep blocked explanatory state; do not invent proof/cancel API.
