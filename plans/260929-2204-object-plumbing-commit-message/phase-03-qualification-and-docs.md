## Architecture

### Concrete fixture notation

In each disposable fixture capture **full** OIDs: target `T0`, branch tip `H0`, remote destination `R0`, unrelated branch/ref `U0`, index raw bytes `I0`, staged/unstaged/untracked bytes `W0`, and target/descendant raw trees/messages/header blocks. Local success yields `T1`, `H1` with branch=`H1`, response `hash=T1`; `H0 != H1` and, for older selected target, `T1 != H1`. Before explicit publish remote=`R0`; after matching lease remote=`H1`. For no-op `T1=T0`, `H1=H0`, `rewrittenCount=0`, `signaturesRemoved=false`, branch reflog unchanged. `U0`,`I0`,`W0` stay equal unless the scenario explicitly mutates them externally. Use `git cat-file -p`/`git rev-parse`/`git show-ref`/raw file comparisons as independent oracles, not the API response echoed back.

## Risk Assessment

- Running Git against user's repository would risk history loss: use independent temp projects/bare remotes only; never force-push real shared history. Isolate service/no-auth on loopback, test credentials and ports.
- A mock/CLI-only pass can hide libgit2 callback reversal or late remote updates: require real git2 and remote independent ref checks. A disconnected transport can have published remotely: `unknown` triggers inspection, never blind retry.
- User-modified `docs/system-architecture.md` or host-resource-SSE artifacts could be overwritten by broad edits/cleanup: surgical Git-section edit and scoped temp cleanup only.

## Security Considerations

- API ownership and selected root/worktree cannot be derived from client-visible project name alone; cross-profile and nested-root tests assert server resolver. Secret-bearing remote URL not echoed/logged; verify remote identity changes are detected after preview.
- Signed commits are never silently de-signed; malformed commit bytes and shallow history fail closed. Ref/OID/refspec input validated, no shell interpolation; callback rejects unexpected refs before transfer. Existing drop/undo/reset/revert protections untouched.
