# Published commit-message editing: research and corrected decision

Status: assessment only; no application changes or tests run here. [Architecture contract](../architecture.md) supersedes earlier alternatives in this report. [Object-rewrite research](./object-rewrite.md) and [disposable CLI smoke](../reports/plumbing-smoke.md) support feasibility, **not** a qualified Rust/libgit2/browser implementation.

## Current implementation (not desired behavior)

- `server/src/api/router.rs:231-232`, `server/src/api/git.rs:694-725`: `POST /api/git/{project}/commit/{hash}/message` takes `message`, optional `worktreePath`/`root`; it only changes local history. `commit_file_ops.rs:486-588` amends HEAD or checks out, amends and rebases older descendants. The manually resolved merge fixture at `server/src/git/tests.rs:1762-1797` conflicts under that rebase. Metadata-only intent does **not** make replay of merges conflict-free.
- `commit_file_ops.rs:163-220` currently rejects dirty and cached-pushed targets; for **new message operation only**, both gates must go. Dirty staged/unstaged/untracked files are **allowed**; preserve bytes, index and current tree without checkout, reset, stash, amend or rebase. Other operations keep their independent dirty/pushed guards. Active-operation, detached, unreachable and incomplete/unsupported ancestry must still block before ref publication; malformed/truncated parent graphs must **not** be treated as roots.
- `repository.rs:207-230,1418-1498`: `GitLogEntry.isPushed` derives from a local upstream-tracking ref; neither live remote state nor all-sharing detection. Remove it as a message-edit eligibility/publish gate. Keep drop and undo protections unchanged.
- `repository.rs:376-433,611-654`: push derives branch remote and merge ref from branch config; normal refspec has no `+`, force mode uses unconditional `+`. `git.rs:187-224` exposes `force` boolean; `packages/ui/src/api/queries.ts:1471-1509`, `client.ts:2019-2024`, `ws-transport.ts:339-358` forward it. UI-accessible Force Push currently calls this bare-force path from `WorkspaceGitPanel.tsx`, `GitPage.tsx`, and `ProjectInfoGitSection.tsx` via `ProjectInfoHelpers.ts:39-56` and `GitForcePushDialog.tsx`. It must be **replaced** with exact lease confirmation, not retained as a second unsafe option. Normal Push stays fast-forward-only.
- `GitLogTree.tsx:51-59,107-116` and `GitHistoryActions.tsx:862-901` prohibit editing if `isPushed`; `WorkspaceGitPanel.tsx:605-620` separately limits editing to the active branch. GitPage edit handling is at `GitPage.tsx:529-535,681-694,747-755` and currently uses default root. `packages/ui/src/api/client.ts:2226-2237,3156-3161`, `queries.ts:1309-1321`, `ws-transport.ts:1049-1065` carry message edit through the owner-bound target. Preserve target/root/worktree/profile ownership on all new requests and callbacks.

## Chosen split contract (supersedes earlier proposal below)

1. **Local edit, regardless of pushed status:** paired existing `GET .../message` returns `{message,branch,headOid}` from one selected worktree/root snapshot; UI freezes it with target OID/owner/root, and same `POST .../message` sends `message`, REQUIRED full-ref `expectedBranch`, REQUIRED full `expectedHeadOid`, optional `allowSignatureRemoval` default false, existing `worktreePath`/`root`. Success names `{hash:newTargetOid,oldTargetOid,newTargetOid,oldHeadOid,newHeadOid,branch,rewrittenCount,noOp,signaturesRemoved:boolean}`. Use raw ODB DAG rewrite and local git2 HEAD+branch lock, re-read HEAD and branch tip under locks, set branch only; do **not** use failed CLI symref-verify transaction. Preserve trees, metadata, manual merge trees and untouched headers/messages; do not rebase or surface new rebase-recovery state. An already-active operation may return existing recovery info; this rewrite must never initiate one. Signatures need explicit consent to remove; unsupported encoding/malformed or truncated ancestry blocks. Dirty state is not a blocker. Local success survives any later publication outcome.
2. **Prepare publish:** independent, on-demand action after any local rewrite or existing Force Push control, **not** conditional on cached `isPushed`. Resolve selected project/worktree/root and actual branch remote/ref and effective push URL; use authenticated remote advertisement to capture exact remote ref OID. Snapshot bound branch/local source OID, remote identity/config and destination ref/OID. No assumed `origin` or branch-name equality. Missing/ambiguous destination is actionable and never guessed; preview does not push.
3. **Explicit publish:** confirmation states exact destination and warns it publishes the **entire** captured branch including other local commits. Re-resolve ownership, HEAD/branch, source tip, remote identity/config; reject stale source/config. Use one `+<fixed source OID>:<exact destination ref>` refspec and existing git2 SSH credential, pack/transfer progress and rejection callbacks. In `git2 0.19`, `PushUpdate.src()` is the **remote old** OID and `dst()` is the **proposed new** OID; compare all update entries and refuse any extra/mismatched ref, old OID, or new OID before sending. Receive-pack still enforces its own checked update; qualify against real bare remote. An SSH-key retry reuses the **same frozen request**, never a refreshed preview. Remote advancement requires another preview **and** confirmation. If transport outcome is uncertain, check advertised state before permitting another attempt; never auto-retry after the write may have reached remote.
4. **User-facing outcome:** maintain local edit success independently from `published`, `already-current`, `stale-remote`, `stale-local`, `stale-config`, `rejected`, `auth-required`, and `unknown` publication states. Do not roll back local edit, do not silently retry another source or remote old OID, and do not claim a failed transport proves remote remained unchanged. An already-current remote OID equal to captured source is a publish no-op, not a forced update. No durable receipt store, generic rewrite engine, extra dependency or new framework.

## Qualified vs unqualified evidence

- [CLI smoke](../reports/plumbing-smoke.md) observed a raw-object rewrite of a published root, both ordered merge parents/manual resolution, side-only descendants, exact staged/unstaged/untracked bytes, no-op, local CAS failure, ordinary push rejection, successful explicit lease and stale-remote rejection in disposable local/bare repos.
- **Standalone git2 qualification, separate from app:** disposable compiled Rust crate with git2 0.19.0 successfully locked `HEAD` and branch, re-read symbolic HEAD/tip, wrote **only** branch and rejected symbolic HEAD switch/same-OID switch/stale tip, preserving dirty bytes. CLI `symref-verify HEAD` plus branch update failed duplicate HEAD update and is **not** chosen. A second compiled git2 probe executed actual `remote.push([+FULL_OID:refs/heads/main])` to disposable **local bare remote**: one negotiation callback, `src()` remote old, `dst()` local new; matching update published, stale remote old rejected after independent advance with remote advance preserved. These do **not** qualify production application Rust, SSH/HTTPS credentials, post-negotiation receive-pack races, live API/browser, or ambiguous push URL handling. Phase 02 targeted product tests/smoke precede phase 03 full gate; parent CLI and standalone probes are only prior evidence.
