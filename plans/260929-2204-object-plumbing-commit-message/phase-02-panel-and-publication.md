## Key Insights

- `isPushed` is cached local remote-tracking ancestry, not a live remote lease. Do not condition local editing, preview or publish on it; do not weaken pushed guards for drop/reset/revert/undo.
- Existing push target uses `branch.<name>.remote` + `branch.<name>.merge`, not necessarily `origin` or same local/remote branch name. Existing `force=true` path emits bare `+` with no expected old ref. Existing `make_push_opts` supplies SSH credentials, progress and rejection callbacks; reuse it.
- Parent's separate disposable **Rust git2 0.19.0 / local bare remote** probe exercised actual `remote.push([+FULL_OID:refs/heads/main])`: exactly one negotiation update with `PushUpdate.src()` = remote old and `.dst()` = proposed new; matching lease published and stale remote-old rejected after independent advance. This is **not** application code, SSH/HTTPS credentials, browser or post-negotiation receive-pack race qualification; keep production gates.
- Dirty staged/unstaged/untracked state is allowed for **message edit**; no checkout/rebase/recovery from this new operation. A separate active operation still blocks. A local edit may succeed despite stale/failed/unknown remote publication; never roll it back or silently push.

## Requirements

Compare normalized newline consistently with server; no-op never prompts signature removal. Change only edit-specific pushed gate; keep drop/undo/reset/revert policy.
3. Publish is independently initiated, on demand, after local success or existing Force Push controls; preview obtains live remote advertisement. Confirmation names selected profile/project/worktree/root, local branch/source OID, remote name and destination full ref/old OID, warns **whole captured branch including other commits** replaces destination history. 4. Normal Push remains fast-forward-only. No reachable bare `force:true` endpoint/caller or alternative unsafe force button; existing Force Push buttons use this **same** preview/dialog/publish contract. 5. Keep request ownership, SSH authentication and push progress/rejection behavior; cached fetch never updates an approved lease. On stale source/config/remote require **new prepare and new confirmation**; credentials retry sends the **identical** approved snapshot and only if auth failure is known to precede any write. Unknown remote outcome is not a local edit failure.

## Architecture

### Exact wire contract (camelCase JSON; Rust serde + UI TS mirror)

| Endpoint / method | Request | Response |
|---|---|---|
| `POST /api/git/{project}/push/prepare`; `git:prepareLeasedPush` | `{worktreePath?:string,root?:string}` (project path segment; owner/profile resolved by bound client) | `PublishPreview = {status:"ready",snapshot:PublishSnapshot,alreadyCurrent:boolean} \| {status:"blocked",reason:"detached-head"\|"missing-upstream"\|"ambiguous-destination"\|"missing-destination"\|"remote-unavailable"\|"auth-required"\|"stale-preview",message:string}`. Prepare has **no** remote mutation. |
| `POST /api/git/{project}/push/publish`; `git:publishLeasedPush` | `{worktreePath?:string,root?:string,snapshot:PublishSnapshot}` | `PublishResult = {status:"published"\|"already-current"\|"stale-remote"\|"stale-local"\|"stale-config"\|"rejected"\|"auth-required"\|"unknown",branch:string,remoteName:string,destinationRef:string,sourceOid:string,expectedRemoteOid:string,actualRemoteOid?:string,message:string}`; `auth-required` only when known pre-write. All non-success states preserve local edit. |

`PublishSnapshot` **all mandatory**: `{branch:string,sourceOid:string,remoteName:string,destinationRef:string,expectedRemoteOid:string,remoteIdentity:string,repositoryIdentity:string}`. `destinationRef` is full `refs/heads/...`; OIDs are full normalized repository-width hex (never seven-character UI abbreviations). `remoteIdentity` = SHA-256 hex of **effective push URL bytes**, not URL exposed to UI (which may contain credentials); `repositoryIdentity` = SHA-256 hex of canonical resolved worktree gitdir + common gitdir + selected root path, length-delimited to avoid collisions. `project`, `worktreePath`, `root` stay **outside** snapshot in request and are captured with it in UI as immutable owner-bound target; the server re-resolves their authoritative paths and recomputes repository identity. No sender-supplied remote URL or refspec is executed. Snapshot is a captured comparison value, not an authorization token or a durable receipt. Retain the selected connection owner/profile generation client-side; profile ID stays in `toWireTarget` owner binding, not REST JSON. Return a sanitized `remoteName`/`destinationRef` display; do not log raw credential-bearing URLs.

**Prepare order:** resolve `ProjectTargetRef` and selected VCS root with existing helpers → require attached HEAD pointing at one branch with local tip `sourceOid` → reuse `resolve_push_target` branch remote + merge ref; reject missing branch/merge, non-`refs/heads/` destination, mirror/wildcard/multi-push-URL or otherwise ambiguous mapping (no `origin` guess) → resolve the **effective** URL that the actual git2 push remote will use (`remote.pushurl()` if present, else `remote.url()`; account for Git URL rewrites/multiple push URLs and fail closed if one effective endpoint cannot be proved) → hash that effective endpoint, capture repository identity → authenticated remote connect/list advertising exact destination ref, **not** remote-tracking or `isPushed`. If that exact remote head absent return `missing-destination` (no guessed creation); if present capture `expectedRemoteOid`. Recheck branch/ref/config/root identity after network read; if changed return blocked stale-preview message, rerun prepare. `alreadyCurrent` iff advertised remote OID equals captured `sourceOid`; show already published and disable confirm; never send a `+` update for this case.

**Publish order and precedence:** resolve current authorized target/root and repository identity (mismatch → `stale-config`) → re-resolve attached branch/upstream/effective push endpoint/ref, compare **every** snapshot config/destination/identity field (`stale-config`) → compare current branch OID with snapshot source (`stale-local`) → only then connect git2 push with captured remote object and exact source/destination; do not recompute/rewrite snapshot fields or use branch name as source ref. For already-current snapshot (`expectedRemoteOid == sourceOid`), re-advertise; if still equal return `already-current` without push, else `stale-remote`; vanished destination (remote ref changed to absent) → `stale-remote`, ambiguous/multiple push URLs → `stale-config`, never fallback. Changed remote at push negotiation → `stale-remote`; definitive ref rejection → `rejected`; transport error after negotiation or uncertain write → `unknown` and inspect live remote before a new preview. `actualRemoteOid` only when confidently advertised; callbacks never replace `expectedRemoteOid`. Source change between validation and negotiation → `stale-local`; fixed OID refspec ensures a later local commit cannot be silently sent. No global atomicity claim against external Git or server-hook behavior.

**Negotiation gate (pseudo-code; production qualifier in phase 03):**

```text
refspec = "+" + snapshot.sourceOid + ":" + snapshot.destinationRef
options = make_push_opts(existing project/progress/SSH credentials/rejection sink)
options.callbacks.push_negotiation(updates => {
    if updates.len() != 1: abort("unexpected-updates")
    u = updates[0]
    if u.dst_refname() != snapshot.destinationRef: abort("unexpected-ref")
    // Installed git2 0.19: src = remote OLD; dst = local NEW.
    if u.src() != snapshot.expectedRemoteOid: abort("stale-remote")
    if u.dst() != snapshot.sourceOid: abort("stale-local")
    if resolved_root/HEAD_branch/branch_tip/remote_identity changed: abort("stale-local/config")
    allow
})
remote.push([refspec], options)   // receive-pack performs its own checked ref update
```

If git2's callback cannot enforce old OID under push races or transport behavior, **stop shipping**, not degrade to bare force. Existing `push_update_reference` status and pack/transfer callbacks remain; record exact classified failure, not `success` after an unexpected update. `remote.push` returning success does not justify a claim for a ref other than the selected destination.

**Client/transport signatures (implement consistently):** `GitClient.git.commitMessage(target:ProjectTargetInput,hash:string,root?:string):Promise<{message:string,branch:string,headOid:string}>` consumes phase 01 enriched paired GET; `GitClient.git.editCommitMessage(target,hash,{message,expectedBranch,expectedHeadOid,allowSignatureRemoval?},root?):Promise<GitActionResult>` sends exact frozen fields. `GitClient.git.prepareLeasedPush(target:ProjectTargetInput,root?:string):Promise<PublishPreview>` and `.publishLeasedPush(target:ProjectTargetInput,snapshot:PublishSnapshot,root?:string):Promise<PublishResult>` invoke `git:prepareLeasedPush` and `git:publishLeasedPush` with `{...toWireTarget(target),root}` / `{...toWireTarget(target),root,snapshot}`. `ws-transport.ts` maps to REST `POST` (project encoded in URL; only `worktreePath`,`root`,`snapshot` in JSON body); paired GET already maps worktree/root query, edit WS body forwards **all** POST fields. `useGitCommitMessage` returns **structured** GET data (not current string-only `.message`) and fetches a fresh snapshot on **each dialog opening** (remove current `staleTime:Infinity`, force refetch; never submit with cached data while fetching). `useGitEditCommitMessage(target,root)` input `{hash,message,expectedBranch,expectedHeadOid,allowSignatureRemoval?}` invalidates scoped branch history only on `ok:true`. `useGitPrepareLeasedPush(target,root)` mutation is on demand/no stale cache; `useGitPublishLeasedPush(target,root)` accepts immutable snapshot, invalidates branch/log/project status on `published`/`already-current`, never replaces snapshot after failure. All resolve bound owner from normalized target and retain target-unavailable handling.

**Credential handling:** preserve `use-git-with-ssh-retry.ts` passphrase/key-load dialog and its `isCurrentConnection(owner)` fence; add typed leased-prepare/publish executor using existing hook state, prompting/replaying **only** `auth-required` known pre-write results. Current `executeWithRetry` only understands `GitOpResult` and string-matched errors: do not cast `PublishResult` to generic push success or retry `unknown`/`rejected`. Closure passed to retry executor captures immutable snapshot and selected target/root/owner at confirmation, never calls prepare on retry. Prepare auth retry may rerun **prepare** before any confirmation and supersedes old preview; publish retry reuses identical snapshot so negotiation returns stale if remote moved. On owner-generation/root/project switch, cancel outstanding prompt/response and clear preview.

**UI state transitions (single shared dialog, no automatic next step):** `closed --click Force Push or explicit Publish rewritten history--> preparing --ready && !alreadyCurrent--> confirming --confirm--> publishing --published--> published`; `preparing --alreadyCurrent--> already-current (no confirm)`; `preparing --blocked/error--> blocked`; `confirming --cancel--> closed (local edit intact)`; `publishing --auth-required pre-write--> SSH prompt --> publishing SAME snapshot or canceled`; `publishing --stale-remote/stale-local/stale-config--> stale (disable old confirm; manual refresh starts new prepare)`; `publishing --rejected--> rejected`; `publishing --unknown--> unknown (disable retry; inspect advertised remote then manually preview/reconfirm)`; owner/scope change in pending state → closed and stale callback ignored. Preserve separate local edit outcome: `ok:true` banner with new target/tip/`signaturesRemoved`; phase 01 `publication-uncertain` means **local branch commit outcome uncertain**, not success nor remote `unknown`—disable publish pending branch re-inspection, never auto-edit/retry. Action \"Publish rewritten history\" opens prepare but is never auto-clicked. Preview/publish failure never changes a definite local-success banner to \"edit failed\". Local no-op displays \"No changes\" and never auto-publishes; explicit Force Push stays independently available.

**Shared UI owner:** create one focused `packages/ui/src/hooks/use-leased-git-push.ts` hook called once per mounted `WorkspaceGitPanel`, `GitPage` toolbar and `ProjectInfoGitSection`: `useLeasedGitPush(target:ProjectTargetInput,root?:string)` returns `{state,preview,result,error,prepare():Promise<void>,publish():Promise<void>,close():void,passphraseDialogProps,sshStatus}`. It owns prepare/publish mutations, owner-generation+target/root key, frozen approved snapshot, transitions above and typed pre-write SSH retry via existing `use-git-with-ssh-retry.ts`; on key/scope change it clears snapshot and ignores late completions. `GitForcePushDialog` is a **pure shared view** of this hook state (same props at all three callers), not another API requester; `GitHistoryActions` owns local edit-only status and can render explicit publish CTA that calls its parent hook `prepare` after definite success. Keep hook local to each mounted surface (no global receipt/cache); this single implementation prevents three divergent retry/lease state machines.

## Success Criteria

- Local dirty/pushed/unpushed edit succeeds offline on attached selected branch with required expected branch/HEAD; no remote operation until separate user confirmation. No stale result paints another panel.
- Preview displays live exact destination and OIDs; absent/ambiguous/multi URL blocks; already-current does not push. Only one intended full-ref/old-OID/new-OID update can negotiate, no other refs changed. Stale remote/local/config rejects without fallback.

## Risk Assessment

- Libgit2 OID callback naming and remote write race are non-obvious: qualify with actual bare remote, extra-ref injection/rejection and concurrent update in phase 03; stop if a race bypasses the lease.
- Existing SSH hook's string error matcher can misclassify late transport failure as auth; typed `auth-required` only pre-write prevents duplicate push. URL rewrites/multi push destinations can invalidate preview: fail closed rather than pick first.
- A profile/root switch may strand pending dialog with another user's snapshot: bind to owner generation and selected target/root; ignore stale callbacks, then require new preview.

## Security Considerations

- Only authenticated project/worktree/root resolver chooses repo; never trust client-provided URL, arbitrary ref or path. Validate full branch ref and OIDs before constructing refspec; avoid shell interpolation and URL credentials in responses/logs.
- Callback lease is concurrency safeguard, not server-side proof user clicked a dialog; preserve existing authorization on both routes. Remote hooks/rejections and indeterminate transport are never reported as success. Existing destructive history protections remain independent.
