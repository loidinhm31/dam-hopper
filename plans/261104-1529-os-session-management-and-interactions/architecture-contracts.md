- `kill_internal_impl` mutates killed/pending/fleet before selecting live (`:2956-2991`); do NOT preflight then call it by bare ID. `remove_with_expected` allocates before checking (`:2270-2294`), so it is not a no-op-on-refusal template.
- `create_with_buffer` holds persistence gate, admits pending identity then publishes under inner with replacement/generation checks (`:1491-1555,1712-1748`); respawn admits pending replacement under inner (`:4302-4348`). The guard must reject stale/pending selection before mutation at the same inner-lock boundary, preserving lock order.
- `LiveSession::terminate()` is best-effort, returns no result, signals reader shutdown before attempting process kill, logs errors (`server/src/pty/session.rs:269-299`). It does not prove actual exit. Reader `child.wait` plus exact ownership checks publishes tombstones (`manager.rs:3218-3291`); bare-ID terminal exit notifications are invalidation hints, not sufficient identity proof.
- Existing terminal inventory handler returns an array (`server/src/api/terminal.rs:327-336`); preserve its body for unrelated clients. CORS already has explicit exposed headers (`server/src/api/router.rs:696-741`). `ws-transport.ts:3156-3194` is the HTTP response decode boundary.
- Reject scout proposal to extend privileged host-actions capabilities and its broad new TransientLayerRegistry recommendation. Reuse terminal-local protocol metadata and existing accessible primitives with a small explicit shell input-state seam.

## C1. Terminal guard wire and original observation authority

1. A PTY-manager-lifetime UUID (`serverEpoch` in this terminal contract) is immutable and shared by manager clones; regenerated when that authority is constructed. Never persist it or borrow SessionChanges/AgentStatus epoch semantics.
2. Existing authenticated `GET /api/terminal` and `/api/terminal/detailed` return additive headers `X-DamHopper-Termination-Version: 1`, `X-DamHopper-PTY-Epoch: <uuid>`, `Cache-Control: no-store`. Expose the two custom headers through existing CORS. Preserve arrays, every legacy numeric field and detailed `buffer_bytes`; add flat `incarnationExact` and `terminationState` to every row. Freeze final header casing case-insensitively; no ambient global last-seen epoch cache.
3. Transport attaches decoded capability/epoch to the SAME inventory observation before query publication. Keep old array API behavior where needed; add a typed observation API/query projection without a second network request/poll loop. The plan must name the exact typed shape and all consumers. Never combine an old session row with a newly fetched epoch; capability GET or per-target GET cannot supply missing authority retroactively.
4. Snapshot identity is immutable `{profileId, generation, serverEpoch, terminalId, incarnation}`; target incarnation is the original row's canonical positive-u64 `incarnationExact` string (max `18446744073709551615`). It is authoritative even when legacy numeric incarnation is unsafe. Missing/malformed exact string never downgrades to numeric; a safe legacy number must agree losslessly, unsafe numeric cannot prove equality or disagreement. Unsupported/missing/malformed headers or identity disables End with accurate guidance; compatibility rows remain readable.
5. New authenticated `POST /api/terminal/{id}/terminate`, bounded strict JSON `{version: 1, expectedServerEpoch: string, expectedIncarnation: string}`. Reject unknown/missing fields, invalid UUID/canonical positive-u64 decimal and unsupported version. `profileId`/generation stay client-only. Existing terminal auth/CORS protections apply. Keep legacy DELETE endpoints for unrelated existing clients only; safe web never falls back.
6. Freeze typed errors in phase 01: invalid request/version (400), missing session (404), epoch/incarnation mismatch, pending replacement, not-live/not-pending or lifecycle conflict (409), signal failure (500), oversized body (413), existing auth/media-type failures. Successful exact live request ->202 `outcome:"terminationRequested"`; exact dead pending restart cancellation ->200 `outcome:"restartCancelled"`. Both echo canonical string identity. Unknown network outcome remains separate; neither 202 nor raw `alive:false` proves completed End.
7. API-only `TerminalInventoryRowDto` flattens `SessionMeta` plus `incarnationExact:string`, `terminationState:"live"|"terminationRequested"|"restartPending"|"restartCancelled"|"exited"|"unavailable"`; detailed projection alone includes existing `buffer_bytes`. Both handlers use `PtyManager::termination_inventory_snapshot(include_buffer_bytes:bool) -> TerminalInventorySnapshot {server_epoch,rows}` once per request, under one `inner` snapshot, then serialize outside lock. Internal rows carry cloned meta, exact u64, state and optional buffer bytes; not two list/state queries. Keep internal `list/list_detailed` callers compatible; do not persist API authority fields or change SessionMeta.
8. Projection uses exact live/request marker or exact dead/fleet pending/cancellation marker. Pending replacement or closing/handoff/unverified state ->unavailable before actionable projection. Exact cancellable dead source ->restartPending even though `alive:false`; retained cancellation marker ->restartCancelled; proven ordinary process exit ->exited. Unavailable/rehydrated/lack of proof never becomes exited by label inference.

## C2. Atomic selection, requested versus ended, and web migration

- Under existing lock order, check expected epoch, current identity, closing/handoff constraints and pending replacement before modifying allocator/killed/pending/fleet/live/dead/persistence/status/ports/process state. Refusals are entirely non-destructive. Pending create/respawn conflicts; do not cancel an admitted newer replacement, even if an old live row still matches.
- Endpoint ends the captured session lifetime: live signal request OR exact dead restart/backoff cancellation, never an admitted replacement. Exact tombstone `will_restart` plus matching fleet pending and no pending replacement is cancellable. Atomically set source restart disabled, clear delay, exact-cancel fleet pending and record `restart_cancelled` on that retained DeadSession; preserve history/tombstone and original process exit. No process signal, raw-ID killed marker, eviction or new persistence column. Duplicate completed cancellation refuses without mutation; inventory marker survives for that exact tombstone lifetime.
- Keep existing `respawn_source_is_current` as exact-source base; split admission (source current + restart enabled + matching fleet pending + no pending replacement) from publication (source current + exact replacement reservation + fleet creating + lifecycle/generation). Queue/timer wakeups and pre-reservation checks use admission; stale cancellation wakes are no-ops. Publication MUST NOT require pending entry consumed at reservation. Cancellation before reservation wins; reservation first ->409 with no effect. Normal respawn must still publish.
- Fence pre-reservation asynchronous validation FAILURE as well as successful admission. `supervisor_loop` may await target validation and bypass reservation on error (`manager.rs:3597-3607,3645-3697`); `finish_respawn_source_failure` currently checks only pending/incarnation (`:3763-3797`). After await, authorize failure transition under existing lock order only while exact restart ownership remains active and uncancelled. Cancelled/superseded work must not mutate/persist tombstone/target-unavailable state or emit final-exit/workflow effects. Emit `TerminalFinalExit` only from an accepted failure transition, not before its guard. Preserve distinct post-reservation failure fencing; do not require consumed pending state there. Deterministic target-validation barrier: cancellation wins, delayed validation fails with target loss, cancellation marker/projection/history remain and no stale persistence/workflow effect occurs.
- Add narrow fallible signaling for guarded live termination rather than best-effort `terminate()` as proof. On success inhibit restart only for captured live identity while retaining live ownership; successful reader wait+exact shutdown/incarnation ownership alone finalizes exit. No fabricated tombstone or lock across await/wait; failed wait stays unresolved. No broad supervision redesign.
- UI action state records immutable target AND `origin:"live"|"restartPending"`: captured -> confirming (initial Cancel focus) -> dispatching -> terminationRequested -> ended for live, OR dispatching -> restartCancelled for pending restart; refused/failed/outcomeUnknown stay explicit. Exact 200 cancellation immediately completes pending-origin End; later same exact `restartCancelled` inventory resolves lost cancellation response. Live-origin 202/loss completes only on exact authoritative exited observation. Ordinary exited/raw `alive:false`/absence cannot resolve pending-origin loss; cancellation marker cannot substitute for live exit. No auto-retry/retarget, and a bare-ID exit only invalidates/refetches.
- Every affected web Kill/End caller migrates: SystemMonitor, use-terminal-manager, use-ports/PortsPanel, typed client/transport command mapping, new frame/window-list prompts. Audit `terminal.remove` because it also kills. Explicit terminal Close must stop calling durable remove; no kill-then-evict sequence, no automatic tombstone eviction. Keep unrelated server DELETE compatibility, not unsafe reachable web aliases. Dead/unreachable old-web paths can be removed only after caller evidence proves obsolete; no legacy shell resurrection.
- Shared explicit Close controller is invoked by frame, pane/window-list and affected controls. Live OR verified restartPending gets Close view / End session / Cancel; End explains signal vs pending-restart cancellation. Unknown/disconnected/unsupported identity offers presentation Close/Cancel with End disabled. Exact exited or restartCancelled is presentation-only Close; programmatic cleanup, minimize and desktop movement/removal never End.

## C3. Hub, placement and Review

- Inventory is existing aggregate terminal data, joined to agent observations, not filtered to them. Filters All sessions / Agents / Background; Background = no open qualified window anywhere. Minimized and other-desktop windows are open, not Background. Unobserved != shell/idle/safe to kill. Preserve project grouping, urgency, owning server labels and Cognito masking.
- Open beside is a qualified intent carrying source Hub window ID plus captured terminal identity and explicit `focus-existing | open-beside | move-beside` action. Do not use raw-ID matching. Reuse/restore same-desktop ordinary view; background opens an ordinary terminals window for existing PTY without backend create. Other desktop offers Go to window or explicit Move beside. Additional sessions tab in adjacent pane; preserve unrelated tile topology. Integration owner settles exact intent/types/store operation in phase 01 before branches consume it.
- Placement keeps SAME xterm and ZERO extra attach/replay/reset. Close/reopen may dispose/recreate/replay but backend PTY remains same. No second renderer or duplicate claims. Reopening missing or replaced session refuses rather than creates.
- Review resolves existing owning-server config + metadata-only Status. Identity includes originating `{profileId,generation}`, exact terminal incarnation, OMP capture ID, SessionChanges serverEpoch and verified non-null rootId/baselineId. This epoch is NOT C1 PTY epoch. Never stringify rounded agent identity, guess `.` or fill generation from a new connection. Join legacy numeric agent evidence only when positive safe integer equality to inventory exact string is proven; unsafe agent identity leaves agent/Review unavailable without hiding inventory or disabling otherwise valid exact End. Status's existing string identity must match exactly; no broad producer/protocol expansion.
- Revalidate before dispatch/after await; exact tuple opens/focuses read-only viewer. Explicit loading/disabled/unsupported/missing/disconnected/retired explanations; exact Server Settings link, no automatic tracking enable. Disable/retirement/disconnect unmounts live viewer, cancels requests and purges protected identity/owner data even for hidden windows, while content-free explanation may remain. Ordinary single-view close cancels/purges only its own identity and preserves active siblings. Query identity/claim matching must include all authority components needed by existing metadata API.
