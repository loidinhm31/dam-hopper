# Agent eligibility research — Host Resources automatic sleep

Planning only; static source inspection. No application edits, tests, builds, formatters, or suspend executed. Required planning skill read from `~/.omp/agent/skills/planning/SKILL.md`; worktree `.omp/skills/` and `docs/development-rules.md` absent. Main owns architecture/final phases.

**Validation supersedes proposals:** user selected DamHopper-managed terminals only. Host-wide discovery/external enrollment recommendations below are historical alternatives, not current implementation scope; use `../contracts.md` and revised Phase 02. Source findings remain valid.

## Findings: authoritative state and its limits

- `server/src/agent_status/types.rs::{AgentState,AgentObservationSource}` defines `Unknown/Idle/Working/Blocked`, `Lifecycle/Hook`. These are semantic reports, not CPU/network/process-liveness classifications. User-selected Free = Idle + Blocked; Working and uncertain/stale evidence block sleep.
- `agent_status/runtime.rs::AgentStatusRuntime::snapshot()` reads `AgentStatusRegistry` under its registry lock. `reducer.rs::AgentStatusRegistry::{snapshot,apply_report,apply_hook_with_prior_exited,check_leases}` serializes reducer truth. Browser stores/badges are projections, not admission authorities.
- Snapshot identity = `server_epoch + revision`; owner identity = terminal ID/incarnation + `reporter_epoch`; session/turn further fence causality. `types.rs::{TerminalAgentStatusRow,AgentStatusSnapshotV1}` omits native process identity, reporter handles and credentials.
- Registry revision changes for membership, availability, semantics and bounded native freshness publication. Identical OMP heartbeats update `last_report_time_ms` without changing revision or `observed_at_ms`; hook renewals can update freshness without an immediate revision (`MIN_FRESHNESS_UPDATE_INTERVAL_MS = 1000`). A public revision alone cannot fence freshness.
- OMP authority requires live current-epoch connection, active terminal credential, and report lease. `runtime.rs::{admit_reporter,apply_report,mark_unknown_on_disconnect,check_leases_with_time}` uses reporters → credentials → registry; hook commit inserts registered-roots before registry. Reports cannot outlive revoked credentials/expired sockets.
- `types.rs::{DEFAULT_HEARTBEAT_MS,DEFAULT_LEASE_MS}` = 5s/15s. `reducer.rs::apply_report` rejects reports at lease age >=15s; `check_lease` expires evidence. Lifecycle DTO has no `expires_at_ms`; its old `observed_at_ms` is not heartbeat age. Direct admission must inspect internal lease state, not DTO age or whether the sweeper ran.
- `collector.rs::handle_reporter_socket` admits only OMP. Its loopback TCP WebSocket proves scoped terminal capability, **not originating agent PID**: `ReporterHello` has no process identity; `handle_reporter_socket` receives no peer identity. TCP does not supply Unix `SO_PEERCRED`.
- `reducer.rs::AgentStatusRegistry.terminals` keys one reducer by `(terminal_id, incarnation)`. `runtime.rs::admit_reporter` rejects a different reporter while one is live; same-reporter reconnect replaces/fences old socket. This is **one owner, not aggregation of every process in that terminal**.
- Native `PrivateHookEnvelope` contains root PID/start_ticks and ancestry. `collector.rs::handle_uds_connection` verifies same effective UID and socket peer PID, then `hook_ingress::verify_reporter_ancestry`; `runtime.rs::apply_hook_event` rechecks active capability and registered PTY root at commit. Native root replacements require exit proof fenced by `NativeOwner {root,generation}`.
- `runtime.rs::check_process_exited` currently treats any `/proc` read failure as exited. Do not reuse that helper as host eligibility exit proof: access/read errors are uncertainty, not a validated exit.
- Native hooks are one-shot, expiring observations, not a persistent lifecycle. `reducer.rs::check_lease` retains native owner but clears turn/state/freshness to Unknown. Unsupported/mismatched/duplicate events do not manufacture freshness.
- `docs/architecture/agent-status.md` §§Native event adapters/ingress and Implemented semantic contract document qualification: OMP 18.4.1, Codex 0.158.0, Claude Code 2.1.250 on Linux x86_64; other versions/platforms unqualified.
- Native `SessionStart` is Unknown; `Stop` is Unknown retaining turn, **not Idle/done**. Codex has no qualified Blocked mapping; matching Interrupt supplies short-lived Idle/interrupted. Claude qualified notifications supply Blocked approval/question; StopFailure supplies Blocked/error. PermissionRequest/question candidates alone are Unknown. Ordinary quiet terminal output proves neither settle nor blocked.
- Consequently an idle/blocked native process usually cannot establish **3h continuous authoritative Free** today: its last hook expires after 15s. Merely extending lease, repeatedly reading stored hooks, checking process alive, or replaying a hook would invent current truth.

## Findings: discovery, traditional terminals and activity policy

- `pty/activity.rs::{ProcessIdentity,TerminalIdentity}` gives PID+start_ticks and terminal ID+incarnation. `manager.rs::capture_activity_snapshot` captures **all live server PTYs**, independent of Fleet/traditional UI presentation. Traditional tabs/sidebar use this same managed backend; `docs/architecture/agent-status.md` §Traditional navigator presentation adds no discovery/ingress.
- `manager.rs` initial create and `automatic_respawn` reserve/activate capabilities, inject reporter environment, register shell root, and retire authority on kill/exit/replacement/shutdown. Switching UI modes or unmounting terminal components must never remove server eligibility coverage.
- `activity/process.rs::ProcessDiscovery::prepare_sample` scans all numeric `/proc` PIDs to build topology, but **matches configured agents only in managed-root reachability plus retained lineage** (`current_attribution`, steps 7–8). An OS terminal/SSH/tmux/headless agent not descended from known PTYs is invisible to recognized-agent count; scanning `/proc` is not currently host-wide agent discovery.
- Retained `(PID,start_ticks)` attribution survives reparenting; recognized agents and descendants remain relevant after shell changes, until validated disappearance/death. Native-hook ancestry rejects nested CLI claims; producer subagent exclusions do not establish that discovered nested processes are free.
- `ProcessSample` exports count, monitored terminal handles, process evidence and sockets, **not a per-agent matched identity→owner mapping**. `RetainedAttribution.is_matched_agent` contains the missing distinction privately; process evidence mixes agents and their children. Count equality/terminal equality cannot match reporters safely.
- `match_candidate_process` uses configured executable basename/absolute path and finite Node/Bun/Python/shell grammars; generic entrypoints require exact paths. Unknown interpreter form/read failures fail closed. No guarantee of detecting an agent omitted from executable configuration; installation status is not live semantic coverage.
- Zero agents currently means no matching agents in managed/retained scope. Empty relevant set skips FD work. Raw output is checked only for monitored agent/retained terminals; ordinary shell output is not a general host workload detector. Terminal input revision is global.
- `activity/sampler.rs::Worker::try_sample_once` combines input, monitored raw output, TCP byte/socket changes, relevant process/image/match changes and managed lifecycle into `ActivityDelta::Genuine`; it mints Final tickets only on `Unchanged`. **No CPU utilization signal is sampled** by these files.
- `activity/tcp.rs::TcpObserver::compare_baselines` considers any sent/received byte change, socket key set or join-inode change activity. Owned sockets include the agent's private reporter connection; therefore OMP's 5s heartbeats cause repeated network resets [INFERENCE from ownership/counter flow; not a runtime observation].
- `coordinator.rs::run_coordinator` resets quiet anchor on every Genuine delta, requires `seen_non_quiescent`, consumes an activity epoch on handoff, then queues async executor work. Neither those resets nor that epoch predicate expresses continuous Free, zero-agent startup, or refusal→new prompt after another 3h without unrelated work.
- `manager.rs::try_claim_agent_activity_handoff` checks policy, accepted request/revisions, deadline, <=5s sample age, input/fleet generation, exact live roots, output sequences and lifecycle before claim. It never checks reducer semantics; unchanged quiet Working passes its semantic gap.
- Bounds: `pty/activity.rs::MAX_LIVE_ROOTS_LIMIT` and `activity/mod.rs::MAX_MANAGED_ROOTS_LIMIT` 256; scanned PIDs 8192; relevant processes 1024; per-process FDs 4096; owned sockets 8192; cmdline 16KiB. Sampler cadence 2s, request deadline 1s, maximum accepted age 5s. Over-limit/access/namespace/identity/counter errors mean unavailable, never empty/free.
- Legacy TCP qualification rejects owned UDP (`UnsupportedTransport`), ignores Unix sockets after classification, requires supported TCP diagnostics/counters, and fails on unresolved ownership/namespace mismatch. Those limits describe traffic measurement, not whether a lifecycle report says Working.

## Proposal: minimal safe contract, with full later implementation scope

1. Add startup policy **`agent-free`**; preserve existing `agent-activity` unchanged. Do not relabel resource quiet as agent Free/Working. Reuse process identity/topology infrastructure, not its byte/output-based quiet timer. Preserve existing RTC wake timing and helper path.
2. Make configured-agent discovery host-wide: apply matcher to all eligible scanned process identities, not just `current_attribution`. Keep terminal attribution optional; retain validated surviving lineage and relevant child coverage. Return bounded matched identity/image/kind evidence and explicit completeness. Permission/namespace/grammar/scan failures cannot certify absence; safely excluded nonagents need actual classification proof. Document configured executable boundary, rather than claiming every possible application is detected.
3. Evaluate the union of discovered configured agents and current semantic owners: a live discovered agent without verified lifecycle is Unknown; a reporter not matched to discovery is coverage uncertainty, not permission to ignore it. Remove dead owners only on validated exact-identity exit; PID reuse/image change invalidates association. External/non-TTY configured agents must appear even without terminal records.
4. Maintain **private per-process semantic inventory**, keyed by qualified process identity plus server/owner generation, separate from existing public terminal projection. Every independent matched agent needs current authority; multiple agents per terminal cannot share one row as proof. Preserve terminal UI through deterministic aggregation (Working before Unknown before Blocked before Idle), never let display aggregation become admission input. Unsupported/nested/headless processes remain Unknown until qualified coverage exists.
5. Minimum OMP upgrade: producer advertises its real process PID; server captures/verifies start_ticks, configured executable/image and PTY ancestry when applicable, then binds the specific persistent connection to that owner. Existing bearer token alone is insufficient. Bind **actual peer**: either qualify a Unix persistent ingress using SO_PEERCRED, or verify accepted TCP peer tuple/socket inode has a unique matching process FD owner, with pre/post start_ticks/image checks and namespace fencing. Reject shared/inherited/ambiguous socket proof; claimed PID alone is not trust. No invented SO_PEERCRED on TCP.
6. Extend OMP collector/runtime admission to concurrent independent per-process owners; reconnect replacement fenced per owner, not terminal. Keep bounded ingress, same-user trust boundary, reporter sequence/session/turn fences, and disconnect/heartbeat expiry. Retain discovered ignored subagents as Unknown unless lifecycle coverage explicitly accounts for them.
7. External OMP needs explicit same-user local enrollment yielding scoped per-process capability; never inject global server credentials or fake PTY identity. Existing extension's `hasUI === true`, `OMPCODE` and non-main exclusions (`assets/omp-agent-status.ts`) mean headless/nested coverage requires real lifecycle qualification before claiming support. A traditional DamHopper terminal is already managed; an arbitrary OS terminal is not.
8. **Phase 2 blocking prerequisite: native authoritative refresh qualification.** Establish actual supported per-process current state and continued freshness for Codex/Claude, including ready-for-input, active retries/continuations/context maintenance, durable waits, resume, cancellation, crash and idle. Hook presence/installation/version-qualified event mapping does not satisfy this prerequisite. Do not change existing Unknown mappings to achieve sleep.
9. Qualification procedure: inspect provider lifecycle APIs/event inventories for exact versions; identify current-state source plus liveness-bound refresh and complete transitions; implement an adapter only where those real sources exist; run version-specific live scenarios including >15s idle/block/long work, missed callback, process replacement and quiet work. Record evidence/limitations in architecture. If no supported authoritative source exists, explicitly block that provider's semantic sleep enablement; unattested discovered native agents continue to block the host. No fabricated heartbeat from historical hooks, transcript/screen polling, or lease stretching.
10. `FreeEvidence` internal contract should include discovery completeness, server epoch, inventory generation, monotonic last-disqualifying/free-epoch timestamp, exact agent identities/images/owner generations/states, per-owner lease deadline and sample completion time. Compute current liveness/freshness under runtime locks; use monotonic deadlines internally (wire wall timestamps remain presentation).
11. Start Free epoch only with complete qualified coverage and all agents Idle/Blocked. Working, Unknown, missing authority, lease expiry, discovery uncertainty, topology/owner replacement or managed lifecycle uncertainty cancels epoch and pending prompt. Idle↔Blocked and same-state heartbeats/refresh do **not** reset it. Track non-Free transitions at mutation time so Working→Idle between sampler polls still resets continuous-Free history.
12. Zero agents is Free only after a **complete host-wide** configured-agent scan, with no live/unresolved semantic owner or retained uncovered agent/child lineage. Allow countdown at zero-agent startup; do not require prior activity. Startup/restart/recovery establishes a new monotonic epoch, never persisted 3h eligibility.
13. Eligibility requires elapsed **strictly more than 3h**, not exactly 3h. Decline/unanswered consent resets a separate attempt/free-wait epoch for another full 3h even if states stay Free; acceptance rechecks evidence. A new authenticated `/ws` UI connection selects consent path, while OMP/private sockets never count as UI. Main owns prompt concurrency/authorization.

## Proposal: heuristic compatibility and final fence

- Preserve proc **identity/completeness** checks; process creation/removal/image/attribution changes invalidate the snapshot and require authoritative reconciliation, not an invented Working state. An agent-set replacement starts a new continuous epoch. Ordinary helper/child churn must be requalified; do not automatically label it semantic work.
- Do **not** use TCP bytes, CPU quiet or raw-output churn to reset `agent-free` countdown or suppress an otherwise qualified prompt. Such vetoes conflict with Free semantics and can permanently suppress prompting through heartbeats/background output. Input invalidates final admission until semantic reconciliation; it is not itself proof that the agent became Working.
- Do not make unsupported UDP/TCP diagnostics a semantic authority failure when complete process identity and independently qualified lifecycle are available. Legacy `agent-activity` retains all transport measurement failures. If chosen identity peer-proof requires network diagnostics, its failure is specifically `unverifiable-owner`, not inferred Working. No relaxation of genuine discovery/authority uncertainty.
- Extend semantic Final request/ticket with FreeEvidence, wait/attempt generation and authorization/consent generation; keep request ID, monotonic sample deadline/age, fleet lifecycle, roots and applicable input fences. Replace `Final && ActivityDelta::Unchanged` requirement only for new policy; raw-output sequence is not its semantic fence.
- Under manager lock, acquire a short runtime admission guard following a documented manager→runtime order; runtime mutations never acquire manager locks. Recheck exact discovered owners/images, coverage, states, lease deadlines **at claim time**, Free epoch, strict 3h deadline, policy/timing and consent/UI generations. Serialize this check with registry mutations/retirement and fleet claim; no procfs/network I/O or awaits under locks.
- Public snapshot revision may be retained for diagnostics but cannot be the only fence. Private non-Free/inventory generation must capture brief work, expiry, replacements and owner loss; bounded refreshes do not invalidate an unchanged eligible epoch merely because freshness advanced.
- `coordinator.rs` currently separates successful fleet claim from async `execute_suspend`; new state may arrive in that interval. Invalidate/cancel pending automatic handoff on semantic/coverage/UI changes and recheck immediately at coordinator/helper-dispatch boundary using the same attempt generation. Do not reuse manual force admission for approved automatic sleep. Main must define final dispatch linearization/cancellation contract: no claim that server locks prevent a local external process from starting work after irreversible OS handoff.

## Precise later implementation surfaces

- `agent_status/{types.rs,runtime.rs,reducer.rs,collector.rs}`: private process-owner contract, per-process inventory, real peer proof, monotonic authority leases, invalidation/guard API; preserve public terminal projection. `runtime::{admit_reporter,apply_report,apply_hook_event,check_leases_with_time,remove_terminal,shutdown}` are semantic/authority mutation points.
- `agent_status/assets/omp-agent-status.ts::{ReporterHello,sendHello,startHeartbeat,extension activation}`: process binding, independently admitted roots, supported external/headless lifecycle only after qualification. `agent_status/{hook_ingress.rs,hook_reporter.rs,codex_hooks.rs,claude_hooks.rs}`: reuse verified identity/causal checks; native refresh adapter requires evidence first, not guessed edits to Stop.
- `idle_suspend/activity/{mod.rs,process.rs,sampler.rs}`: host-wide matched-agent evidence, optional terminal attribution, complete zero result, semantic observation/Final ticket separate from existing TCP sampler. `pty/{activity.rs,manager.rs}`: existing incarnation/input/fleet fences and new semantic handoff guard.
- `idle_suspend/{policy.rs,coordinator.rs,status.rs}`: new policy, independent monotonic Free/attempt epochs, semantic subscription/reconciliation, explicit uncertainty reasons, strict deadline, restart/expiry/refusal behavior; Main supplies helper/consent integration. `docs/architecture/agent-status.md` must document coverage limits and new ownership/qualification contract.

## Behavior acceptance and checks for implementer/main later

- Reducer/runtime tests: quiet Working blocks; Idle and each qualified Blocked reason allow; same-state heartbeat extends actual authority without resetting Free; expired OMP rejects even before sweeper; expired hooks are Unknown; Stop/SessionStart remain Unknown; mismatched/old reports never recover evidence.
- Discovery tests: host-wide external OS-terminal/non-TTY agents included; traditional and Fleet PTYs identical; reparented agent/child retained; multiple agents in one terminal require independent coverage; one Unknown/Working prevents host sleep; missing matcher coverage never represented as provider support; complete zero starts timer, incomplete zero blocks.
- Identity tests: forged PID, recycled PID/start_ticks, changed image, foreign ancestry/UID, shared TCP owner, namespace ambiguity and revoked capability reject; one process cannot steal another's owner; concurrent valid reporters no longer lose independent evidence; stale replacement disconnect cannot clear new owner.
- Clock/race tests: exactly 3h not eligible; >3h eligible; Idle↔Blocked doesn't reset; brief Working between polls does; expired lease at final claim cancels; authority/topology changes during scan, between scan/claim and claim/dispatch invalidate stale attempts; clock jumps cannot extend internal lease or qualify timer.
- Policy tests: OMP reporter traffic/raw terminal redraws do not postpone `agent-free` prompt; legacy `agent-activity` continues TCP/output resets and UDP failure; qualified lifecycle plus UDP does not imply Working; refusal/unanswered repeats after new 3h without need for new activity; zero UI directly uses helper, any UI requires current consent; RTC wake unchanged.
- Native live qualification: actual long ready/wait/work observations, continuation after Stop, cancellation without hook, missed callback/refresh, process exit and version mismatch. Unknown/stale deliberately blocks with safety explanation; do not mark Phase 2 passed from synthetic adapter mocks.
- Existing test surfaces: `server/src/agent_status/tests.rs`, `server/tests/{agent_status_runtime.rs,agent_status_hooks.rs,omp-agent-status.test.ts}`, inline `idle_suspend/activity/{process.rs,sampler.rs,tcp.rs}` tests and `idle_suspend/tests.rs`. Suggested later checks: `cargo test --manifest-path server/Cargo.toml --lib agent_status`, `--lib idle_suspend`, `--test agent_status_runtime`, `--test agent_status_hooks`; use repository's runner for producer TS tests. No checks exercised here.

- Native provider authoritative continuous refresh is **not implemented/proven** by inspected sources; Phase 2 must establish real sources before semantic enablement. External/headless OMP peer transport/lifecycle also needs live qualification. These are implementation/qualification blockers, not permission to weaken Unknown/stale safety or silently ship OMP-only coverage.
