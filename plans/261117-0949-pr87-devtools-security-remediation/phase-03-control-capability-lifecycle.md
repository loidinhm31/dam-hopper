# Phase 03 — Control-bound DevTools capability lifecycle

## Context / overview
[Plan](plan.md) · [Evidence F3 and authority transactions](reports/evidence-and-design.md). P1; pending; 10h. Sequential after Phase 02, same integration owner. Three bounded tasks: capability binding, ordered command/revocation boundary, client cutover. All required for F3 closure; an API-only or UI-only guard is insufficient.

## Requirements / architecture
Full native DevTools mutates via Input/Runtime/DOM/navigation/children; gate entire capability. Download/geometry/target/ServiceWorker restrictions remain independent of control. Reuse SessionInputManager token/viewer/epoch/ending, authority generation/native gate, cancellation AND pending/confirmed held-input accounting. UI/native dispatch currently records key/button holds; direct DevTools relay does not (R2). No shadow lease manager or separate CDP ledger. DevToolsLeaseManager retains hashed bearer tokens/capacity/TTL with immutable control binding.

States: Absent → Issued (authenticated live owner + exact live paired viewer control) → Connected (all bindings rechecked) → Revoked (all authority loss). Failed setup → Revoked; socket close → Revoked; only remint creates a replacement. Same-epoch input renewal may keep current DevTools alive within auth deadline; new epoch, even same viewer, invalidates old capability. Keep auth 5s supervisor as defense-in-depth, not control transfer authorization.

### bind-devtools-control-epoch
1. Change POST `/api/browser/sessions/{id}/devtools` to authenticated JSON `{viewerId, leaseToken}`. Validate bounded canonical identifiers and current session ownership. Resolve live input manager (no creation on missing authority), token+viewer+non-ending+unexpired epoch together; verify viewer's admitted pair belongs to exact principal/auth session/logical target, not merely a caller-supplied viewerId. Derive epoch/incarnation/profile/native target server-side.
2. Store principal/auth-session admission, viewerId, derived control epoch, browser/logical/native identity and existing cancellation/TTL; do not retain plaintext input token or expose it in token URL/log. Existing response token remains secret in memory, no persistence; add only typed non-secret fields necessary for client correlation.
3. Reuse/extend existing attachment admission lookup for exact viewer identity. Current acquire endpoint accepts viewerId and principal session ownership; it is not by itself auth-session provenance. Tighten the boundary needed for mint without redesigning all unrelated acquire APIs. Reject non-admitted/wrong-auth-session viewer even with otherwise valid target.
4. Asset resolve/refresh and WS claim validate all bindings against live authority. Recheck after native connection setup, before activation/first command; no stale issue→transfer→upgrade race. Refresh cannot revive a revoked epoch. Maintain single WS claim and existing capacity accounting on failed upgrades.
5. Migrate existing Rust lease/mock/real test setup to admitted paired current holder; reject old bodyless requests rather than support fallback mint. Tests distinguish foreign-principal 404 from same-owner missing/stale-control denial; stable non-sensitive errors.

### fence-devtools-command-admission
1. At existing input authority owner, admit every DevTools operation with the native transition/write order. Capture auth/control epoch, logical/native target incarnation, connection namespace and root/child native session identity; register bounded operation permit/cancellation before dispatch. Recheck after awaited setup, never hold state/lease locks across network/database awaits. Queue/writes observe fence cancellation.
2. **Stateful Input contract (R2):** inventory supported deployed Input methods/variants before enabling them. Account `dispatchKeyEvent` keyDown/rawKeyDown/keyUp/char (repeat/modifier semantics included) and `dispatchMouseEvent` mousePressed/mouseReleased/mouseMoved/mouseWheel (buttons/modifier state included) through existing authority prepare/acknowledge/release owner. `dispatchTouchEvent`, `emulateTouchFromMouseEvent`, `dispatchDragEvent`, `setInterceptDrags`, `cancelDragging`, `synthesizeTapGesture`, `synthesizeScrollGesture`, `synthesizePinchGesture` are denied unless that same owner supports their full start/update/end/cancel cleanup on captured identity. Classify `insertText`, `imeSetComposition`, `setIgnoreInputEvents` and any deployed additions explicitly: allow only proven non-held target-local effects or managed lifecycle; unsupported/unknown stateful variants deny, not raw relay. Required frontend typing/click/scroll remains a positive gate.
3. **One shared hold ledger:** reserve pending key/button/contact/drag obligations BEFORE native write, capturing epoch plus native target/session/connection incarnation. Native transport success alone is not execution confirmation: correlate bounded native reply; success confirms obligation, rejection removes only the unapplied pending change and preserves prior hold, ambiguous write/reply/cancel retains potential hold until reconciliation or release. Matching up/cancel reserves a release and clears hold only on confirmed native outcome. Repeats do not duplicate physical holds. UI-down/CDP-up and CDP-down/UI-up operate on the same captured physical-state entry; channel origin is provenance, not separate ownership/refcounts. A stale epoch or different identity cannot clear successor holds; conflicting state never becomes an assumed release.
4. On release/active expiry/transfer/same-viewer reacquire/control disconnect/pair cancellation/recovery suspension/auth logout/target retirement/reset: **fence old authority and revoke assets/socket → cancel/drain bounded ordinary operations → release all pending+confirmed native holds on captured identity → confirm cleanup → publish successor**. Compose existing selection lease-end hook, do not replace it or rely on its current delayed post-successor timing. Wait for settlement so a late down cannot race after release. If a hold spans child/proxy session loss, release only via captured route or proven equivalent internal route to that same native incarnation; never resolve it against current replacement target/session.
   DevTools socket disconnect/capability cancellation with outstanding dispatches or pending/confirmed holds must enter that same captured-epoch authority transition, not discard the socket's bookkeeping while leaving UI control active. With no outstanding work/holds, normal dock close may revoke only its capability. Never retire another viewer/replacement epoch from a late socket callback.
5. Include cancellation in stalled `write_with_cancel` (not loop-select alone); queued old Runtime/DOM/navigation/Input commands cannot commit after fence. Cleanup uses a bounded internal authority-owner release permit, independent of revoked viewer cancellation: revocation cannot cancel its own release. No state lock across cleanup awaits; epoch-qualified completion cannot clear replacement state. Rejected/failed/ambiguous release or unresolved dispatch leaves target/control unavailable until reconcile or retire; no success/successor on empty confirmed-only ledger while pending holds remain.
6. Linearization remains honest: pre-fence committed JS/timers may execute and are not undone. Managed native-input releases are required cleanup, not arbitrary JavaScript rollback. Auth unavailable fails closed. Deterministic barriers cover prepare-before-write, native success/rejection/missing reply, stalled writes, concurrent mixed-channel up, cleanup failure/cancel and every revocation trigger. Assert actual native release before successor, existing geometry/recovery gates and no new lock inversion.

### migrate-devtools-control-ui
1. Add typed request DTO/client signature and update every repository mint caller and tests. Dock receives current viewerId/leaseToken/control authority identity; BrowserApp enables/open only when current live controller, visible connected owner and privacy-safe. No automatic control stealing to open DevTools.
2. Include viewer/control binding in request identity and async attempt guards; late mint after loss/transfer is revoked via original captured connection if still current, never mounted against new authority. New epoch/token requires remint; same live epoch renewals need not churn pane.
3. Unmount dock and clear token on controller loss, expiry, rejected renewal, control/media socket loss, mask, owner change, hidden/minimized/tab switch/logout/retirement. Preserve existing privacy and owner-generation protections. No input lease in URL/storage; do not log minted URLs.
4. Present explicit acquire-control requirement/denial state using existing Browser toolbar/dock conventions; do not render a fake read-only or silently functional pane. Backend remains authoritative even if malicious client ignores UI guard.

## Success / risks / security / rollback / next
Avoid lock inversion between transition/lease/native transport; one bounded operation/cleanup ordering. Shared ledger is physical state under captured epoch/native identity, not independent UI/CDP refcounts. Cleanup permit cannot be revoked by the authority it is retiring; failures keep unavailable/reconcile/retire. No per-command unbounded auth call; local fence remains authoritative with live-auth deadlines/post-await checks. Capability URL secret and bound. Holder can mutate owned target only, never download/context-wide ServiceWorker policy. Rollback disables/drains DevTools and completes hold cleanup before matched server/SPA revert; do not bypass uncertain release or restore permissive mint/raw Input relay. Next Phase 04 applies every child/metadata policy under this same authority and accounting.
