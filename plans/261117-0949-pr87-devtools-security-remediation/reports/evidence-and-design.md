## Chosen architecture and alternatives
Retain Rust Axum/native Chromium/bundled frontend. Extend bounded effect filtering, existing input authority/shared native-hold accounting and one positive target/frame projection; no sidecar, credential store, read-only mode, per-tab broadcast heuristics or parallel lease/hold manager. `target_ownership.rs` is shared projection, not session registry. Manager owns logical/native lifecycle; actor protocol; input owner control and pending/confirmed release order; DevTools manager secret/cancellation; filter per-connection policy/correlation; UI projects authority. Phase 01 finite effect inventory stays limited to currently-forwarded reachable nonlocal surfaces (ServiceWorker, analogous Storage/Network browser-state and Target context routes), not full-CDP redesign.

Rejected: Input.* denylist (Runtime/DOM/navigation mutate); Browser.*-only download protection (Page alias exposed); same-origin/type/opener-only worker inference (shared/foreign ambiguity); checking every 5s (transfer race); blacklisting known foreign IDs (unknown/default leaks); attributing unknown frames to first/all viewers (misdelivery). Do not expand raw automation authority redesign into this plan: retain explicit trust boundary and audit, confirmed by the user's `retain-privileged` choice.

## Authority transactions
- Mint request body `{viewerId, leaseToken}` over authenticated owner-bound transport. Server derives epoch, target, incarnation and identity; client epoch is never authority. Require same live paired viewer and principal/auth-session admission; reject absent/foreign/stale proof. Store token hash and non-secret immutable control binding, not plaintext input token in capability record.
- Absent → Issued only inside current-control admission; Issued → Connected rechecks binding at claim AND after upstream setup before any command. Assets also require current capability binding; asset refresh never prolongs control authority. Connected refresh may extend TTL only while control epoch and auth remain current; control renewal of same epoch does not require remint.
- On release/expiry/transfer/same-viewer reacquire/disconnect/pair cancel/recovery/auth loss/retirement/reset: fence old epoch and revoke capability → cancel/drain ordinary operations → release pending+confirmed native input on captured identity → confirm → publish successor. A DevTools socket/capability cancellation with outstanding work/holds enters same captured authority transition; no-hold dock close may revoke capability alone. Late callback never retires replacement. Assets/upgrade/commands denied; child/correlation removed; new epoch requires remint.
- Register pending native hold/release before dispatch with epoch, native target incarnation and connection/session namespace. Key/keyUp/char/repeat/modifier and mouse/button/move/wheel supported variants join existing UI ledger; touch/emulation/drag/interception/gestures/IME/state switches explicitly classified, unsupported stateful variants denied. Native reply success confirms; rejection rolls back only unapplied pending change; write/reply ambiguity retains obligation. UI-down/CDP-up and reverse share physical state, not channel refcounts; confirmed matching up clears only captured entry.
- Ordinary write admission linearizes with control fence. No old writes after fence; already committed JS/timers may execute and cannot be undone. Native held-input cleanup is required, not arbitrary script rollback. Drain prevents late down after release; unknown dispatch/release result keeps unavailable until reconcile/retire. If captured proxy/child route dies, only a proven same-native-incarnation internal release route can substitute, never current target lookup. Cleanup is bounded internal owner authority unaffected by the viewer's own revocation; no state locks across network waits. Existing selection hook composed synchronously before successor, not relied on after publication.

## Positive ownership and event ordering
Owner key = principal/dev namespace + browser incarnation/profile epoch + logical/native target incarnation. Frame edges seeded from owned root frame tree and verified live parent attachments; maintain frame attach/navigate/detach, OOPIF swaps, navigation gaps and actor lifecycle. Session IDs scoped to connection and retired on reconnect/detach. No frameId==targetId assumption. Only causal attachment to a proven parent plus target kind/semantics establishing exclusivity can promote a dedicated worker/OOPIF; shared/service workers remain ambiguous unless exclusive provenance is actually demonstrated. Browser discovery alone, common origin, opener and principal ownership do not prove tab ownership.

GUID Unseen → Bound(owner key, source frame, download) only once on positively owned begin; Bound → terminal progress for same owner; terminal retention bounded until duplicate handling safe, then retired. Missing/conflicting ownership drops attribution; unknown progress dropped. Repeated begin cannot rebind owner; conflicting duplicate fail-closes that GUID. Detach invalidates future frame admission; GUID stays pinned for a continuing download while original logical/native incarnation lives. Session retirement invalidates GUID routing; later progress cannot attach to recreated session. Event loss/overflow invalidates relevant frame/target facts and re-seeds before future admission. Bounded maps deny new admissions/retire uncertain connections at capacity—never clear and default-allow.

DevTools target Unknown → Owned after authority proof → Detached/Retired; Foreign/Unknown suppress metadata/IDs and deny command routing. Pending native attach is quarantined before response/event forwarding. No child command/event can pass while pending. Failed/unowned attach is detached without exposing metadata, resuming unknown code or touching foreign lifecycle. Track correlated response IDs and expected target so direct queries/attach returns cannot bypass event filters; notifications and flattened responses receive the same session validation. Reject legacy nested transport outright (`Target.sendMessageToTarget`); recursively opaque wrappers are not a new supported protocol.

ServiceWorker is a distinct context authority, NOT covered by Target positive ownership. Default-deny commands and suppress events/results (including embedded registration/version/script/scope/target/client metadata) unless deployed evidence and complete effect/payload enforcement prove exclusive target scope. Context-wide lifecycle such as stopAllWorkers always denied, including current holder and owned child sessions. Attachment to an owned service-worker Target is not domain scoping proof. Inventory analogous currently-forwarded nonlocal methods/events with evidence/policy/test mapping; unproven nonlocal routes denied. Qualifier independently establishes B worker beforehand and uses same held live-instance channel/nonce after each A actual-proxy enable/inspection/lifecycle attempt: re-created worker or surviving registration is insufficient. Real frontend/owned worker/OOPIF compatibility must still pass with restrictions active.
