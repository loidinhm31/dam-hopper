## Binding implementation architecture

### A. Scope / simplicity
- Functional developer browser/CDP/JPEG only; no media engine, Electron/Node sidecar, arbitrary reverse-proxying or extension dependency for Browser app. Native Android unchanged; Android web browser clients included.
- Maintain one lazy managed Chromium process/profile per authenticated principal/server; dedicated no-auth profile. Initial supported/qualified capacity one active admin process, two targets, two viewers, configurable hard caps, broader concurrency unqualified. Other principals never share data. Admission at cap returns typed busy, no unbounded wait queue.
- One browserSessionId represents a logical page target; one browser incarnation identifies process lifetime. Native CDP target IDs are internal binding, not URL identity. Stable server session IDs plus creation idempotency key avoid duplicate targets after lost create response; bounded principal-owned request record, no blind create retry on ambiguous outcome. Adopt existing same-session target after reconnect; process restart explicitly reloaded, do not promise unsaved DOM state.

### B. CDP client and process
- Use pinned `chromiumoxide_cdp` + `chromiumoxide_types` 0.9.1 maintained generated command/event types, plus `tokio-tungstenite` production dependency for a narrow bounded internal actor. Do NOT adopt full `chromiumoxide` runtime/unbounded listeners or write a general-purpose automation framework. Candidate pin must compile/qualify in first implementation phase; unavailable schema uses a small typed serde DTO for a REQUIRED standard method, not guessed optional parameters. Unknown CDP events/extra fields ignored/count-only, never crash; malformed required responses fail the owning operation.
- Rust owns launcher and descendants. Admin-provisioned executable, dedicated restricted user-data directory, ephemeral loopback debug port (`--remote-debugging-port=0`), bounded stderr discovery/DevToolsActivePort validation and startup deadline. Never fixed/public port, silent download, attach to ordinary Chrome, no-sandbox, ignore-certificate-errors or blanket-disable-web-security. Pipe transport is deliberately NOT selected; approved scope accepts lack of local-user isolation. Any local process/user able to reach loopback may bypass gateway; untrusted local users require a separate OS/network isolation design.
- Allowlist launcher args instead of blindly copying chromiumoxide defaults (notably ignore HTTPS errors, password-store=basic, timer/background switches). Default browser sandbox/web security and TLS verification remain on. Profile permissions 0700/0600 equivalent Windows restricted DACL; no plaintext password-store override or secret-bearing debug URL in logs.
- Unix supervise process group; qualify parent-death cleanup and Chromium descendants without blanket systemd KillMode changes that kill PTYs. Windows suspended spawn / early Job Object assignment before child creation, kill-on-job-close, qualify nested sandbox jobs. Reject unsafe launcher capabilities rather than silently run uncontained. Process exit/wait, not signal dispatch, permits directory deletion. Profile lock owned through teardown. Never unlink active SingletonLock based only on PID/time; stale/orphan state blocks with actionable recovery unless exact managed identity and all descendants gone are proven. Restricted persisted manager metadata/tombstone enables crash recovery without adopting an arbitrary process.

### C. Ownership / API / sockets
- Fully evaluated live admin actor + current account role in production. Development exception only for state.no_auth AND actual bound listener loopback AND peer loopback AND exact configured web Origin; Origin-less native/agent requests only loopback. No forwarded-header/public tunnel authority. Include browser-specific allowed target/asset origins configuration; no-auth general Internet browsing disabled.
- Expose capabilities with availability/reason/protocol/config bounds. Server owns authorization; UI profileId/generation only client fencing.
- REST `/api/browser/capabilities`, `/api/browser/sessions` list/create, `/api/browser/sessions/{id}` get/delete, target children for navigation/history/reload/viewport/control lease/selection/dialog, `/api/browser/attachments` issuance, `/api/browser/profile/reset` confirmed destructive action.
- Prefer separate media and control sockets: `/api/browser/media` carries binary frames + small ACK/pause controls only; `/api/browser/control` carries ordered input/control/events, not image bytes. Separate from existing `/ws`; input must not queue behind own outgoing JPEG. Each socket single bounded writer with cancellation independent of enqueue/write. API integrator freezes exact route spellings in contracts before parallel producer/client work.
- Attachment auth: bearer-authenticated REST issues short-lived, one-use, purpose-bound tickets, bound to actor subject/auth-session/version/deadline, managed instance/incarnation, exact target/viewer and Origin. Media and control tickets not interchangeable; memory only, no local/sessionStorage. Prefer ticket in `Sec-WebSocket-Protocol` (echo ONLY fixed protocol, not ticket); authorize atomically at upgrade before work; browser sends expected Origin; no bearer token or raw Chromium URL in URLs/logs. Existing fs/media-session cookies not reused for Browser authority.
- Raw-CDP gateway: bearer Authorization header for clients supporting headers; optional short-lived one-use attachment capability when unavoidable, transport via subprotocol preferred, query capability only if needed by selected existing agent and explicitly redacted, TTL 30s, purpose `agentCdp`, never long-lived account token in URL. Pick one mandatory interoperability baseline: existing Playwright `connectOverCDP` using Authorization headers and `/api/browser/cdp/json/version` returning authenticated gateway WS URL, `/json/list` discovery rewritten similarly. No new agent tool. Gateway opens dedicated upstream loopback session per agent and passes bounded messages; do not multiplex through stream actor.
  - Superseded where ambiguous by [Advisor disposition — Superseding logout and gateway guards](advisor-design-disposition.md#superseding-logout-and-gateway-guards): every Origin-bearing discovery/upgrade must match exact allowed Origin; Origin-less requests require header authentication. Phase01 proves headers reach both discovery and upgrade.
- Raw CDP authorizes the ENTIRE owned principal instance, including all its targets and native host file/network privileges. It is not target-sandboxed, not confined by cooperative lease, not an egress boundary. Target discovery confined naturally by per-principal process; no misleading Target.* filter sandbox. No exposure of another principal instance, unauthenticated discovery or raw debug endpoint.
- New media/control/CDP active auth supervisor: reuse `/ws` session/version/deadline semantics (5s persisted check, 2s DB timeout) plus current enabled Admin role; absolute timer for auth deadline, cancel directly on failed check/revocation/role change/shutdown, do not await congested alert queue before cancellation. Targeted session revocation/expiry closes only that login's connections/tickets and releases its inputs, not sibling attachments/profile. Auth-store failure closes, no stale role fallback. Own bounded admission counts; do not fake terminal presence receipts.

### D. Stream protocol / bounded state
- One independent producer per watched target; one dedicated CDP Page session, subscribe-before-start. `Page.startScreencast` jpeg q65 max1280x900 everyNthFrame=1 initially. Optional modern experimental params omitted. Prompt exactly-one producer ACK for each accepted event from current producer run after bounded admission OR explicit drop; never use viewer ACK as CDP ACK. CDP sessionId is per run, not frame ID. Track local producer run epoch and received event accounting; no duplicate ACK on error/recovery. Unknown/old run drops without over-ACK. Stop/reconfigure serially.
- Do NOT pace CDP ACK as initial design: researched Chromium149 can hold three not two, over-ACK underflows, and credit starvation may lose final static frame. Prompt ACK + latest mailbox + viewer 10FPS governor prioritizes correctness. This bounds delivery/decode backlog, NOT engine capture FPS; animation may still capture/encode rapidly. Measure CPU/loopback bytes; if budget fails, stop release and revisit governor rather than claim 10FPS producer or silently add screenshot polling.
  - Superseded where ambiguous by [Advisor disposition — Superseding logout and gateway guards](advisor-design-disposition.md#superseding-logout-and-gateway-guards): name bounded quality/dimensions and qualified everyNthFrame tuning; final-static-frame correctness remains mandatory. Record the condition requiring architecture revisit instead of an open-ended tuning loop.
- Read CDP WS with message-size bound before allocating/serde. At ingress retain at most one latest encoded frame candidate, do not create a task per event; raw event draining never waits for browser viewer. Decode base64 once only for selected latest publication; immutable shared `Bytes`/Arc fanout, no JPEG decode/re-encode server side. Parse bounded JPEG dimensions/header, checked length arithmetic. One latest target cache and per-viewer latest pending reference, max2 outstanding per viewer. Bound base64/event bytes, JPEG bytes, targets/viewers/command maps/queue memory and global budget explicitly in contracts.
- Binary frame envelope: fixed prefix magic/version/header-length/payload-length plus bounded metadata header (JSON <=1KiB acceptable) + JPEG; exact sequence integer serialization safe across JS (u64 decimal strings or safe bounded u32). Carries session UUID, browser incarnation, producer/viewer subscription epoch, viewport epoch, frame sequence, encoded dimensions, target CSS geometry/pageScale, capture timestamp. Header/payload atomic ONE WS binary message, not independently reorderable pairs. Validate identity/length/dimensions before image decoding.
- Viewer `frameAck` exact outstanding sequence+subscription+epoch, after draw; `frameDiscarded` frees only the corresponding actually outstanding frame if skipped as obsolete/hidden/decode failure. Duplicate/future/foreign/stale ACK never adds credit. Stale geometry must not erase credits for the current epoch. ACK timer reaps stalled viewer (30s proposed), producer unaffected by any one viewer. WS send deadline/cancellation handles a physically blocked writer, not just missing presentation ACK. Bounded control traffic too; abusive control disconnects.
- Client one decode active + one replaceable latest pending compressed frame; dispose ImageBitmap on all paths, notify skipped frames so outstanding credits cannot leak. No React per-frame state, asynchronous decoding completion rechecks subscription/owner/privacy/epoch before draw. Canvas draw then rAF/event timestamp is application-presented measurement, NOT physical display scanout guarantee.
- Stop screencast at zero visible demand; viewer inactivity heartbeat timeout needed for suspended tabs/missing pause. Keep agent running. Start/recovery screenshot at most once per attach/resize/restart epoch, only if no valid native frame within bounded timeout; snapshot with layout metrics bracket/epoch recheck, display-only until trusted coordinate geometry if uncertain. No perpetual fallback or post-input screenshot loop. Existing latest cached frame first on resume if current. Static settled pages produce zero periodic screenshot requests.

### E. Input / viewport / visible lifecycle
- Cooperative per-target controller lease: human viewer or declared agent, one holder; raw CDP is trusted bypass, honest warning. Only current lease holder controls viewport/DPR; other viewers letterbox to authoritative viewport. Agent Emulation/zoom changes detected through cached layout/frame metadata, transition viewport epoch before UI can input again. No per-pointer layout CDP calls. Navigation revision separate from viewport epoch; invalidate selection and pending destructive DOM handles on navigation.
- Ordered control input binds exact session/incarnation/viewer subscription, lease token, sequence, viewport epoch and owner capture. Coalesce pointer/wheel only within order barriers; preserve key/button/text/releases and modifiers. Bounded reliable queue; saturation releases held state and revokes controller rather than drop keyUp. Clear on blur/privacy/modal/lease loss/disconnect/auth closure; cleanup uses original target, never ambient replacement. Keep websocket cancellation able to clear keys if socket send stalls.
- Coordinate contract must specify image letterbox CSS fractions -> CDP CSS viewport pixels, DPR/pageScale/visual viewport offsets; epoch update prevents stale mapping. Future first-phase real-engine probe proves at DPR1/2, scroll, browser zoom, page/pinch scale; if unsupported geometry, temporarily disable input with explicit reason, not silently wrong click. Full requested zoom support remains release acceptance, not silently waived.
- Remote Android-web interaction: real focusable text input/textarea proxy for composition/beforeinput/IME commits, no duplicate key+insertText, explicit soft keyboard focus, pointer/touch tap/drag/scroll and cancel, clipboard paste as text only. No revived terminal-specific virtual keyboard policy; no native Android files. Copy/find not native canvas magic: implement explicit bounded selected-text copy and page find controls or clearly unavailable policy if outside requested scope. Do not promise DOM accessibility from pixels.
- Root browser runtime/controllers and canvas DOM under OsResourceHost preserve page/session/DOM continuity across all OS placements. Geometry attachments via existing slot/portal ownership pattern, not arbitrary React node removal. Media subscription may pause/close hidden; target survives. Pause at window hidden/minimized/inactive desktop, document hidden, Cognito, PIN and modal input suppression. Black/clear retained canvas synchronously on privacy activation; late decode cannot repaint. Explicit window-close path closes its target; component unmount never destroys target. Two viewers same target: presentation claims viewer-local, not URL identity/global exclusion.
- Browser create/navigation restore must be idempotent: target identity not URL. OS persistence stores display URL and non-secret stable logical session reference; never transport tickets/lease/rawCDP endpoint/incarnation as future authority. On SPA reload re-list authenticated live target and bind exact current identity; restart gets explicit reload/restore state without blind duplicate or unsaved guarantee. Recipes export URL/config only; never live target capability/ID that would share another launch's resource.
