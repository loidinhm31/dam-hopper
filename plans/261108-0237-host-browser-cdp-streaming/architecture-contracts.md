# Architecture contracts — intended implementation authority

Status: planning and Phase 01 frozen contracts. Primitive adapter, process containment, and protocol validation qualification has run on Linux x86_64 ([engine qualification report](reports/engine-qualification.md)); deployment, streaming performance, and Windows containment remain unintegrated and unqualified. Binding decisions: [design direction](reports/design-direction.md), approved [brainstorm](../reports/brainstorm-261108-0138-host-browser-cdp-streaming.md). Existing implementation references are in the scoped reports; this file does not assert deployed production behavior.

## 1. Scope, identity and trust

- Functional developer Browser/CDP/JPEG; remote Android **web** included. Native Android, smooth video/audio, Electron/Node sidecar, general automation framework and hostile-tenant isolation excluded. No copied AICoworker source.
- One lazily started Chromium/profile per authenticated principal/server; dev namespace separate. Initial qualified capacity: one active principal process globally, two page targets globally, two viewers globally (including two viewers of one target), two raw-agent connections. Other principals never share data; admissions at cap return `429 browserBusy`, no wait queue. Larger configurable deployments remain unqualified.
- `browserSessionId`: server UUID for one logical page target, distinct from URL and internal native target ID. `browserIncarnation`: fresh UUID per process. Counters (`profileEpoch`, `viewportEpoch`, `navigationRevision`, `frameSeq`, `inputSeq`): decimal u64 strings; canonical positive decimals `[1-9][0-9]{0,19}` with numeric value <= 18446744073709551615 (zero, leading zeros, signs, whitespace, and non-ASCII digits rejected); parsed as BigInt/u64, never converted via IEEE-754 JSON numbers. Counter exhaustion closes/recreates identity, never wraps. `producerRun` and `subscriptionEpoch`: fresh UUIDs.
- Client owner capture `{profileId,generation}` only fences asynchronous work; live server subject/session/current role is authority. Native target IDs/debug URLs are never persisted as future authority. UI resource claims are viewer-local, not global URL exclusions.
- Raw CDP authorizes **entire owned instance**, all targets and browser-native host filesystem/network privileges. Cooperative lease, target mapping and HTTP checks cannot sandbox it. Loopback debugging accepts that any local process/user able to connect may bypass gateway; stronger local/tenant isolation requires another OS/network design. No claim that a same-account/local-user boundary is enforced.

## 2. Candidate CDP engine and actor

- Pin `chromiumoxide_cdp = =0.9.1`, `chromiumoxide_types = =0.9.1`, and current-compatible `tokio-tungstenite` runtime dependency; do not import full chromiumoxide runtime/listeners. Maintained generated types for required methods/events; tiny serde DTO only for a required standard method absent in pinned schema. Optional `maxFramesInFlight`/`sendLastFrame` omitted.
- One bounded internal connection actor, dedicated flattened Page session per watched target/run; fresh session on ambiguous run failure. Raw agents use dedicated upstream connections, never internal actor multiplexing. Actor bounds enforce three distinct limits: (1) 32-message writer channel queue between client and actor; (2) max 64 total admitted commands across queued + in-flight; (3) shared RAII command budget of 2 MiB logical serialized command length across queued + in-flight commands (held from pre-serialization reservation until response, caller cancellation, deadline sweep, or teardown). This 2 MiB byte allowance is logical serialized length across queued+in-flight, not queued-only memory or a heap/RSS ceiling. Max 64 KiB payload bytes per command. Non-waiting slot reservation precedes serialization; byte reservation precedes enqueue; overflow returns typed busy (`TooManyPendingCommands` or `WriterQueueFull`) or closes affected producer/connection if safe continuation impossible. Writes use a bounded 5s deadline (`WRITE_DEADLINE = 5s`) yielding to close. While a write is stalled (<= 5s), the single actor task pauses reads and sweeps (independent read-during-write is not provided); callers maintain their own command deadlines (configured ceiling 10s) and are never held past them.
- Read WS message cap 4 MiB, frame cap 4 MiB, before serde/allocation; bounded fragmentation handling and tungstenite write/read buffers. Required response malformed => owning operation fails; invalid framing/oversize closes actor. Unknown event/method and extra response/event fields ignored with atomic counter without queue allocation. Required known fields remain validated: specifically, a malformed known `Page.screencastFrame` (unparseable envelope, non-string sessionId, missing integer frame sessionId, non-object or non-finite metadata) has no routable owner and would strand native frame credits, so it closes the actor with `MalformedResponse`. Actor closure is connection-fatal; the future Phase 05 producer must treat actor closure as an ambiguous run failure and start a fresh flattened Page session.
- Process args allowlisted: explicit executable, `--headless=new`, restricted managed user-data-dir, `--remote-debugging-port=0`; no fixed/public debug port, silent download, ordinary-profile attach, no-sandbox, certificate bypass, blanket web-security disabling, password-store=basic or copied background-throttling overrides. Default sandbox/TLS/web security stay on.
- Discovery max64KiB retained stderr/port-file data, startup15s; validate endpoint host loopback and child/profile identity. Never log raw endpoint, bearer, ticket or page payload. Future phase01 must prove exact binary/hash/schema/static/zoom/multi-session behavior on Linux and Windows; report failure blocks dependents. Chromium149 source/156 primitive observation is not a supported-version claim.
- Qualification fixture: maintained test-only `server/examples/browser_host_qualification.rs` plus `packages/ui/e2e/fixtures/browser-host-qualification.ts`. Package runner CWD is packages/ui: helper derives absolute repository root from its import.meta.url via fileURLToPath+path.resolve (same existing application-services convention), sets child cwd to root and uses absolute manifest path. Scoped worker fixture timeout660000ms is OUTSIDE each60s test; Cargo prebuild has its own600000ms deadline, separate from20s post-spawn readiness and bounded cleanup. Prebuild with `cargo build --manifest-path <absolute-root>/server/Cargo.toml --example browser_host_qualification --message-format=json`; incrementally parse bounded compiler-artifact records and resolve exact matching target executable (including native .exe), never guess target/debug path or launch Cargo for readiness. Optional documented prebuild uses this same command and artifact parser, not an unverified path. Spawn resolved executable only AFTER successful build; readiness20s starts AFTER binary spawn. Retain <=64KiB stdout and <=64KiB stderr total, max4KiB readiness JSON line; overflow/malformed/missing readiness fails (no skip). qualificationReady contains loopback baseUrl+synthetic bearer in memory only. Finally includes partial-start/readiness-failure paths: close stdin, bounded reap, then Unix process-group/parent-death or Windows Job descendant termination/wait; never kill only Cargo/root. Build timeout also reaps build process group/Job. Phase01 mode uses production actor/launcher with bounded real forwarding/Origin/session checks, no future gateway dependency or shipped alternate gateway. Phase04 explicitly adds production-gateway mode mounting actual manager/auth/router/CDP handlers in this fixture and repeats headers+Origin+independent native Page-session proof before producer/UI exist.

- Media `/api/browser/media`, control `/api/browser/control`, raw gateway `/api/browser/cdp/ws`. Browser WebSocket protocols: fixed `damhopper.browser.media.v1` or `damhopper.browser.control.v1`, plus `damhopper.ticket.<base64url>` capability. Server echoes **only fixed protocol**. Header Authorization used on raw gateway, fixed `damhopper.browser.cdp.v1` optional capability path only if concrete client needs it.
- REST issue/atomic consume binds hash(ticket), purpose, subject, authSessionId, auth/credential versions, effective deadline, profileEpoch, incarnation, exact session/viewer/subscription and expected Origin. Media/control cannot swap tickets. Both connect under same newly allocated viewerId/subscriptionEpoch (UUIDs); per-pair reserve expires30s, or15s after first socket without mate. Control alone cannot send input until paired identity admitted. Admission fixes subscriptionEpoch immutably for the media socket lifetime; resume/rebind/reconnect requires fresh media socket+one-use ticket/new subscription and matching newly admitted control socket, no inherited credits or input sequence.
- Tickets never localStorage/sessionStorage/cookie/URL. Failed Origin/purpose checks consume or invalidate token to prevent probing; one atomic upgrade winner; revalidate current role/session at consume. Listener/peer checked at upgrade too.
- Each connection writer bounded and independently cancellable; absolute deadline timer never depends on watcher tick. DB failure/demotion/version/revoke/session disabled closes directly; best-effort close reason is not awaited before cancellation. Max healthy-store revocation observation5s, error path<=7s plus scheduling; qualify actual timing. Targeted revoke clears only matching login attachments/input/tickets; sibling profile remains. - Raw discovery: authenticated `/api/browser/cdp/json/version`, `/api/browser/cdp/json/list` (and `/api/browser/cdp/json` alias only if mandatory Playwright proves requirement; otherwise none). ## 6. Frame wire format and producer accounting

Atomic binary message, big-endian16byte prefix:

| Offset | Size | Value |
|---|---|---|
|0|4|ASCII `BHJF`|
|4|1|version1|
|5|1|flags0 (unknown nonzero flags reject)|
|6|2|JSON header byte length1..1024|
|8|4|JPEG payload byte length1..2097152|
|12|4|reserved0|

Message.byteLength must equal16+headerLength+payloadLength with checked arithmetic; no trailing bytes or separate header/image messages. UTF-8 strict JSON; reject duplicate required keys/invalid types/unsafe nonfinite geometry. Required header:

`{browserSessionId,browserIncarnation,profileEpoch,producerRun,viewportEpoch,frameSeq,width,height,captureTimeUnixMs,geometry:{cssWidth,cssHeight,offsetTop,scrollX,scrollY,pageScale,visualOffsetX,visualOffsetY,dpr},inputTrusted}`

UUID fields canonical UUID strings; counters canonical positive decimals `[1-9][0-9]{0,19}` (`profileEpoch`, `viewportEpoch`, `frameSeq`); `captureTimeUnixMs` safe JS integer<=2^53-1 for diagnostics, not sequence authority. Width/height match checked JPEG SOF. Geometry finite within documented viewport limits: `cssWidth` in (0, 1920] and `cssHeight` in (0, 1080] (CSS viewport ceiling 1920x1080; zoom<100% unqualified); offsets absolute<=10000000CSSpx, `pageScale` in 0.1..10.0, `dpr` in 0.1..10.0 (out-of-range values rejected); unexpected geometry disables input until qualified layout reconciliation. Unknown extra header fields ignored if total bound valid. `captureTimeUnixMs` source uncertainty marked in diagnostics; no cross-machine wallclock latency claims.

Wire binding example: media socket M1 admitted subscription S1 and control C1(S1); M2/C2 admitted S2. Both receive IDENTICAL `[BHJF16][target header without S1/S2][JPEG]` Bytes for publication P. M1 callback captures S1 and emits frameAck(S1,P) on M1 only. After resume M3/C3(S3), late M1 decode emits discard(S1,P) only to captured M1 if open, otherwise no send; never ACK(S3,P). Server rejects S1 sent on M3 and S3 on M1 before touching credit. Prefix16+header<=1024+JPEG<=2097152 remains <=2098192bytes.

Producer transitions `Stopped -> Starting(run) -> Streaming -> Stopping -> Stopped`; reconfigure never overlaps runs. Dedicated Page session has subscription installed before start. Fresh flattened session per run removes ambiguous old native sessionId correlation; frame event is accepted only for current attached Page session/run and established start. First current event establishes native screencast sessionId for that run; mismatched old session/run drops without ACK. Previously accepted events keep exactly their queued ACK obligation while stop drains; drain timeout closes Page session, never replays ambiguous ACK.

For each current-run event: validate size/envelope and reserve one ACK slot; assign local received ordinal; put bounded candidate or explicit drop; enqueue **one** `Page.screencastFrameAck(nativeSessionId)` immediately. ACK native sessionId is run credit, not frame ID. No viewer credit participates. If reservation/write fails, abort run/connection with explicit loss accounting; never retry ambiguously sent ACK or synthesize surplus credit. Exactly-once means enqueue/write attempt per accepted event; network failure cannot promise peer receipt. Event that cannot be safely admitted is connection-fatal, not an unbounded deferred ACK. Preserve FIFO stop/ACK command ordering.

Retain newest base64 candidate, decode once only when selected for publication and free replaced candidate. Build one immutable complete BHJF prefix+target-scoped header+JPEG `Bytes` buffer per publication, then clone Bytes handles for cache/writers/outstanding/pending; no application-level per-viewer JPEG copies or server image decode/re-encode. Candidate overwritten after ACK is explicit drop, not lost obligation. JPEG SOF checked length/dimensions/pixel ceiling. Each publication advances frameSeq within process; target geometry changes advance viewportEpoch **before** new-epoch publication/input. Native encode may run above10FPS; governor only limits delivery/decode.

## 7. Viewer flow decoder visibility

- Shared header contains only target/process/profile/producer/viewport/publication values: no viewerId, subscriptionEpoch, ticket, login or per-viewer data. Locked Axum0.8.8/tungstenite0.28.0 accepts contiguous Binary(Bytes): serialize the complete envelope once/publication, clone identical Bytes for each viewer; no segmented-message/custom WS framework. Unavoidable WS/TLS/network copies are outside the application-level no-per-viewer-JPEG-copy promise. Outstanding key is `(capturedSocketSubscription,producerRun,viewportEpoch,frameSeq)`; reserve before writer, max2 entries+1latest pending, delivery>=100ms apart, ACK timeout30s/send deadline5s. Charge each unique COMPLETE buffer (prefix+header+JPEG) until LAST cache/pending/outstanding/slow-writer clone drops; closing credits cannot prematurely release an active writer reservation.
- Media text controls: `{kind:'frameAck'|'frameDiscarded',subscriptionEpoch,producerRun,viewportEpoch,frameSeq,reason?}`, plus `{kind:'pause',subscriptionEpoch}` and `{kind:'heartbeat',subscriptionEpoch,visible:true}`. Discard reasons `replaced|obsolete|hidden|decodeFailed|ownerChanged`. Match/removal exact: duplicate/future/foreign/stale control does not add credit; server first requires the control subscription to equal that exact admitted media socket context, then removes only its matching outstanding key. Foreign/old-socket controls never affect replacement credit; closed-socket cleanup owns its old entries, never ambient current subscription.
- Decoder: message callback captures originating media socket+immutable admitted subscription, attaches this local context to parsed target-scoped header, and validates both before decode. Never read/reassign ambient current subscription for an old callback or ACK/discard. If idle decode; else replace compressed pending and disposition previous pending. Active decode cannot be cancelled safely; token recheck after completion prevents stale draw and sends discard. Always close bitmap in finally. Draw then frameAck; visibility/privacy/owner/epoch rechecked synchronously immediately before draw. No React per-frame state. rAF/application-present metric is not physical scanout.
- Pause/hidden closes subscription demand and releases its credits, held input and lease; retain target/cache/root canvas. Resume/rebind requires a fresh media socket, fresh one-use ticket and subscription UUID, with newly admitted matching control pair; never retag a surviving media socket. Use valid cached current-geometry frame; old in-flight packets cannot repaint. Privacy Cognito/PIN clear/black retained canvas synchronously **before** async pause; late completion fenced. Minimize/inactive desktop/document.hidden/modal input suppression release original target state; modal may retain display but no input.
- Heartbeat5s with15s expiry catches suspended tabs. Native screencast stops when target has no visible subscriptions, agent stays alive. At attach/resize/restart epoch use current cached frame first; after250ms without valid native frame one `captureScreenshot(jpeg)` allowed, bracket `getLayoutMetrics` before/after and recheck epoch. Uncertain geometry display-only. Once/epoch flag persists through retries; no periodic/static/post-input polling. Reconfiguration rate-limited/debounced100ms; demand/epoch changes serialize.

## 8. Viewport lease input contract

Geometry basis: image fractions `u=(clientX-drawX)/drawWidth`, `v=(clientY-drawY)/drawHeight` from contained aspect-fit rectangle; reject out-of-image. Normal desktop mapping candidate `x=u*cssWidth`, `y=v*cssHeight+offsetTop` subject to CSS viewport ceiling (`cssWidth` in (0, 1920], `cssHeight` in (0, 1080]; zoom < 100% unqualified); scroll offsets are metadata, **not added** again to viewport mouse coordinates; DPR rescales image only, never multiply CDP CSS coordinates twice. Phase 01 authoritative visual-marker qualification verified: (1) Out-of-image aspect-fit rejection; (2) Visual marker centroid mapping from decoded screencast JPEG pixels to CDP input coordinates under DPR 1.0/2.0, document scroll (60, 50), pageScale 1.0/2.0, and nonzero visual viewport offsets (offset 50, 50), with verified formula `x = u * visualViewport.clientWidth`, `y = v * visualViewport.clientHeight + offsetTop` (visual viewport offsets are handled internally by Chrome's visual coordinate space; document scroll offsets are not added); (3) Native browser zoom (80%, 125%, 200%) was investigated across keyboard shortcuts, Ctrl+wheel, launch flags, and protocol methods, and confirmed UNREACHABLE via standard CDP/launch in headless Chromium 157; native browser zoom remains UNVERIFIED and `inputTrusted:false` disables clicks on nonunit native zoom geometry. Full zoom support remains required acceptance; inability is a release blocker, not permanent view-only scope reduction.

`control input = {kind:'input',browserSessionId,browserIncarnation,profileEpoch,subscriptionEpoch,leaseToken,inputSeq,viewportEpoch,event}`. Ordered contiguous inputSeq; duplicates ignored only for exact previously processed sequence, gap/out-of-order revokes lease and releases held state. Reliable queue128/256KiB; coalesce adjacent pointerMove/wheel only, not across key/button/text/resize/lease barriers. Overflow releases keys/buttons and revokes, never drops keyUp. Viewport updates accepted only holder; all viewers letterbox authoritative dimensions. Lease30s renewed5s; human or declared agent one holder. Raw CDP is privileged bypass and may change viewport/navigation: reconcile cached metrics/frame signature, advance epoch, reject stale input first. No per-pointer metrics CDP request.

NavigationRevision independent of viewportEpoch; navigation invalidates selection/DOM handles even if dimensions same. On geometry uncertainty use cached layout update at bounded1Hz max outside pointer path, no screenshot loop; input remains off until coherent epoch. Blur/privacy/modal/lease loss/disconnect/auth cancel release original captured target modifiers/buttons/pointer, never ambient replacement. Reliable release failure terminates lease/session input channel and marks unavailable, not silently stuck success.

Text proxy is actual focusable textarea/input, composition/beforeinput commits once via insertText; composing keydown is not duplicated text. Explicit soft keyboard focus, pointer/touch tap/drag/scroll/cancel, paste text only. Copy selected text bounded64KiB with current admission+lease, find explicit controls. Canvas offers no automatic DOM accessibility promise. Native Android unchanged.

## 11. Lifecycle reset and account logout ordering

Lifecycle states under exclusive principal lock: `Dormant -> Starting -> Running -> Stopping -> Dormant`; crash -> `Recovering` only with exact identity/descendant proof, else `CleanupPending`. Reset `Dormant|Running -> Resetting -> Dormant(empty,newEpoch)` or `CleanupPending`. `Disabled|Unavailable` capability does not launch engine. Profile lock stays owned through stop/reset. Unix group+parent-death and Windows suspended-spawn/Job-before-resume/killonclose qualified natively; root kill alone is insufficient. No stale SingletonLock unlink from PID/time. Restricted persisted manager metadata/tombstone supports recovery, not arbitrary process adoption.
Stable restricted principal-root layout: `manager.lock`, `manager.json` (identity/profileEpoch) and `reset.json` tombstone are OUTSIDE deletable `user-data/`. Reset removes/recreates only `user-data/`, never manager lock inode or tombstone; all reset/recovery paths preserve this fence. Directory permissions/Windows DACL apply to principal root and children.

Credential profile per principal intentionally shares site logins across sibling DamHopper logins. Explicit **fully live Admin Log out and clear shared Browser data OR confirmed Browser reset** removes all principal Browser credentials/targets; **Log out, keep Browser data** always invokes server logout/revocation without wipe. Missing confirmation, stale or old-client logout still revokes that login successfully with retained/resetRequired outcome; passive expiry/remote session revoke never wipes. No-auth profile separate and never production logout target. **V1 user validation: no preselected logout choice.** Explicit keep/clear/Cancel required; choosing neither and pressing Enter never dispatches logout or wipe.

Public `/api/auth/logout` currently decodes claims, so do not make decoded/expired token/cookie destructive. Exact new flow:

1. Client captures owner/token and preflights admitted Browser capabilities/profileEpoch; warns all sibling Browser targets/logins reset. Initial focus goes to **Cancel**; Escape cancels; neither logout button is default or autofocused. Enter on initial focus cancels, dispatching neither logout nor wipe. Keep-data still calls server logout: revoke session/media+clear cookie FIRST, then200 retained/resetRequired (or truthful unknown/absent), not local-only signout. Clear branch requires live admission, sibling warning, exact Origin/CSRF, explicit confirmation and expected epoch; Cancel keeps login/profile. Local Remove server profile is explicitly local configuration removal and says **server Browser credentials retained**, not remote logout/wipe. Offline local signout reports remote status unknown, never cleared.
2. Server may fully evaluate live actor/session/version/current Admin and record request-local admission receipt **before** revoking this request's session. Then ALWAYS preserve existing idempotent decoded-claims session revoke, fs/media-ticket revoke and cookie clear **FIRST**, before any destructive Browser work. No expired/decoded-only claims create destructive authority. Store failure retains current endpoint compatibility but is logged/reported truthfully; no Browser wipe unless full admission succeeded.
3. Missing/malformed/stale confirmation is NOT failed logout: old SPA/native/script/expired clients receive200, `browserResetState:'retained'` for admitted known retained credentials or `'unknown'` when admission unavailable, with conservative `browserCredentialsRetained:true,resetRequired:true` meaning this request did not clear credentials (not proof a profile exists). No profile metadata to expired/ordinary callers. New UI offers reauthentication then confirmed reset, not destructive retry with revoked token. No managed profile verified => cleared/false/false without deletion; unknown never means cleared.
4. Only successful pre-revocation live Admin admission receipt plus CSRF/exact Origin (Origin-less native **bearer-header** allowed), confirmed browserReset, expectedProfileEpoch and operationId permits Browser wipe. Initiating account auth is already revoked; siblings retain DamHopper auth but lose shared Browser resources on accepted wipe. Reset-only preserves initiating login. Reauthenticated same principal can GET status/retry confirmed reset; expired claims cannot query destructive state. Tombstone cannot clear before descendant/deletion proof. Targeted DELETE auth session only closes matching Browser attachments/held input, never enters profile reset. Passive expiry preserves credentials.
