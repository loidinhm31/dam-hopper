## Findings

### F1 — High / high confidence: runtime keys alias replacement transport objects

- Plan: `P/contracts.md:16-21,41-45,54,91,244-247` uses connection/socket values as captured runtime authority and requires an old cached target to be refused after socket replacement; `P/phase-04-retained-integration.md:169-172,178-182` relies on that fence.
- Source: `S/core/transport/WsConnection.kt:48-50,100-101` starts a per-object socket sequence and creates `sock-1`; `S/core/model/ConnectionRef.kt:55-64` makes equality solely connection + socketId. `S/features/profiles/ProfileRepository.kt:147-158` creates a fresh WsConnection without advancing generation; root recreates it on active-profile changes (`S/ui/screens/DamHopperMobileApp.kt:230-249`). Host replacement itself correctly distinguishes object identity (`A/main/kotlin/dev/damhopper/nativeapp/platform/workspace/NativeWorkspaceViewModel.kt:537-553`).
- Failure: visit profile A, switch to B, return to A. Two transport objects can have identical `(ConnectionRef, sock-1, endpoint, account)` while server epoch, terminal incarnation and workspace registration remain unchanged. The frozen target cannot distinguish the obsolete attachment; old receipts/clicks can compare equal to successor authority, contradicting stale-target rejection.
- Smallest correction: freeze a monotonically allocated retained-host attachment incarnation in runtime keys, inventory captures, publications and activation targets; replace it whenever the host replaces its WsConnection. Fence old work against that token, independently of display-cache logical ownership. Keep socket creation/lifetime unchanged. Add same-generation/same-socket-value replacement tests to Phase04's existing owned test files; propagate the contract before G2 freeze.

### F2 — High / high confidence: claimed atomic commit lacks runtime-side serialization

- Plan: `P/contracts.md:234,240-247` and `P/phase-04-retained-integration.md:180-182,203` prescribe profile mutex + registry admission and a non-suspending main-thread callback as the final owner/socket/epoch/instance transaction.
- Source: `S/core/ownership/ConnectionRegistry.kt:240-250` excludes registry retirement only and prohibits blocking/reentry inside admission. Runtime collectors inherit `Dispatchers.Default` (`A/main/kotlin/dev/damhopper/nativeapp/platform/workspace/NativeWorkspaceViewModel.kt:542,554-556,885`); socket loss changes activeSocketRef under a different lifecycle mutex (`S/core/transport/WsConnection.kt:395-415`); reducer epoch/baseline changes use its independent mutex (`S/features/terminal/AgentStatusReducer.kt:123,357-383`).
- Failure: final callback reads current socket/epoch; a background collector revokes/replaces that authority before route/session/profile mutations. No suspension on Main does not exclude those producers. Registry admission can still succeed, publishing Committed for a runtime already invalidated locally.
- Smallest correction: specify the local linearization point and participating mutations explicitly. Serialize roster runtime attachment/epoch/inventory/registration invalidation and commit through one bounded admission mechanism or documented confinement; all those producers must participate. Define lock order and nonblocking admission failure (registry callback may only try-lock an independent gate), and ensure retirement never waits on a child needing held profile/registry locks. Do not claim synchronization with future server changes. Add deterministic invalidation-at-final-admission tests; assign any additional necessary writable paths explicitly.

### F3 — High / high confidence: overlay authority omits a reachable overlapping search and shortcut path

- Plan: `P/contracts.md:251-253` freezes exactly `settings || privacy || compactAgents`; `P/phase-04-retained-integration.md:188-189,196` and Phase05 input journeys test only that subset. “Preserve existing predicates” cannot cover blockers that currently have no such predicate.
- Source: root shortcuts can open search or switch panels (`S/ui/screens/DamHopperMobileApp.kt:455-469`), while ShortcutGate blocks only Settings (`:489-505`). Full-screen search is composed over the workspace (`:639-658`) and requests its own focus (`S/ui/screens/WorkspaceSearchView.kt:67-69,106-119`). Terminal eligibility has no search/modal/focus check (`S/ui/screens/ProjectTerminalState.kt:170-176`). Terminal create/diagnostics/kill modal state is local (`S/ui/screens/ProjectTerminalScreen.kt:188-190,1698-1712,1775-1777`, targeted search).
- Failure: compact Agents opens, root hardware shortcut opens search above it, then closing/resizing Agents clears the three-way cover while search still occupies the terminal. Root shortcuts can also change route/panel underneath the sheet. The plan neither prevents this overlap nor defines the remaining blocker, focus owner or Back/Escape order; qualifying only the three-way truth table misses it.
- Smallest correction: enumerate every overlapping surface encountered by the Agents host (search, pending departure, local terminal dialogs/popups, Settings/privacy), and choose explicit suppression/exclusivity or composed blocker reporting into one authority. Freeze root-shortcut eligibility plus topmost Back/Escape/focus restoration rules. Extend integration/device acceptance for search+Agents and modal overlap; preserve unrelated notification policy and avoid bundling general popup repairs. Existing root/workspace/terminal files are owned by Phase04; revise ownership if a new helper/test is required.

### F4 — Medium / high confidence: qualification introduces unsupported external setup gates

- Plan: `P/phase-05-qualification-and-docs.md:23,52,98,109,114,129-140,153,158` requires a real older-server snapshot404 run but identifies neither supported version nor runner/setup contract; equal-ID seeding is treated as potentially unavailable. These gaps can prevent required qualification indefinitely even when current supported endpoints suffice for most scenarios.
- Source: current snapshot route is registered (`server/src/api/router.rs:295-299`) and its handler unconditionally returns a JSON snapshot (`server/src/api/agent_status.rs:379-381`), not a configurable 404. Conversely current terminal creation accepts caller-supplied `id` (`server/src/api/terminal.rs:28-42,85-107`) and routes exist for create/list/kill/remove (`server/src/api/router.rs:283-294`); isolated servers can seed the same chosen ID without inventing a backend feature. Existing fixture only supplies general server/token/project arguments (`A/androidTest/kotlin/dev/damhopper/nativeapp/NativeFileServerFixture.kt:46-63`), not this older-server facility.
- Smallest correction: specify deterministic identical-ID creation/cleanup across disposable servers; stop presenting collision setup as an unknown prerequisite. Separate controlled real-HTTP404 transport/reducer coverage from actual older-server compatibility. For mandatory older-version device acceptance, supply a verified version/artifact, compatible authentication/setup and exact fixture/runner inputs; otherwise obtain coordinator/user disposition of that acceptance change, rather than silently converting a hypothetical old server into an unresolvable required blocker. Controlled HTTP404 is not proof of older-version compatibility.
