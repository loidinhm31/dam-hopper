## Initial design constraints supplied to author
1. Freeze native-only immutable contracts and UI callbacks first. Then disjoint parallel slices: pure roster projection/filter/local persistence vs stateless Compose sidebar. Single integration owner follows both, qualification then docs sequential. No fictional backend slice.
2. Native open membership = successful current-owner terminal list projected into each retained workspace's visible selectable Traditional tabs, not every server session and not just instantiated controllers. Exact project + normalized nullable worktree match defines workspace membership for the roster. Keep current project terminal behavior otherwise unchanged. Order workspaces by retained registration/first encounter and members by accepted tab list order. Deduplicate by profile/id/incarnation; metadata decides canonical workspace, never map iteration or active workspace. Conflicting metadata fails closed with explicit refresh state.
3. Publish membership with exact endpoint/account/ConnectionRef and request ticket; reject late refresh. Unmount/panel switch retains it; explicit workspace close, profile logout/delete/account/endpoint replacement purges affected membership/observations. Generation/socket replacement retains only same logical-owner cached observations as unavailable until revalidated. No process-death session/output persistence.
4. Existing retained runtime collector owns all new observation of status and terminal-lifecycle/invalidation signals. On connected baseline, foreground/sidebar opening/manual refresh and relevant existing lifecycle or agent status incarnation mismatch/removal: reconcile listDetailed once per existing runtime, with coalesced invalidation/request tickets and a follow-up if invalidated mid-fetch. Update all already-registered memberships for that runtime, never register new projects from server inventory. No periodic poll, new socket, keepalive service, runtime, scheduler or flags. Network failures mark retained rows unavailable and show retry; exit/removal safely prunes exact instances. Hidden stopped/removed membership must not remain Working just because its screen is inactive.
5. Effective presentation derives exact registry owner, endpoint/account, live socket/state, accepted status and inventory baselines, typed client unsupported flag. Cached READY alone cannot render Working. 404 is client Unsupported, other failures Unavailable. Keep cache across temporary offline, purge on identity loss. Do not weaken notification reducer high-water or generate alerts from projection/filter/refetch.
6. Grouping/filter/status/cycling match web. Local storage only saves status selection on user action; defensive scalar/array decode with no invented migration requirement, all sentinel and canonical order. Retained UI open/focus state ephemeral; selected filter persists independently of selected profile.
7. Activation captures complete target: logical workspace owner, ConnectionRef/socket, server epoch where applicable, terminal ID/incarnation. Revalidate existence/alive/type/project/worktree via existing listDetailed before routing AND after any async dirty departure dialog. Recheck captured registry/runtime identity immediately before atomic navigation commit. Refuse stale/restarted/missing/offline target explicitly, never fallback to first terminal. Selection side effects/profile/target changes only on successful commit. Do not reuse NotificationTarget admission/read/auto-switch semantics. Close phone sheet only after committed route, not merely deferred guard.
8. Existing navigation needs a small shared verified-route entry/internal commit seam that supports asynchronous revalidation after guard; migrate affected callers if signatures change, no compatibility shims. Keep existing notification semantics unchanged. Exact API frozen in contracts before branches. Retained scope owns suspended routing; replacement or cancelled/failed guard cannot commit late.
9. Width choice: reuse 600dp pin threshold and 280dp sidebar width from editor, clamp phone sheet to available width. Inline Agents trigger within existing workspace/terminal header, no new global nav row/FAB/rail; Terminal panel only. Phone sheet scrim consumes touch, hides IME, focus trapped; Back/Escape close before route back, Settings/privacy have higher blocker precedence. Root computes OR of all blockers (Settings/privacy/compact agents) once; no competing setInputSuspended(false). Pinned mode permits terminal input only when terminal has focus and all other input predicates pass. Rotation preserves process-local open/filter/selection without PTY recreation; resize while open never duplicates host.
10. Agent Settings opens captured-origin retained Settings at HOST → AGENTS using selected workspace's registered profile as B; leaves preference source A unchanged and labels it. If context invalid, show explicit target choice/no ambient fallback. Preserve return panel/session/dirty editor. No dormant 12-panel Agent Store cutover.
