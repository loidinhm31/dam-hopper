- No `/api/advisor/policy/update` or harness-model endpoint, policy writer, model-listing subprocess, or fallback model catalog was found in the inspected server/UI source.
- Existing account policy DTO, API auth layers, home-directory resolution, safe-file helpers, subprocess patterns, UI provider/transport seams, fixtures, and test harnesses give clear implementation insertion points.
- The requested `server/src/advisor/state.rs` does not exist. Shared runtime state is `server/src/state.rs`; `AdvisorService` is implemented in `server/src/advisor/history.rs`.

### Current policy read contract and security boundaries

- The resolved fixed path is `<effective-home>/.evcrate/advisor-routing.json`; no client-provided path is accepted by `read_current_policy`.
- It calls `symlink_metadata` on the final candidate and rejects a symlink, non-regular file, or metadata length above 16 KiB as `POLICY_FILE_UNSAFE`; it also rejects a read whose byte length exceeds 16 KiB. It does not currently provide a writer or atomic update semantics.
- It hashes source bytes with SHA-256 into `revision`. Parse failures are `INVALID_JSON`; credential-like property names anywhere in the JSON tree are rejected as `ROUTE_CREDENTIAL_FIELD`.
- V1 documents or documents with top-level `hosts` return `migration_required`; V2 route entries reject unsupported backend values as `unsupported` / `ROUTE_ENTRY_INVALID`. Missing/invalid fields and invalid wait/history ranges return `ROUTE_SCHEMA_INVALID`.
- Disk keys are snake_case (`warn_after_ms`, `retention_days`); DTO serialization is camelCase (`warnAfterMs`, `retentionDays`). The existing V2 document includes `version`, both advisor routes, `wait`, and `history`. The routes should be updated without dropping or silently defaulting those unrelated policy values.
- The current safe-path check is on the final policy file. The implementation does not explicitly validate that `$HOME` and `.evcrate` are non-symlink directory components. The existing symlink API test concerns the history directory, not the policy file or its parent.
- `MAX_POLICY_BYTES` bounds current read input. A write path must also bound serialized output and avoid a read/modify/write race or symlink redirection. No current policy-specific lock, expected-revision check, or atomic writer exists.

## 5. Contracts, risks, and unresolved questions

1. **Update request/result and concurrency:** No body contract exists yet. A route-only request carrying `primary` and `backup` (plus optional `expectedRevision`) avoids clients replacing unrelated policy fields. `PolicyReadCurrentResultDto.revision` is already SHA-256, but there is no optimistic-concurrency check; concurrent administrators can otherwise overwrite each other.
2. **Missing, V1, or invalid current file:** Decide whether update may create a V2 document, refuses missing configuration, or requires V1 migration first. Existing read behavior distinguishes `not_configured`, `migration_required`, `unsupported`, and `invalid`; do not silently invent wait/history defaults or overwrite unparseable files without an explicit contract.
3. **Path safety/write semantics:** Existing read rejects a final-file symlink and caps size, but does not validate all ancestors. Decide how a missing `.evcrate` directory is created, which file mode/ownership to preserve, and whether directory-component symlinks are forbidden. The symlink test in the current API suite does not answer this for policy storage.
4. **Stable validation errors:** Current read exposes `issueCode`; `AdvisorError` write errors currently use generic `InvalidInput`. Define the wire shape and frontend mapping for `ROUTE_BACKUP_IDENTICAL` and invalid backend, keeping the required code observable to the inline editor.
5. **CLI contract / fallbacks:** No server-owned harness argv, parser, fallback values, model catalog DTO, or effort catalog is present; installed CLI help is summarized in §6. Specify per-harness executable/argv and bounded output/deadline; treat absent/malformed CLI output as fallback conditions. Keep the executable and args server-owned (closed backend map, no shell interpolation). Custom model text must remain supported even when it is not in the dynamic/fallback list.
6. **Harness coverage mismatch:** Routing enables four backends including `pi`, whereas current agent status `AgentKind` only has `omp`, `codex`, and `claude`. Model discovery must cover `pi` independently rather than assuming the status/integration enum already does.
7. **Advisor disabled behavior:** Existing `/policy/current` uses `check_advisor_enabled`; settings/status are accessible while disabled. Decide explicitly whether policy update and model discovery are also disabled-gated, especially if administrators are expected to edit routes while the Advisor toggle is off.
8. **Effort choices:** The policy DTO accepts effort as an arbitrary non-empty string; no supported effort options are defined per harness. Define selector values and whether custom effort text is supported rather than hardcoding a global scale from current policy examples.

**Checks:** This was a source/fixture reconnaissance report; no tests, builds, or linters were run.
