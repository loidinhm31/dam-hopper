### C. Code Standards (`docs/code-standards.md`)
- Added durable conventions for:
  - **Client Git Mutation DTOs:** Strict fail-closed typed unions with no legacy string fallbacks (`ResolveRequest` with discriminated `action`: `reviewedText`, `indexSide`, `delete`; `OperationActionRequest` with discriminated `action`: `continue`, `abort`). Wire transports must reject untyped payload shapes or legacy fallback fields (`{ path, content }`). Documented per-request precondition tokens: `conflictId`, `snapshotVersion`, `fullIndexFingerprint` on resolve; `operationPrecondition`, `fullIndexFingerprint` on operation actions. Separated the two distinct domain outcome taxonomies:
    - `ResolveOutcome`: `applied`, `stale`, `unsupported`, `busy`, `failedBeforeWrite`, `worktreeChangedStageFailed`, `outcomeUnknown`.
    - `OperationOutcome`: `continued`, `aborted`, `blocked`, `stale`, `failed`, `outcomeUnknown`.
    Blind retries on uncertain outcomes (`outcomeUnknown`, `worktreeChangedStageFailed`) are strictly forbidden.
  - **In-Memory Draft Capacity Fences:** Draft stores must remain strictly memory-only; accounted UTF-8 text bytes (`TextEncoder`), not JavaScript object heap overhead, must govern hard capacity ceilings (10 MiB total, 2 MiB per draft, 10 dirty drafts). Clean drafts may be evicted oldest-first, dirty/recovery drafts must never be silently discarded, and prospective edit growth must fail closed. Stale drift mandates operator recovery and review rather than automated replay.
