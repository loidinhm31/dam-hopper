## Critical

1. **Slow/vanished consumer pins socket tasks + child tree (spec violation, DoS on 2-slot global cap).** `semantic_ws.rs` reader arm awaits `gateway.handle_incoming_text(..)` → `send_outbound` → `outbound_tx.send().await` (`gateway.rs:995-998`, also rate-limit/binary replies `semantic_ws.rs` ~l.385-415). Queue = 32 msgs. Nonreading client: writer stuck in `ws_sink.send().await` (no deadline, no cancel race), queue fills, reader stuck inside the select arm body → `cancel_rx.changed()` never polled → loop never exits → `gateway.teardown()`/`writer_task.abort()` never run. Watcher path reaps children only on auth invalidation; it never aborts reader/writer tasks. Non-auth case (client just stops reading, or half-open TCP): nothing reaps. Doc with open overlay never idles (session idle timer needs 0 docs). `MAX_GLOBAL_SEMANTIC_TREES = 2` ⇒ one user can starve semantics for everyone. `SOCKET_SEND_TIMEOUT` (resources.rs:71) defined, **never used** (grep). Spec Req l.34/Risk l.111/Success l.100 explicitly require bounded send deadline + task abort independent of network.
   Fix: all outbound sends via `try_send` or `timeout(SOCKET_SEND_TIMEOUT, send)`; on failure/full → cancel + teardown. Wrap writer `ws_sink.send` in `timeout(SOCKET_SEND_TIMEOUT)`. Watcher must hold writer/reader abort handles (or `select!` cancel against reader body) and `abort()` after `invalidate_connection`. Completion workers (`gateway.rs:852-915`) same `send().await` → use same bounded helper and select on cancel.
2. **No heartbeat/liveness on semantic socket.** Pending guard is never `promote`d (cf. `ws.rs:296-301`, heartbeat task `ws.rs:454-491`); semantic socket has no ping, no pong deadline. Half-open peer holds child tree indefinitely (see #1). Also `PENDING_UPGRADE_TIMEOUT` = 30s prunes the reservation (`client_presence.rs:26,213-224`), so after 30s the held `pending_guard` is a no-op: presence cap does not bound live semantic sockets, and during the 30s window semantic upgrades consume shared `/ws` `max_clients` slots (violates "semantic pressure never consumes /ws capacity", Success l.104). Need: own bounded semantic connection cap (per-user/global) + server ping/pong deadline; decide whether presence is reserved-only-at-upgrade or promoted.

## High

3. **Client JSON-RPC id forwarded verbatim to child (`gateway.rs:808`, `session.rs:692-699,717`).** No shape/size cap (any JSON value up to 4 MiB incl. objects/arrays kept in `in_flight_requests: HashMap<Value,..>`), spec l.78 "cap request IDs". Duplicate in-flight id overwrites map entry (first caller gets `CANCELED`, child answers twice, 2nd answer resolves wrong request → cross-request result mix). `id:null`/missing falls to server counter starting at 100 (`session.rs:311`) → collides with client id 100 (test itself uses 100). Fix: gateway keeps `client_id → internal u64` map (reject dup, accept only int/short string ids), child sees only server ids; `$/cancelRequest` mapped via same table.
4. **URI canonical grammar not enforced** (probe run against `parse_virtual_uri`, temp test since deleted): `a%2Fb.ts`, `a/./b.ts`, `a//b.ts`, `a/b.ts/`, `%61/b.ts` all → `Ok(relative_path "a/b.ts")`. Spec l.55 requires reject encoded separators/alternative encodings. No traversal escape (`..`, `%2e%2e`, `%5C`, NUL, abs, drive rejected ✔) but aliases allowed → same doc under many URIs, cache/overlay key games, weakens later string comparisons. Existing unit tests don't cover `%2F`. Fix: after decode, reject `/`-containing decoded segments as encoded separators (split raw string on `/` first, decode per segment, reject empty/`.`/`..`/contains `/`,`\\`,NUL), then require `build_virtual_uri(parsed) == input` (round-trip canonical check).
5. **Result filtering semantics wrong vs spec l.59-60.** (a) no `outsideTarget` marker anywhere (grep: only comment) — all-outside result becomes `[]`/`null`, indistinguishable from "no definition". (b) `filter_location_or_link_result(..).unwrap_or(Value::Null)` (`gateway.rs:863-868`): one malformed/unmappable item (`InvalidRange`, `FsError`, non-file URI) aborts whole filter → *all* authorized results silently dropped to null; spec: preserve multi-results. (c) Invalid `originSelectionRange` silently omitted (`uri.rs:429-437`) vs errors for target ranges—inconsistent. (d) `validate_range` only checks ordering; no u32/UTF-16 bounds/finite checks, no result count cap. (e) destination freshness (G5) — only open-overlay version check in session.rs; unopened-destination freshness unproven and not STOP-gated.  Fix: per-item filter returns `Ok(Some)|Ok(None)|skip-on-error(+count)`; emit `{"result": [...], "damHopperOutsideTarget": true}` style flag (or explicit error code) when ≥1 item omitted for containment; cap items.
6. **Cancellation-ordering gap on writer close + close codes lost.** Watcher computes `(code, reason)` but binds `_code`, only logs `reason` (`semantic_ws.rs` watcher tail); writer always sends Close 1000 "Normal closure". Clients cannot distinguish MFA_REQUIRED(4403)/revoked(4401)/backend(1013), which `/ws` delivers. Final close send also has no timeout. Fix: carry `(code,reason)` through `watch<Option<CloseInfo>>`, write bounded best-effort close.
7. **`connection_epochs` map leaks** (`supervisor.rs:332-337`): `invalidate_connection` `entry().or_insert` for every connection (called twice per socket) and nothing ever removes. One String entry per connection forever. Fix: remove entry after final teardown (new `release_connection`) or store epochs only for live connections.
8. **`didChange` silently drops unparsable content changes yet still advances version** (`gateway.rs:636-642`): `if let Ok(change) = from_value(..)` skips bad entries ⇒ overlay diverges from editor while `damHopperDocumentVersion` fence still matches ⇒ navigation on wrong content with "fresh" version (defeats G5 fence). Reject whole message and invalidate/close doc. All didOpen/didChange/didClose errors are swallowed (`let _ =`) incl. overlay-limit exceed ⇒ client never learns doc not tracked (later `DocumentNotFound` as internal error).

## Medium

9. **Auth/Origin/live-check logic duplicated, not extracted** (spec Arch l.45, Todo "Reuse exact … decisions"). `semantic_ws.rs` upgrade token→claims→`AuthDecision`→code mapping (~100 lines) and live watcher (~100 lines) are copy-paste of `ws.rs:144-253` / `518-619`; only change to `ws.rs` is `pub(crate)` on `websocket_origin_allowed`. Drift risk (e.g. FullLoginRequired reason→code string matching is already fragile `contains("version")`). Extract `authenticate_upgrade(state,&params,&jar,&headers)->Result<Actor,Response>` and `check_live_auth(state,&actor)->Option<(u16,&'static str)>` into shared fn used by both; `/ws` keep behavior. Minus ~200 LOC.
10. **Blocking FS in async reader**: `virtual_uri_to_file_uri` (`exists`, `canonicalize`) and `dunce::canonicalize` + `directory_identity` in attach run on tokio worker per message (didChange can be high-rate, 40 msg/s). Use `spawn_blocking` or reuse `fs/secure_path` rooted helpers (spec l.56 says use them; not used). `candidate.exists()` follows symlinks: dangling in-root symlink → "not exists" → ancestor-only check passes → returns symlink path (`uri.rs:208-226`); use `symlink_metadata`.
11. **Target identity not rechecked** — `TargetBinding.root_identity` is `#[allow(dead_code)]` (`gateway.rs:83`), never compared after async resolve or per request (spec l.56 "recheck target/identity", Req l.37 immutable identity). Removed/replaced worktree keeps serving until connection ends (Phase 08 partly covers owner invalidation; in-phase attach/initialize recheck still required). `fence` target_generation hard-coded 1 (`supervisor.rs:255`).
12. **Error text leakage**: `format!("Failed to spawn semantic session: {e}")`, `"LSP child initialization failed: {e}"`, `"Navigation failed: {e}"`, `"Failed to resolve target project: {e}"` (`gateway.rs:306,474,487,837,899`) interpolate Display of Launch/ToolProfile/Session/AppError which may carry paths/child stderr summaries. Spec Sec l.116 & Success l.103: no raw child/host details. Map to fixed messages + code.
13. **Binary frames and Ping/Pong not rate-limited** (limiter only on Text). Binary flood yields 1 reply each via blocking send (see #1). Rate-limit exceeded never disconnects (unbounded error echo); message hardcodes "40 msg/s, burst 80" instead of constants; error code −32004 reused for rate limit and `RPC_ERR_IN_FLIGHT_FULL`.
14. **Outbound byte budget unenforced**: `MAX_QUEUED_BYTES` unused on outbound channel (count-only, 32 × ≤4 MiB worst case = 128 MiB/conn). Spec l.36 queue-byte limits.
15. `u64 as u32` truncation (`gateway.rs:754`): `line=4294967296` ⇒ 0. Validate `<= u32::MAX`/`i32` LSP range, reject otherwise. `damHopperDocumentVersion`, `version` default `1` on missing didOpen version — be strict.
16. Child server requests answered `Null` for any method, `workspace/configuration` → `[{}]` regardless of item count (`session.rs:755-759`, Phase 04 code but gateway depends on it): spec l.61 "reject all unknown request behavior". Return JSON-RPC MethodNotFound for non-G3 methods; size config array to `params.items.len()`.
17. Extra copy of up-to-4 MiB payloads: `msg.get("params").cloned()` (`gateway.rs:190`), `text.to_string()` for didOpen. Use `msg.as_object_mut().remove("params")` / move string.
18. Descriptor accepts `"javascript"` (`gateway.rs:262`); spec: exactly `"typescript"`.

## Verified OK
- Origin predicate reused exactly (`websocket_origin_allowed`); origin-less requires query token/no-auth; cookie-only origin-less rejected (test asserts 403).
- Token precedence query > cookie matches `/ws`; AuthDecision→status/code mapping identical; store None unreachable for session actors (`evaluate_claims` returns Unavailable when store absent).
- Watcher policy (5s tick, 2s `AUTH_STORE_LOOKUP_TIMEOUT`, version/enabled/revoked/deadline/MFA/expiry, timeout/error fail-closed) identical to `ws.rs:518-619`; ordering is supervisor-invalidate **before** `cancel_tx.send` — correct cancellation-first.
- Supervisor: tree caps rechecked under sessions write lock; runtime epoch + connection epoch rechecked after async startup under same lock; shutdown of late handle done after dropping guard; no lock-order cycle. Race with `invalidate_connection` is closed.
- Navigation: submit decoupled from completion (`submit_navigation` → spawned worker, in-flight counter RAII) — no reader head-of-line block on child latency; stale-version fence enforced in session actor; `damHopper*` extension stripped (`to_standard_lsp_params`).
- 4 MiB `max_frame_size/max_message_size` set; serde_json default depth 128 bounds nesting; binary/batch/non-object rejected.
- Child→virtual mapping drops outside/symlink-escape/sibling targets and strips unknown fields (unit tests).
