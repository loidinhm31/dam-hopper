## Warnings

### High
1. **Document fence erased by audio-source change.** `packages/ui/src/browser-host/stream-controller.ts:598-614`: new `audioRun` resets `lastAudioDocEpoch`/`retiredAudioDocEpoch` *before* validating the incoming document. Observed: accept run A/doc 1; `resetAudioAuthority("2")`; previously unseen run B/doc 1 gets delivered. Cross-socket navigation/source races can revive retired-document audio. Preserve subscription-wide document floor across source changes; validate before changing source authority. Confidence: high; read-only runtime probe reproduced.
2. **Quality callback captures initialization visibility/generation forever.** `packages/ui/src/os/BrowserStreamKeepAliveHost.tsx:1144-1195`: callback installed only when controller absent, but closes over `isSuppressed`, `isEffectiveVisible`, `qualityTuple`. Initial parked/masked controller keeps rejecting diagnostics after reveal; generation replacement can publish new-generation events into retired tuple after `releaseGeneration`. Cleanup at `:1902-1911` also captures old tuple/generation. Use current authoritative/ref-backed visibility and tuple, validate tuple against credentials; release latest owned tuple on final close. Confidence: high, static control flow.
3. **Async attachment overwrites latest mute with stale render value.** `packages/ui/src/os/BrowserStreamKeepAliveHost.tsx:1018-1029,1641-1644,1713-1719,1754-1786`: connect starts while tab `connecting`, so `canPlayAudio()` false and captured `shouldMuteAudio` true. Snapshot makes tab live while ticket mint awaits; layout effect may set false, then attachment writes captured true again. Boolean remains false next render, so effect need not correct it; unmuted UI can remain server-muted. Same pattern can override a mute changed during mint. Compute current mute from live slot/owner at admission, not effect-start closure. Confidence: high; interleaving inferred, not browser-reproduced.
4. **Quality event mixes proposed and proven settings.** `server/src/browser_host/screencast.rs:805-818,853-893`: `shared_tier = target.tier` even when run/version/quality/dimensions come from old proven snapshot; warming branches publish target settings before matching native frame. BrowserTools displays these as shared tier/resolution (`packages/ui/src/os/browser/browser-tools.tsx:183-208`). Violates applied-only contract; failed/in-flight switches can advertise fidelity never delivered. Publish coherent proven tier/settings/version; warming must not masquerade target as applied. Also snapshot read spans separate locks/awaits, allowing run replacement during construction. Confidence: high, static evidence.

### Medium
5. **Pending has no reliable acknowledgement.** `packages/ui/src/os/browser/browser-stream-quality.ts:99-115`; `packages/ui/src/browser-host/stream-controller.ts:551-576`; `server/src/browser_host/media.rs:1435-1440`: choice sets pending, server emits only changed effective state, client drops duplicate state. High/Auto requests can legitimately leave settings unchanged under safety/shared limits; "Switching…" remains indefinitely. Conversely any unrelated status clears pending before chosen preference applies. Observed unchanged status leaves pending true. Correlate accepted preference state separately from effective fidelity; do not infer acceptance from arbitrary status. Confidence: high.
6. **Rust/TS validation not identical.** `server/src/browser_host/protocol.rs:1010-1027,1201-1217,1288-1305`; `packages/ui/src/api/browser-host-types.ts:676-712`: Rust audio envelope accepts unknown fields (including additional legacy `producerRun`), TS rejects; Rust `Option<audioReason>` admits omitted field when unsuppressed, TS requires exactly 14 keys. Rust tagged parser lacks TS's overall message-size guard. TS `atob` also accepts noncanonical padding (`AAAAAB==`, observed), whereas Rust STANDARD decoder is strict. Require same exact shape, total bounds and canonical base64 policy; add shared negative fixtures. Field rename itself has no compatibility alias. Confidence: high for shape/size; base64 Rust rejection inferred from decoder policy, not independently executed.
7. **Avoidable per-frame work / status→control feedback.** `server/src/browser_host/media.rs:1716-1722`; `server/src/browser_host/screencast.rs:805-913`: every viewer/frame reconstructs event, awaits locks, clones geometry, formats UUID/version/subscription strings before equality suppresses serialization. Writer slot bounds memory, not this CPU/allocation cost. `packages/ui/src/os/BrowserStreamKeepAliveHost.tsx:586-593` additionally resends preference on *every* status/clear notification, not preference changes only (probe confirmed status-only notification triggers preference update). Use dirty/revision comparison before allocations; sampled ticker plus explicit changes; subscribe/compare preference separately. Confidence: high; no throughput benchmark claimed.
8. **Fresh-unmute race remains unproven and structurally exposed.** `server/src/browser_host/media.rs:1652-1661,1743-1766,1943-1962`: gate generation invalidates writer-slot audio, but unread broadcast chunks acquire the *current* generation only when dequeued. If unmute wins select before a ready pre-unmute chunk, that old chunk can be admitted as fresh. No source-sequence/cursor boundary at reopening. Establish an admission watermark at gate reopen, reject earlier chunks; test queued broadcast backlog with rapid mute/unmute/tier recovery. Confidence: medium; static interleaving, not runtime-reproduced.
9. **Phase lifecycle acceptance insufficiently exercised.** `packages/ui/browser-tests/host-browser-lifecycle.browser.tsx:591-620`: new "unequal viewers/reload" test only manipulates memory map then calls `releaseGeneration`; no viewer stream, reload, selector, reconnect or generation lifecycle exercised. `packages/ui/src/os/BrowserStreamKeepAliveHost.test.tsx:255-292` adds mocks but no quality lifecycle assertions; `packages/ui/src/os/apps/BrowserApp.test.tsx:202-218` adds storage setup only. Add integration regressions for warnings 1–5/8, placement/reconnect/current-generation teardown, and real keyboard interaction. Confidence: high.
