**Disposition: reject cutover acceptance.** Repository-level wire helpers improved, but production terminal lifetime/uncertainty behavior does not satisfy C6. C5 supports one outbound unbind path, not null-aware hydration end to end.

## Critical issues / acceptance blockers

1. **Critical — uncertain-create persistence is disconnected from production dispatch and restore.** `TerminalRepository.kt:55-96` dispatches both create methods without saving/loading an intent or passing a request-local admission receipt. Production screen creates (`ProjectTerminalScreen.kt:1254-1264,1493-1514,1608-1624`; `WorkbenchScreen.kt:1054-1085`) call `createSession` directly. Search across commonMain/androidApp finds no production caller of the new persistence methods outside their store implementations. Therefore Android `commit()` at `AndroidPreferencesStore.kt:149-160` does not establish a before-network barrier, and restoration/corruption cannot block subsequent creates. A lost create response/process death leaves no durable blocking evidence. Correction: wire the existing retained owner/create admission path through required storage, restore pending intents before enabling create, and settle only with exact original-success/noncreation proof. Remove silent no-op persistence defaults (`PreferencesStore.kt:39-41`). **Confidence: high.**

2. **High — all inventory-based End actions send lifecycle state as PTY epoch.** `TerminalRepository.kt:39-49` discards list headers, while `ProjectTerminalScreen.kt:1236-1243,1631-1650` and `WorkbenchScreen.kt:1100-1111` use `session.terminationState` as `expectedServerEpoch`. Server rows contain states such as `live`, not UUIDs (`server/src/api/terminal.rs:344-380,387-411`; `server/src/api/tests.rs:7633-7646`). Server rejects those bodies as malformed UUIDs (`terminal.rs:555-565`). Additionally `createSession` overwrites `terminationState` with a create-response UUID (`TerminalRepository.kt:67-69`), conflating two different domains; callers discard that result anyway. Correction: retain same-response inventory protocol version/PTY epoch separately, preserve original create epoch, validate exact inventory/incarnation before granting destructive authority. Fail closed for absent/unverified protocol. **Confidence: high.**

3. **Critical — refusal/acknowledgement is discarded; Restart still launches a replacement.** `terminateSession` converts HTTP refusal to a returned outcome (`TerminalRepository.kt:144-151`), but callers ignore it. Active End unconditionally closes the controller/removes the row after the call (`ProjectTerminalScreen.kt:1645-1658`), including on 400/409. Restart proceeds after refusal, missing epoch, or merely 202 acknowledgement to remove the original view and create another PTY (`:1235-1267`). This can leave the original process or pending restart running while a replacement starts; even fixing epoch capture alone leaves this defect. Correction: consume typed refusal/unknown/acknowledged outcomes, retain the original row, and do not infer process exit or permission to replace from an acknowledgement. **Confidence: high.**

4. **High — C5 inbound null remains indistinguishable from omission.** `UiPreferences` nullable shortcut fields default to null (`RemoteConfigModels.kt:40-51`); `getUiPreferences` decodes directly into that DTO (`RemoteConfigRepository.kt:46-49`); `applyTo` treats null as keep-current (`SettingsModels.kt:623-626`). A server `{"ui":{"searchTextShortcut":null}}` therefore keeps a previous/default active shortcut rather than unbinding it. Server schema explicitly serializes nullable shortcut values (`server/src/config/schema.rs:1057-1088`). Recreating the provider/device snapshot or switching sources can reactivate remotely unbound actions. Extra-binding state is also not represented in this production hydration/edit path. Correction: preserve presence plus JsonNull through hydration, local/storage consumers and sparse edits; omit unchanged/unknown keys. **Confidence: high.**

## Warnings

- **High — tests overstate process-death and integration coverage.** `TerminalRepositoryIntegrationTest.kt:212-240` reads the same `InMemoryPreferencesStore` instance, computes its own blocking Boolean, and never executes a create gate, reinstantiates a provider/store, drops a response, or asserts zero replacement requests. `:140-209` supplies correct epoch directly to the repository, bypassing broken inventory/UI binding. `TerminalLifetimeContractTest.kt:21-179` mainly covers serialization/value objects. Add real provider/store recreation and dropped-create/dropped-terminate production-path tests; include original epoch mismatch and corruption/failed-commit barriers.
- **Medium — local hide is not retained separately from inventory.** Local Remove is mutation-free (`ProjectTerminalScreen.kt:1291-1300`; `WorkbenchScreen.kt:1120-1144`), but only filters the current session list. Next inventory assigns all rows back (`ProjectTerminalScreen.kt:686-694`); there is no hidden-instance filter or explicit reopen in these handlers. The active tab close still opens a dialog labelled “Close Terminal Session” that invokes remote termination (`:1053,1629-1651,2110-2120`), rather than offering clearly separate Close View and End actions.
- **Medium — corruption error is lazy and nonreactive.** Android initializes ordinary preferences/source only (`AndroidPreferencesStore.kt:41-44`); uncertain-create corruption is discovered only on explicit record load (`:133-145`). Settings captures `storageError` once (`SettingsRepository.kt:211-212`). Without startup uncertain-record loading/error propagation, preserved bytes do not become a visible recoverable error or admission block.
- **Medium — request validation accepts arbitrary epoch/incarnation strings.** `TerminateSessionRequest` only rejects blanks/version mismatch (`TerminalModels.kt:145-155`); lowercasing and size bounding (`TerminalRepository.kt:126-132`) do not prove UUID/canonical positive u64 validity. Actual `live` inventory values reach the wire. Validate canonical forms before dispatch; never synthesize an incarnation such as the `"1"` fallback at `ProjectTerminalScreen.kt:1633`.
- **Medium — obsolete/dead paths and duplication remain.** `updateGlobalDefaults` still exposes the retired `/api/global-config/defaults` mutation (`RemoteConfigRepository.kt:96-112`), with no production caller found. `PatchValue`/`RawGlobalConfigDocument` have no production consumers (`SettingsModels.kt:756-793`); `createSessionGuarded` is test-only. `toSparsePatch` duplicates the complete field list in `toPatchObject` (`RemoteConfigModels.kt:63-131`), while the repository separately enumerates 12 shortcut keys. These invite drift and violate clean-cutover/KISS/DRY intent.
- **Medium — unknown-key test checks omission only.** `SettingsRepositoryTest.kt:306-318` correctly inspects an outbound sparse body, but its server handler only returns `updated:true` (`:177-178`); it does not mutate/reload remote config. It does not establish remote preservation, null hydration, extra bindings, or null/empty/omitted distinctions.

## Suggestions

1. Address create admission/restore and epoch identity first, then outcome handling before running live destructive smoke.
2. Use one production null-aware patch/projection representation; derive wire serialization rather than maintaining parallel field lists. Keep unknown OS keys unpresented and untouched.
3. Delete obsolete defaults mutation and unused alternate abstractions once callers are migrated; do not add another terminal owner/runtime.
4. Main should run stopped-wave shared/app compilation, scoped terminal/settings regressions, real provider dropped-response/restoration scenarios, and live Settings/PTY smoke. Do not treat the current serialization/in-memory tests as acceptance evidence.

## Positive observations

- Termination helper uses POST, encodes the ID path segment, sends version 1 and a string incarnation, lowercases the supplied epoch, and checks UTF-8 body size <=512 bytes (`TerminalRepository.kt:121-137`). No all-zero epoch fallback was found in reviewed actions.
- Outbound production Settings saves really call `updateGlobalUiSparse` with a request-local guard (`SettingsRepository.kt:365-395`). Nonblank-to-empty known-shortcut edits become JsonNull; unrelated keys remain omitted.
- Android record writes/removals use checked synchronous `commit()` and decode failures retain original raw data plus a recovery copy (`AndroidPreferencesStore.kt:133-174`); useful implementation pieces, but not connected to production create admission.
