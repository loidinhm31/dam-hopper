## 1. Executive Summary

### Issue Description & Business Impact
GitHub Actions run `36096912370` failed during release execution for `v0.5.0`. Specifically, job `Build Rust release binary (x86_64-pc-windows-msvc)` failed at step `Build Windows release server binary` with 11 Rust compilation errors (`E0432`, `E0433`).
Downstream release jobs (`Package deterministic Windows archive and installer`, `Publish immutable GitHub release`, `Generate GitHub artifact attestations`) failed to run or were canceled. The `v0.5.0` Windows release binary and distribution archive could not be generated.

### Root Cause
PR #34 (`feat/plugin-platform`, merged in `9f317b64`) added `server/src/plugins`, introducing two platform-specific compile-time defects on Windows targets (`x86_64-pc-windows-msvc`):
1. **Unconditional `tokio::net::unix` imports in `plugins`**:
   `tokio::net::unix::OwnedWriteHalf`, `tokio::net::UnixStream`, and `tokio::net::UnixListener` were imported unconditionally in `server/src/plugins/runner_client.rs` and `server/src/plugins/runner_server.rs`. In Tokio 1.x, the `unix` module and Unix domain socket types are conditionally compiled under `#[cfg(all(unix, feature = "net"))]` and are completely absent on Windows.
2. **Missing `durable_fs` facade in `linux_release_windows.rs` & ungated Unix calls**:
   Modules `package_extract.rs`, `registry.rs`, `registry_journal.rs`, and `lifecycle_journal.rs` call `crate::linux_release::durable_fs::{atomic_write_file, sync_dir}`. On Windows, `server/src/lib.rs` mounts `linux_release_windows.rs` instead of `linux_release/mod.rs`. `linux_release_windows.rs` omitted `pub mod durable_fs;`, leading to 8 `cannot find durable_fs in linux_release` errors (`E0433`). Furthermore, `server/src/linux_release/durable_fs.rs` contained ungated POSIX calls (`fs::Permissions::from_mode` and `File::open(dir)`).

### Priority
**P0 (Release Blocker)**: Required for compiling release binaries on Windows runner and unblocking the `v0.5.0` release pipeline.

### 2.3 Detailed Root Cause Analysis

1. **`server/src/plugins/runner_client.rs` & `server/src/plugins/runner_server.rs`**:
   The author previously guarded several Unix-specific traits in `runner_client.rs` and `runner_server.rs` using `#[cfg(unix)]` (such as `std::os::unix::fs::PermissionsExt` and `stream.peer_cred()`). However:
   - Imports of `tokio::net::unix::OwnedWriteHalf`, `tokio::net::UnixStream`, and `tokio::net::UnixListener` remained top-level and ungated.
   - `ConnectedSession` held `writer: Arc<TokioMutex<OwnedWriteHalf>>`, making the struct unconstructible/unusable on Windows.
   - `RunnerClient::connect_and_handshake`, `execute_call`, and `execute_invoke` had no non-Unix fallback returning `PluginError::runner_unavailable(...)`.
   - `RunnerServer::run(&self)` directly called `UnixListener::bind(...)` with no non-Unix stub.

2. **`server/src/linux_release_windows.rs` & `server/src/linux_release/durable_fs.rs`**:
   - `server/src/lib.rs` delegates `linux_release` on Windows to `server/src/linux_release_windows.rs` (commit `851e6f4`).
   - `linux_release_windows.rs` did not re-export `durable_fs.rs`.
   - When `server/src/plugins/` was implemented, modules called `crate::linux_release::durable_fs::{atomic_write_file, sync_dir}`. On Linux this resolved to `server/src/linux_release/durable_fs.rs`, but on Windows it resolved to `server/src/linux_release_windows.rs` where `durable_fs` was absent.
   - In `server/src/linux_release/durable_fs.rs`:
     - Line 61: `fs::set_permissions(path, fs::Permissions::from_mode(0o755))` called Unix-only `PermissionsExt::from_mode`.
     - Lines 37-44: `sync_dir` opened `dir` using `File::open(dir)` and called `f.sync_all()`. On Windows, standard `File::open` on a directory returns `ERROR_ACCESS_DENIED` (os error 5).
