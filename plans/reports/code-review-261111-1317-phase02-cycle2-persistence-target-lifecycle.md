## Critical issues

1. **Runtime preflight still fails open before destructive DELETE.** `packages/ui/src/os/browser/browser-close-lifecycle.ts:125-147` catches every non-404 GET failure and continues to DELETE. Meanwhile `browser-native-reference-census.ts:31-37` excludes a retained reference with incompatible runtime. With a retained replacement-runtime reference plus failed exact GET, the newly added mismatch check never executes and deletion is still authorized. Late-create and inventory callers omit available runtime evidence (`browser-create-lifecycle.ts:120-125`; `browser-session-inventory.ts:89-102`). **Fix:** fail closed on unverifiable GET/runtime, retain blockers, carry captured response/selected-target runtime into closure, and recheck owner/reference/runtime before dispatch. Do not let an incompatible reference prove safe deletion of the replacement.

2. **Late-create cleanup loses durable ownership before cleanup is secured.** `browser-create-lifecycle.ts:108-135` removes the create marker before deciding adoption versus cleanup. On owner change the exact target exists only in `withheldCleanups`; reload loses it and the durable unknown/group blocker has already disappeared. `processWithheldCleanups` has no production caller; it also removes queue entries before an unawaited close stages or succeeds (`48-58`). Immediate cleanup is likewise detached, omits captured runtime/group linkage and can reject during staging without an owner handling it. **Fix:** retain the exact outcome and original durable group blocker until adoption or reference-safe cleanup plus durable settlement; wire original-scope resumption, await/handle staging and outcome, and remove queue ownership only after proven completion. No retry framework needed.

## Warnings

1. **High — coordinator still treats rejected close as completion and has unfenced mutation gaps.** `browser-window-close-coordinator.ts:74-95,103-114,117-154`: only `unknown` sets `hasUnknown`; runtime/owner rejection therefore settles parent and removes the window although target remains. Replacement-window state can be marked closing after the first staging await; the final operation-ID check happens before another awaited stage/settlement and is not repeated inside the state updater. The legacy branch still removes in `.finally`, even on unknown/staging failure (`165-173`). Child-stage failure is only logged and can strand a pending shell (`156-159`). **Fix:** remove only on proven `closed`/`released`, retain/report every other outcome, and fence each local commit by captured window incarnation/operation after its last await. Retire or safely handle the still-reachable legacy branch.

2. **High — durable settlement failure is reported as success.** `browser-close-lifecycle.ts:93-105,128-150` and `browser-create-lifecycle.ts:104-109,141-148` swallow settlement errors. A successful DELETE followed by blocked storage returns `closed`, opens the gate and permits shell removal while durable recovery still says unresolved. Followers have the same problem. Exact DELETE 404 is also classified unknown by the outer catch, despite being a named settlement condition. **Fix:** propagate continuity failure/unsettled state; retain the blocker/gate until exact settlement commits. Handle typed exact DELETE 404 explicitly.

3. **High — atomic admission still missing.** `browser-session-inventory.ts:33-37,71-82` adds a post-GET check but only returns a DTO; it does not atomically install the retained reference. A final close may pass census and enter its gate between that return and caller admission. `browser-close-lifecycle.ts:86-107` serializes only in-flight DELETEs, not admission commits. **Fix:** provide one native-key guarded local admission/release commit, not a check-then-later-attach API. Recheck scope/runtime within that commit. No new registry required.

4. **High — restored gates absent on reload; notification refresh never removes settled gates.** Only production call to `restoreClosingGatesFromRecovery` is inside the future storage-event handler (`OsShell.tsx:252-278`); initial hydration (`203-210`) never restores gates or unresolved notices. Existing durable markers thus do not block initial inventory admission. The restoration routine only adds to its Set (`browser-close-lifecycle.ts:38-47`): another document's settlement cannot clear a gate previously restored from its pending record. Same-document commits also have no notice refresh. **Fix:** initialize recovery gates/notices before hydration publication and reconcile durable-derived gates on refresh, preserving separate active local gates; publish writer-local committed changes too.

5. **High — strict validation remains incomplete; Browser corruption can be silently overwritten.** `persistence.ts:69-70` discards parser errors. `browser-persistence.ts:119-167` skips malformed tab entries, invents IDs/blanks and silently repairs invalid active selection; local hints survive missing/invalid owner scope (`130-132,170-187`). `browser-recovery-validation.ts:35-64` accepts arbitrary group address elements, fractional/out-of-range active indexes, arbitrary operation kinds and unvalidated optional session/group/tab IDs; duplicate operation IDs are not rejected. Duplicate IDs can cause exact settlement to erase multiple records. **Fix:** validate complete nested contracts and scope/ID uniqueness, propagate visible parse failures and preserve original bytes; keep legitimate URL omission/popup exclusion distinct from malformed schema rejection. Output-size checks added this cycle are useful, not sufficient.

6. **High — hydration gate can permanently skip deep links.** `OsShell.tsx:281` reads `hydrated`, but dependency list `381-389` omits it. If handlers/profile are ready while the recovery lock delays load, the effect returns while unhydrated and hydration completion alone does not rerun it. **Fix:** add `hydrated` to dependencies; author delayed-lock regression with already-ready handlers and no other dependency changes.

7. **Medium — recovery failure discards valid unrelated OS state from the loaded view.** `persistence.ts:692-704` handles recovery get/parse failure as corrupt OS JSON, returns a completely default session and labels the notice `corrupt-data`. The outer lock-failure path already preserves non-Browser state/exact hints while withholding URLs (`707-720`). **Fix:** separate valid-OS parsing from recovery access failure; report continuity/storage error, preserve unrelated windows and validated hints, withhold Browser addresses and keep writes blocked. Raw recovery must remain untouched.

8. **Medium — restore blocker expanded from affected group to entire owner.** `browser-recovery-store.ts:121-125` returns true for every pending/unknown operation of the owner even when its group differs from the selected group. An unrelated abandoned create can disable future independent remembered-group restores indefinitely. **Fix:** block only operations associated with the affected group; preserve unrelated unresolved notices.

9. **High — required fault/race regressions still unauthored.** Six Browser test files remain mostly happy-path cases; lock doubles immediately invoke callbacks without exclusion (e.g. `browser-recovery-store.test.ts:35-43`). Runtime mismatch got one direct service test, but no rejected coordinator case. Missing authored cases include corrupt/blocked recovery get/set/settlement, mixed multi-target outcomes, close-during-create and owner-return cleanup, replacement-window fencing across delayed storage, simultaneous hidden cross-profile release, admission-commit race, hydration/deep-link timing, malformed nested recovery, both public import/export authority paths and stale-suppression writes. **Fix:** queued-lock/deferred unit cases for each finding; retain planned real two-document Phase 05 qualification. The later execution gate does not waive Phase 02 test authoring.

## Suggestions / architecture / performance

- Keep focused modules, explicit projection modes, shared storage exclusion and no new backend API/dependencies/polling. These are good KISS/YAGNI choices.
- Preserve improvements: distinct target operation IDs, suppression-aware group staging/consume, frozen URL/viewport request, projection output bound, post-GET inventory owner checks, and pre-hydration flush guards.
- Reuse active-selection remapping in remembered-group projection: `browser-group-projection.ts:18-25` defaults an active popup to index zero instead of its surviving opener. Shared resolver also needs nearest-ordinary fallback when opener is absent (`browser-url-normalization.ts:29-39`).
- Remove dead imports in `window-store.ts`, unused coordinator `win` and unused cleanup `currentScope`; avoid callback-driven correctness and unchecked `as unknown as` casts where typed local commits suffice.
- No new hot polling or broad algorithmic regression identified. Recovery work is byte-bounded, but duplicated parse/project serialization on every save is secondary to correctness; do not introduce a cache that bypasses fresh locked reads.
