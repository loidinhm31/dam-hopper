## Critical Issues (3)

1. **Test-harness bearer credentials can be sent over arbitrary remote cleartext HTTP.** `native/android-app/androidApp/src/androidTest/kotlin/dev/damhopper/nativeapp/NativeTerminalAgentsServerFixture.kt:174-180` constructs a caller-supplied URL and unconditionally adds Authorization when a token is provided. Runner URLs are unrestricted at lines 48-54. Unlike the production request boundary, no HTTPS-or-loopback restriction is enforced. A credentialed run against `http://<LAN/public-host>` transmits the token in cleartext. **Correction:** validate credential-bearing origins before any request; allow HTTPS or verified literal loopback only, reject userinfo, and disable redirects or enforce same-origin redirect policy. This is an instrumentation-fixture vulnerability, not a finding that the production ApiClient sends these requests. **Confidence: high.**

2. **Contradictory inventory can win the final-admission race.** `native/android-app/androidApp/src/main/kotlin/dev/damhopper/nativeapp/platform/workspace/TerminalAgentsActivationCoordinator.kt:270-284,349-360` accepts the first entry matching terminal ID and never rejects a second entry with another incarnation/canonical target. `TerminalAgentsInventoryCoordinator.kt:438-450` first publishes that response as CURRENT and completes activation waiters; conflict marking occurs later through `RetainedTerminalAgentsCoordinator.kt:80-84`. Interleaving: captured valid target -> activation refresh returns `[matching target, conflicting same-ID entry]` -> waiter resumes before projection collector -> first-match validation and final CURRENT check pass -> route commits -> collector eventually marks CONFLICT. This violates the required fail-closed canonical ownership rule. **Correction:** reject contradictory ID metadata synchronously during receipt acceptance, or repeat ambiguity validation under the final roster gate. Do not depend on a projection collector to establish admission authority. Add a deterministic test that delays that collector. **Confidence: high; race derived from source, not reproduced.**

3. **Required live qualification is an incomplete journey that falsely passes missing prerequisites.** `native/android-app/androidApp/src/androidTest/kotlin/dev/damhopper/nativeapp/NativeTerminalAgentsJourneys.kt:46-49` prints a message and returns normally when servers are unavailable, making JUnit record a pass. Its only test, lines 52-84, creates two `sh` PTYs and checks two controls; it does not establish authenticated profiles, navigate projects, create/verify observed agent rows, exercise dirty-guard/refusal, inactive exit/restart, reconnect, Settings A/B, input isolation or recreation. Its exact selectors also disagree with production: `"Agents"` versus `"Agents, N eligible terminals"`, and `"Filter agents"` versus `"Filter agents by status: ..."`. `RetainedWorkspaceLifecycleTest.kt:113-130` only rereads the same service from the same ViewModel after calling a hook; it does not recreate Activity or check nondefault filter/open/selection/controller state. **Correction:** implement the Phase05 journeys against actual MainActivity and configured disposable servers; required qualification must fail/report blocked when prerequisites are absent, never return a passing no-op. Replace hook-only lifecycle evidence with actual recreation assertions. **Confidence: high.**

## Warnings (6)

1. **Display cache is rebound before status requalification.** `native/android-app/androidApp/src/main/kotlin/dev/damhopper/nativeapp/platform/workspace/TerminalAgentsInventoryCoordinator.kt:448-450,474-480` replaces cached inventory and each published workspace's runtime/tab metadata while retaining the prior attachment's observations. With the same terminal ID/incarnation on a replacement attachment and no successful new status baseline, `TerminalAgentsMembership.kt:148-174` now treats the new receipt/workspace as fresh and joins old cached observations to new metadata, assigning the successor runtime/fence. The frozen last-qualified join and its old non-routeable target are lost, contrary to contracts.md:96. Example: old observed terminal title A, replacement inventory title B, new baseline fails -> unavailable row now has B's target/metadata although B never requalified its observation. **Correction:** retain the complete last qualified membership/status/runtime join until a new qualified join supersedes it; do not advance cached workspace/target identity merely because listDetailed succeeded. **Confidence: high.**

2. **Snapshot-loading state can still render Working/Done.** `native/android-app/shared/src/commonMain/kotlin/dev/damhopper/nativeapp/features/terminal/TerminalAgentsPresentation.kt:24-39` ignores `snapshot.status.isSnapshotLoading`. `AgentStatusReducer.kt:216-223` preserves an installed baseline while starting another snapshot, so the projector can return READY during that request and the cache updater can capture it as qualified. contracts.md:98 explicitly requires loading to close current qualification. **Correction:** downgrade loading to UNAVAILABLE and preserve only display-qualified cache; add a loading-with-existing-READY-baseline case rather than only loading-without-baseline. **Confidence: high.**

3. **Mounted roster participants still issue independent full-list requests.** `native/android-app/shared/src/commonMain/kotlin/dev/damhopper/nativeapp/ui/screens/ProjectTerminalScreen.kt:548-564` falls back to its own listDetailed whenever lastAgentsRuntime is unknown or shared refresh fails. Initial mounting can therefore race the runtime's connected fetch, and failure causes an additional uncoalesced request. This defeats the single-runtime requester contract and can install a screen-local list without an accepted receipt. **Correction:** resolve/join the retained runtime inventory for participants; an unavailable shared result should remain unavailable. Keep the old requester only for genuinely nonparticipating/no-service callers. **Confidence: high.**

4. **Lower Agents sheet intercepts Back underneath search after resize.** `native/android-app/shared/src/commonMain/kotlin/dev/damhopper/nativeapp/ui/screens/DamHopperMobileApp.kt:420-430` registers the compact-sheet interceptor without checking external cover. Repro path from source: open pinned Agents -> open search -> resize below 600dp -> search stays topmost, sheet becomes compact underneath -> MainActivity's Back dispatch invokes the sheet interceptor and closes the lower sheet instead of search. WorkspaceSearchView has no Back owner. **Correction:** dispatch Back to rendered search first and only enable the Agents interceptor while its sheet is the topmost surface; keep higher cover intact across resize. **Confidence: high; source-traced, not device-exercised.**

5. **Deferred sheet origin/request ownership is lost on Activity recreation.** `native/android-app/shared/src/commonMain/kotlin/dev/damhopper/nativeapp/ui/components/TerminalAgentsSidebarHost.kt:241-253,284-286` stores closeGate and pendingRequestId only in remember. The root saver (`DamHopperMobileApp.kt:853-856`) retains only open. If a deferred activation has returned, rotating creates a new host with no tracked request while the retained coordinator still owns the confirmation continuation. Its later matching Committed receipt cannot close the restored sheet; pending indicator/duplicate-click prevention is also lost. No receipt replay reconstructs tracking. **Correction:** retain/save the origin's exact request identity and restore its ownership without accepting another origin's receipt. Test deferred click -> recreate -> confirm/refuse. **Confidence: high.**

6. **Actual coroutine cancellation is not fenced at the mutation boundary.** `native/android-app/androidApp/src/main/kotlin/dev/damhopper/nativeapp/platform/workspace/TerminalAgentsActivationCoordinator.kt:129-134,290-305,349-379` spends a request only after a CancellationException is observed; final predicates inspect RequestState, not the activating Job's activity. Cancellation from another thread after entering Main/admission but before the first mutation can leave the request LIVE and commit anyway. Conversely, a cancelled dispatcher return can throw after a real commit; the internal receipt remains committed, but immediate sheet tracking is established only after activate returns. The test at `TerminalAgentsActivationCoordinatorTest.kt:458-475` calls cancelPending; it does not cancel the coroutine Job or exercise prompt dispatcher-return cancellation. **Correction:** bind request lifetime to its owning Job, check cancellation at the admitted pre-mutation boundary, and test both sides of linearization with a real dispatcher hop. Preserve committed outcomes after the leaf; do not undo them. **Confidence: medium-high; timing derived from source, not reproduced.**

1. **Avoid duplicate projection work.** `RetainedTerminalAgentsCoordinator.kt:83-84` joins full membership for conflicts, then DefaultTerminalAgentsProjector performs the same join again. Reuse one evaluated join for conflict reporting and projection rather than sorting/grouping/allocating twice per status tick.
2. **Reuse canonical labels.** UI `TerminalAgentsGroupRow.kt:42-67` duplicates status/reason/source labels from TerminalAgentsPresenter. Share the existing pure label functions; keep only harness-specific UI labels local.

Either implement that fixed mutation-only publication or explicitly revise/test the contract; do not claim all public StateFlows change atomically merely because the internal receipt does.
