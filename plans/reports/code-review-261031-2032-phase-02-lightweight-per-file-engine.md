Findings below are grounded in current source. Runtime consequences/interleavings marked **[INFERENCE]** were not reproduced with new tests. Confidence high unless stated otherwise. Passing existing tests does not establish missing acceptance cases.

### Critical issues

1. **Unsafe path-based reads permit containment races and false originals.** `server/src/session_changes/capture.rs:70-120`. Ancestors/target are lstat-checked, then `std::fs::read` independently resolves the path, following any newly substituted symlink. The root itself is not pinned/revalidated. Post-check compares only length, ignores failure, and does not verify identity, symlink type, mtime or permissions. **[INFERENCE]** Replacing a checked ancestor/target can disclose outside-root files through baseline/detail; same-size replacement or deletion after read can still seal an incorrect original. Correction: descriptor-relative no-follow/beneath traversal from a pinned authorized root; bounded read from that descriptor; identity/type/stability checks before and after. Safely detected ENOENT alone can establish absence; other races must seal unknown.

2. **Capture publication and OFF/purge have opposite lock ordering.** `capture.rs:463-485`, `store.rs:148-153,165-170`. Capture holds `records` then requests `lifecycle.read()` through `try_reserve_storage_for_generation`; purge holds `lifecycle.write()` then requests `records`. **[INFERENCE]** Concurrent capture publication and OFF deadlock, blocking purge and shared record access. Correction: consistently acquire lifecycle before records, validate under that order, and avoid recursively requesting lifecycle inside an already protected transaction. Add deterministic lock-order coverage.

3. **Timeout invalidation/concurrent first touch can publish post-edit bytes as original.** `capture.rs:323-338,382-395,449-524`. `unproven` seals a pending entry, but the pending worker never checks reservation/capture ID before overwriting it. A sealed result from the same timed-out attempt is never downgraded. Concurrent first touch returns `alreadyKnown` even when the original is still pending; the producer treats this as acknowledgment (`server/src/agent_status/assets/omp-session-changes.ts:992-995`). Publication checks neither expected baseline nor record generation/reservation; only present-byte reservation checks the service generation. **[INFERENCE]** A tool proceeds after timeout/concurrent acknowledgment, and its edited bytes become the claimed immutable original; OFF/ON plus re-registration can also let old work mutate a replacement record. Correction: one reservation state machine with capture-ID, baseline, generation and deadline fences; pending is not acknowledgment; exact-attempt unproven cancels pending publication and downgrades its unacknowledged sealed result while preserving independently acknowledged originals. Cancellation must seal/release reservations.

### Warnings

1. **High — memory bounds apply after allocation and omit comparison storage.** `capture.rs:93-110,138-140,484-495`; `comparison.rs:23-33,69-76,88-95,255-262,461-464`. `fs::read` is unbounded if a file grows after lstat; cap detection happens after allocation. Probe clones bytes, comparison clones the tracked map and originals, and cached original/current buffers have no global accounting or admission. **[INFERENCE]** 500 unproven paths can retain approximately 1,000 MiB of current bytes in one comparison while the global baseline counter remains zero. Correction: reserve before allocation, capped descriptor reads, RAII release, shared immutable original buffers, and admission/accounting for every retained comparison/current byte.

2. **High — 500-path cap is not a cap.** `capture.rs:317-357,396-414`. Pre-edit over-cap handling inserts another entry; unproven inserts without any cap or syntax validation. Repeated requests grow metadata without bound; invalid raw paths are retained before probing. Correction: validate/canonicalize literal paths and request count/length before mutation; reject unknown paths when no slot remains without inserting them; preserve existing known paths. The 501st-path test (`capture_tests.rs:306-328`) checks only response, not map length.

3. **High — two blocking permits and comparison deadlines are ineffective.** `capture.rs:454-456`, `comparison.rs:39-40`, `comparison.rs:527-565`. `acquire_owned()` returns a future that is never awaited/polled; no permit is held. Public comparisons can spawn unrestricted blocking jobs, with no overall deadline. Detail performs synchronous filesystem/Git work directly on an async handler thread while holding the global record mutex, bypassing permits altogether. Correction: acquire an actual owned permit before spawning, move it into the closure through completion, reject saturation with busy, enforce bounded evaluation deadlines, and perform detail reads outside locks/off runtime workers with fenced publication.

4. **High — detail coherence and rendering limits are incomplete.** `comparison.rs:552-565,567-619`. Mutation checking runs only when a previous current buffer exists and compares hash only. Deleted files recreated after comparison and mode-only changes with identical bytes are not rejected. Renderable depends on kind, not text byte/line/line-length limits or successful UTF-8 decoding; detail can return both full 2 MiB sides without the combined text/serialization/concurrency limits. Correction: compare complete current presence/mode/content fingerprints for every row and enforce existing text/detail limits before constructing content. Stale state must return refreshRequired.

5. **High — capture incarnation and path-exclusion contracts are incomplete.** `capture.rs:290-305,35-68,70-169`; `control.rs:238-289`. Capture validates the bearer-derived incarnation string, not `req.terminal_incarnation`; mismatched request tuples are accepted. Lookup ignores request version/known tuple fields. Probe has no explicit nested repository/gitlink/.git ancestor policy; gitignore query errors default to eligible. Correction: validate the full tuple/version and normalized path contract before reserving slots; restore direct per-path nested-root/exclusion checks without directory enumeration, failing conservatively when eligibility cannot be established.

6. **Medium — counts claim unsupported changes are exact zero.** `comparison.rs:178-211,266-289`; `inventory.rs:15-16`. Added binary/non-UTF-8 files produce `additions: 0` and can leave countsComplete true; added overlong-line text discards the incomplete flag. Deleted invalid UTF-8 can emit row deletion count zero. NUL-only binary classification labels other invalid UTF-8 text and detail may say renderable while content is absent. Correction: propagate unsupported/non-UTF-8/text-limit reasons and null counts consistently; reuse bounded text eligibility logic for added/deleted/modified cases.

7. **Medium — cursor and stable file-ID contracts regress.** `api/session_changes.rs:238-307`; `comparison.rs:110,156,195,277,358,487-515`. Cursor without revision triggers a new comparison and applies an old offset to it. Invalid cursor silently becomes page zero; cursor is just an unqualified offset. Rows use ordinal fid-N instead of the retained UUID, changing identity when preceding rows disappear. Serialized page cap is unused. Correction: require revision on cursor requests, reject malformed/unqualified cursors, use the retained file ID, and enforce serialized page bounds.

8. **High — Windows compilation regression.** `capture.rs:3`. `use std::os::unix::fs::PermissionsExt` is unconditional despite the guarded usage below. The documented Windows server cannot compile this import. Correction: guard the import with `#[cfg(unix)]`; validate the supported Windows target in CI. Windows build was not exercised here.

9. **Medium — metadata readiness and disabled behavior disagree across endpoints.** `store.rs:250-263`, `binding.rs:53-59`, `control.rs:248-270`. Full status computes incomplete from entries, but retained selectors use rec.state, initialized ready and never updated by capture. Disabled lookup returns HTTP 200/unavailable instead of required no-store 503 trackingDisabled. Correction: share one metadata status projection and one disabled HTTP policy.

10. **Medium — cutover and qualification remain incomplete.** `types.rs:53-78,125-146,171,322-375,482-585,749-759`; `types_tests.rs:13-31,70-79,118-124`. Rust retains obsolete producer DTOs/barrier states/from-now origin and a legacy provenance deserialization alias; Rust tests still exercise the retired contract. Keeping old fixture vectors for TS does not require production Rust aliases/types. Existing lifecycle tests named capture races only invoke register (`session_changes_lifecycle.rs:125-225`), and the 64 MiB test directly exercises the atomic counter rather than real capture/comparison ownership (`capture_tests.rs:371-387`). No deterministic no-I/O/no-diff seams, pending/unproven late-publication tests, same-path races, file-growth tests or full root/revision/disabled contract fixtures were found. Phase 02 remains pending in its plan. Remove dead Rust protocol surface, retain only TS-needed fixture data, and qualify the actual paths. Documentation still describes AbsenceTrie/128–512 MiB old limits (`docs/code-standards.md:122-136`) and TargetUnavailable disabled semantics (`docs/project-overview-pdr.md:79-80`); update current normative documentation without rewriting historical reports.

### Suggestions / positive observations

- Preserve the good architectural direction: absence modules and recursive inventory removed; comparison iterates observed paths only; settled/status/lookup have no explicit content reads or diff spawning; public refresh propagates rootId; viewer requests do not manufacture baselines; API responses generally use no-store.
- Prefer one small reservation/publication helper and one bounded file-probe/content-eligibility helper over duplicated state assembly. This addresses DRY without adding a generic framework.
- Replace decorative/dead fields/constants with enforced contracts or delete them: reserved_at, capture_id ownership, dirty_settled_hint, last_settled_turn_id and multiple resource constants currently do not enforce the promised behavior. Use the stored settled turn when publishing viewer metadata where required.
- Fix correctness/security findings first, then run deterministic regression gates; do not treat the passing happy-path suite as a reason to relax these bounds.
