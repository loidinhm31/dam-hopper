## Phase 02 Code Review — Cycle 2

**Score: 4/10 — changes required; Phase 02 not ready for acceptance.**

Review: security, correctness, resource bounds, lazy execution, architecture, YAGNI/KISS/DRY. Implementation was inspected, not modified. No plan/task-state updates, per assignment. Runtime interleavings and exploit consequences below are **[INFERENCE]**, not newly reproduced. Confidence high from source unless stated otherwise.

### Confirmed improvements

- Capture publication now takes `lifecycle` before `records` and reserves storage directly inside that transaction. The previously identified lock inversion is removed (`capture.rs:561-567,613`; `store.rs:148-154`).
- Unix descendant traversal uses descriptor-relative no-follow opens and bounded descriptor reads; a pending entry sealed by unproven cannot subsequently be overwritten by its worker (`capture.rs:62-139,578-600`). These are meaningful partial fixes, not full containment/timeout resolution.
- Both capture modes stop inserting new paths at 500. Rows use stable retained file IDs; malformed cursors are rejected; cursor requests require a revision.
- Comparison artifacts retain metadata, not duplicate original/current buffers. Modified binary counts are honestly unavailable. Detail reads moved off the async runtime and detect changed content hashes.
- Lookup now validates version/known epoch and returns disabled 503. Retained selectors account for unknown entries. Unix imports are guarded.
- Settled/status/lookup remain metadata-only by inspected control flow; no recursive inventory, absence modules or from-now route remains.

### Critical issues

1. **Containment still fails at the root and on non-Unix platforms.** `server/src/session_changes/capture.rs:42-45,164-205`; `store.rs:71`; `root.rs:157-208`. The record stores a pathname, not an authorized directory handle/identity. Every Unix probe opens that pathname with `File::open`, following a substituted root or ancestor symlink before descendant `openat` protection begins. **[INFERENCE]** Rename the authorized root and replace its old path with a symlink to another directory: subsequent capture/comparison can read that directory's files. On non-Unix, even a pre-existing symlink/junction ancestor is unchecked: only the final path is lstat-checked, then `fs::read` follows the whole path. Correction: pin/validate the authorized root handle during registration; perform traversal relative to it, using equivalent Windows handle/reparse-point containment. Fail closed where safe probing is unavailable. Guarding imports only fixes compilation, not Windows security.

2. **Timeout and concurrent first-touch semantics can still adopt post-edit bytes.** `capture.rs:424-439,495-508,532-555,578-621`; producer `server/src/agent_status/assets/omp-session-changes.ts:991-995,1008-1025`. Existing pending entries return `alreadyKnown`, which the producer treats as permission to proceed; the original worker may not have opened the file yet. Unproven invalidates only a matching *Pending* entry; once a worker seals the result, the same timed-out attempt cannot downgrade it, despite retained `entry.capture_id`. `reserved_at` is never checked. **[INFERENCE]** Client timeout allows the tool to edit, worker reads/publishes those bytes, then the invalidation arrives and leaves that false original intact. Concurrent preEdit requests can similarly proceed while the first read is pending. Correction: do not acknowledge pending reservations as established originals; enforce reservation expiry/ownership, and conservatively downgrade sealed results from the same unacknowledged attempt, releasing their storage. Preserve earlier independently acknowledged attempts. Add deterministic tests for both orderings.

### Warnings

1. **High — special files can hang workers before rejection; deadlines remain unenforced.** `capture.rs:86-115`; `comparison.rs:42-58,373-375,541-545`; `types.rs:15,26`. Final `openat` is blocking `O_RDONLY` without `O_NONBLOCK`; a FIFO without a writer blocks before `fstat` can reject it. **[INFERENCE]** Two such paths exhaust the two real capture/comparison permits indefinitely. Detail has no blocking permit at all. No overall comparison deadline uses the declared five-second bound. Correction: nonblocking safe-open/type rejection, acquire permits before expensive work/spawn and hold through worker completion, apply bounded evaluation deadlines and cancellation-aware publication. A timeout wrapper alone does not stop an already blocked blocking closure.

2. **High — buffer duplication/admission still bypasses the intended memory bound.** `comparison.rs:22-35,531-532`; `store.rs:37-50`; `capture.rs:122-125,605-621`. `TrackedPathEntry: Clone` includes `Option<Vec<u8>>`: comparison clones every original under the global mutex *before* its worker acquires a permit. Detail also clones an original before any concurrency admission. **[INFERENCE]** Each in-flight comparison can duplicate up to 64 MiB outside accounting; request bursts allocate even when work ultimately returns busy. Capture admits storage only after allocating/reading. Non-Unix still uses unbounded `fs::read` after a size check. Correction: shared immutable originals with explicit accounting/lifetime ownership, admission before allocation, bounded descriptor reads on every platform, and detail admission before cloning/reading.

3. **High — detail is not fenced across its await or against mode/presence changes.** `comparison.rs:515-577,639-648`; `api/session_changes.rs:371-407`. After cloning metadata/originals, detail awaits I/O and never rechecks enabled generation, record/baseline identity or current revision. **[INFERENCE]** OFF/removal/refresh during that await can still return the old baseline/detail with HTTP 200 after purge. Only SHA is compared; `current_mode` and `current_size_bytes` are stored but unused. A chmod produces old row metadata plus a different `current.mode` in the same revision. `None` SHA also conflates snapshot Unknown and Absent, allowing a formerly unknown current side to become Absent without rejecting the revision. Correction: compare full presence/kind/mode/size/hash fingerprint and revalidate lifecycle/baseline/revision after I/O immediately before constructing/publishing the response. Map a raced disabled result consistently to 503, not generic 400.

4. **High — probe stability checks miss ordinary same-second writes.** `capture.rs:118-156`. Before/after checks compare only size and second-resolution `st_mtime`; nanoseconds, ctime, mode and actual read length versus sampled size are ignored. **[INFERENCE]** Same-size in-place rewrites within one second can change during the read and still seal as stable, including a mixed buffer. Correction: compare full available descriptor metadata at filesystem timestamp precision, verify byte count, and conservatively reject observed changes. Universal external-writer attribution remains out of scope; detecting available evidence of races is not.

5. **High — capture does not enforce normalized literal paths or nested-root eligibility before mutation.** `capture.rs:212-252,413-455,495-539`. Entries are keyed by raw strings before validation; unproven never probes/validates. `Path::components()` normalizes separators/interior dots, so `src/lib.rs`, `src//lib.rs` and `src/./lib.rs` can occupy separate immutable first-touch slots for one file. Empty/glob/overlong paths can be retained through unproven. No request path-count validation precedes reservation. Rejecting a component named `.git` does not exclude files *inside* a nested repository/gitlink; ignore-query failure defaults to eligible. Correction: one boundary validator for both modes, enforce count/length/depth/literal canonical form, key by that form, and perform bounded direct ancestor nested-root/gitlink checks with conservative eligibility errors. No recursive scanning is needed.

6. **Medium — unsupported counts, render eligibility and serialized response limits remain incomplete.** `comparison.rs:163-199,243-279,478-502,554-589,620-637`; `inventory.rs:15-16`; `types.rs:18-26`. Added/deleted invalid UTF-8 is classified Text and can emit row counts `Some(0)` without a reason; overlong-line text emits a numeric row count even when its complete flag is false. Detail checks per-side byte size, not existing line/line-length bounds, and ModeOnly is always renderable. Page/detail serialization caps are unused. **[INFERENCE]** A 200-row page with long valid paths exceeds 512 KiB; two control-character text sides can JSON-expand beyond the 12 MiB detail bound. Correction: reuse bounded content eligibility/count logic consistently; emit null unsupported counts with NonUtf8/TextLimit reasons; enforce combined rendering and serialized limits before response publication.

7. **Medium — production cutover/dead-weight removal and documentation are unfinished.** `types.rs:53-78,125-146,171,322-375,482-585,749-759`; `inventory.rs:3-13`; `types_tests.rs:13-31,70-79,118-127`; `docs/code-standards.md:122-134`; `docs/project-overview-pdr.md:79-81`. Obsolete prepare/activation/receipt/failure/from-now DTOs, barrier variants/invariants, provenance alias and unused CapturedFile survive in production. Legacy fixture retention for unmigrated TS does not require these Rust types/tests. Standards still advertise the old 128/512 MiB budgets and sessionStart/fromNow contract. Correction: delete obsolete Rust paths/tests while retaining only necessary TS fixture inputs; update current docs to the approved toolObserved/64 MiB/500-path contract. Keep this a small domain-specific implementation rather than adding compatibility layers.

8. **High — qualification does not establish the repaired security/race contracts.** `capture_tests.rs:169-219,260-329,371-387`; `comparison_tests.rs:145-207,272-329`; `server/tests/session_changes_lifecycle.rs:125-225`; Phase 02 plan acceptance at lines 42,51,60 and ordered steps 75-94. The tests named capture-publication/in-flight-capture races actually call register, not capture. The 64 MiB test only exercises the atomic counter; 501st-path test does not inspect retained map size or unproven. No deterministic pending/unproven completion permutations, actual read/publish OFF/removal races, FIFO, root substitution, Windows ancestor containment, no-I/O/no-diff seams, or full detail-mode fencing tests are present in inspected suites. Correction: add focused deterministic regressions for these actual paths before accepting Phase 02. Existing green tests are valuable but do not close missing acceptance criteria.

### Suggestions

- Keep the effective lifecycle-before-records transaction pattern; do not reintroduce nested lifecycle acquisition through reservation helpers.
- Use a small shared path validator, content-eligibility helper and explicit reservation transition function. This reduces duplicated state assembly without a generic framework.
- Replace manual raw intermediate-fd vectors/close loops with owned descriptor RAII. Preserve `errno` immediately after a failed `openat`, before cleanup calls.
- Wire existing settled/dirty metadata into comparison freshness where required, or remove inert fields/constants after contract decisions. Current viewer calls always pass `None` for settled turn; `reserved_at`, record generation and several bounds presently promise more than they enforce.
