## Critical issues

1. **Destructive cleanup still drops available runtime identity.** `packages/ui/src/os/browser/browser-create-lifecycle.ts:25-31,46-52,106-145` receives the exact create DTO but neither retains its incarnation/profile epoch nor passes `runtime` to immediate or withheld cleanup. `browser-session-inventory.ts:89-102` similarly closes only an ID, losing selected-runtime evidence. `browser-close-lifecycle.ts:122` checks replacement only when `params.runtime` exists. Therefore an exact ID now resolving to a different runtime passes GET and can be DELETEd; successful preflight does not fix this. The census also excludes incompatible retained snapshots (`browser-native-reference-census.ts:31-37`) instead of withholding destructive action on conflicting evidence. **Correction:** carry captured runtime through selected close/late cleanup and queue, reject conflicting evidence before destructive dispatch, preserve the unresolved blocker. Regression: replacement runtime between selection/create completion and cleanup; zero DELETE.

2. **Native-target admission/release is still check-then-act, not atomic.** `browser-session-inventory.ts:33-37,71-82` returns a Boolean/DTO, never commits a retained reference under the same native-key exclusion used for final release. `browser-close-lifecycle.ts:76-96,114-157` performs one census before awaiting GET, with no subsequent census/admission commit exclusion. An inventory result can pass the gate, then final close sees no installed reference and enters its gate, then the caller installs that reference before DELETE. The in-flight DELETE map only deduplicates deletion; it cannot serialize admission. **Correction:** one native-key guarded local admission/release commit, with owner/runtime checks at commit and before DELETE; no new registry needed. Regression: deferred inventory delivery/commit racing final close, including hidden cross-profile reference.

## Warnings

1. **High — late-create conversion removes the affected-group blocker.** `browser-recovery-store.ts:67,76-93` associates an outstanding create with a closing group, but later replaces the operation wholesale. `browser-create-lifecycle.ts:116-124,164-171` restages the same operation without its durable `groupId`; the catch path can also replace a known exact close target with a generic create-unknown record without `sessionId`. Once the parent window marker settles, `consumeRememberedBrowserGroup` (`browser-recovery-store.ts:120-128`) sees no linked operation and permits automatic restore while late cleanup remains unresolved. **Correction:** update the fresh durable operation without dropping group/exact-result identity, including on storage/network failure; retain exact response ownership in memory until a durable transition commits.

2. **High — create adoption and close startup still have await fencing gaps.** `browser-create-lifecycle.ts:107-112` checks owner/tab before awaiting settlement, then returns `adopted: true` without rechecking or atomically adopting. A replacement/close during that lock wait gets a stale adoptable result after the marker disappears. `browser-window-close-coordinator.ts:60-95` similarly stages asynchronously, then marks whichever Browser window currently occupies the ID closing, using the old window's target list (`97-112`). Final operation-ID fencing does not protect this initial replacement overwrite. **Correction:** fence original window/tab/owner/action identity inside local commits after every awaited storage transition; root ownership must choose adoption versus cleanup at that commit.

3. **High — settlement/resumption failures remain swallowed or strand the UI.** `browser-create-lifecycle.ts:102,124,136,155` still swallows durable writes/settlement errors. `processWithheldCleanups` (`41-57`) removes queue entries before an unhandled asynchronous close and does not requeue rejected/unknown/staging-failed cleanup; its extra settlement also swallows failure. The new OsShell caller helps reachability but does not repair ownership. `browser-window-close-coordinator.ts:165-166` only logs a child-stage/settlement failure, leaving `closing.status = pending`; later closes return at `39-44`, with no unknown acknowledgment/retry path. Legacy staging rejection also lacks a catch (`178-186`). **Correction:** retain/requeue exact cleanup until committed settlement; surface continuity failure as actionable unresolved state, never success or permanently pending shell.

4. **High — malformed Browser data is still silently discarded/rewritten.** `persistence.ts:70-71` discards parser errors; load/save/import can report success after dropping unsupported or oversized Browser state. `browser-persistence.ts:119-167` silently skips malformed tab entries, invents IDs/blanks and repairs active selection; `130-132,170-187` preserves local session hints even when owner scope is absent/invalid. Thus valid outer OS JSON with broken nested Browser data bypasses corrupt-byte preservation and can be autosaved without the original pages. **Correction:** propagate nested parse notices/failure, preserve original bytes and withhold unsafe projection, require qualified local hints; do not silently truncate pages.

5. **High — recovery validation remains incomplete.** `browser-recovery-validation.ts:10-16,42-53,58-80`: address strings need only be nonempty (userinfo/non-HTTP values accepted), endpoints are not validated/canonicalized, optional `sessionId/groupId/tabId` are unchecked, and duplicate groups/owner groups are accepted. `ALLOWED_OP_KINDS[op.kind]` (`63`) accepts inherited keys such as `toString`/`constructor`. Duplicate group IDs can make consume remove another owner's group (`browser-recovery-store.ts:130`). **Correction:** own-key membership/Set, full nested typed validation, sanitized address policy, canonical owner scope and group uniqueness; reject malformed documents before any rewrite. Added active-index/op-ID checks are useful but insufficient.

6. **High — single-flight forgets an already-used action token.** `browser-create-lifecycle.ts:73-75,178-184` deduplicates only pending promises, deleting the action entry even for unknown results. Dispatching the same action sequence again after resolution creates another key/POST, without explicit new-intent or acknowledgment enforcement. **Correction:** retain consumed/unknown intent disposition for the tab action lifetime; explicit retry uses a new action token, unknown requires the defined reconciliation/acknowledgment path. Regression: same token after success, rejection and unknown; no second POST.

7. **Medium — initial recovery publication is not the promised atomic/visible refresh.** `OsShell.tsx:208-212` publishes session state before calling `restoreClosingGatesFromRecovery()`; that function performs an unlocked reread and swallows failures (`browser-closing-gates.ts:25-35`). Initial unknown operations do not publish a notice; only a later external storage event does (`OsShell.tsx:258-268`). Same-document recovery commits do not refresh notices, and successful refresh does not clear obsolete recovery notices. **Correction:** pass one locked recovery snapshot to gate/notice initialization before publishing hydration; report read failures and publish writer-side notice refreshes. Keep active local and durable-derived gate ownership explicit rather than blindly clearing a shared Set.

8. **High — required fault/race regressions remain unauthored.** Six new test files remain primarily happy-path tests, with immediately executing lock doubles (`browser-recovery-store.test.ts:35-43`), not real exclusion. Missing: new GET failure/DELETE-404/settlement-failure branches, owner-return cleanup, close-during-create group linkage, post-settlement adoption/replacement fencing, rejected/mixed coordinator outcomes, admission-commit race, simultaneous hidden cross-profile release, malformed nested recovery and both public Browser import/export authority paths, stale-suppression autosave, delayed hydration/deep-link behavior. **Correction:** author queued-lock/deferred unit cases now; independent-document/live qualification remains Phase 05, not a requirement to run live checks during this review.

## Suggestions / architecture / performance

- Preserve focused modules, immutable request data, one shared recovery Web Lock, fresh suppression reads, explicit projection modes and no new backend API/dependency/polling. Good KISS/YAGNI boundaries.
- DRY: centralize typed exact-operation updates so pending/unknown transitions cannot drop `groupId`, runtime or exact-session evidence. Avoid introducing a generic task/retry engine.
- Remove dead imports in `window-store.ts`, unused coordinator `win` and unused cleanup `currentScope`; prefer typed local commits over unchecked double casts/callback-dependent ownership.
- `browser-url-normalization.ts:29-39` still falls back to the first ordinary tab rather than nearest ordinary when popup opener is absent. Group projection now correctly reuses opener remapping.
- No new hot polling or broad algorithmic performance regression identified. Metadata work is bounded; repeated parse/project serialization on autosave is secondary to correctness. Never optimize away fresh locked suppression reads.
