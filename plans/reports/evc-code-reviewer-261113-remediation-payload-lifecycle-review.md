### Warnings
1. **High — publication is not atomic with viewport transitions.** `server/src/browser_host/screencast.rs:2850-2861,2954-2999` checks the candidate epoch before several awaits, then reloads the epoch for the header; the final publication guard checks only `current_run`. `update_geometry` changes epoch without rotating that run (`:1380-1382,1482`). **Scenario:** candidate passes epoch 1 check; resize sets `1 | (1 << 63)` and awaits CDP; publisher resumes and broadcasts that transitional epoch. It is a valid positive u64. Client records it as its high-water mark (`packages/ui/src/browser-host/stream-controller.ts:773,807-820`) and rejects subsequent normal epoch 2 frames indefinitely on that attachment. Alternatively old pixels are mislabeled with a newly committed epoch. Fallback has the same check-to-publication gap (`screencast.rs:3101-3105,3188-3204`). **Fix:** serialize epoch/geometry validation and cache+broadcast commit against geometry fences; retain the candidate epoch, reject transitions, never relabel an old capture. A lone additional atomic load is not sufficient.

2. **High — screenshot response remains resident outside admission.** `server/src/browser_host/screencast.rs:3082-3118`; response routing at `server/src/browser_host/cdp.rs:1229-1263` transfers an uncharged `Value` through the oneshot. **Scenario:** capture returns multi-MiB base64 while the global budget is nearly full; fallback retains it across the subsequent `GetLayoutMetrics` await before trying `_text_guard`. Multiple producers can hold these responses concurrently; rejection happens after allocation and prolonged retention. This is not merely a transient WebSocket parse buffer. **Fix:** reserve response payload at actor handoff and carry its reservation through typed conversion/fallback, before retaining it across another await. Decoded+packed overlap is otherwise correctly pre-reserved.

3. **High — changed native screencast identity can still strand credit.** `server/src/browser_host/screencast.rs:2720-2730` returns `None` on a native `frame_session_id` mismatch: no ACK, no abort. `update_geometry` reissues native `Page.startScreencast` on the same Page session (`:1416-1427`) without resetting/rotating the run's native identity. **Scenario:** after native restart, current Page session emits its new native screencast ID; all such events are silently dropped, outstanding native credit is never returned, no ACK watcher fails, and cached pixels can remain indefinitely. **Fix:** make restart establish an explicit fresh native/run boundary; treat an unexpected current-session identity as ambiguous and recover rather than silently continuing. Existing resize serialization test (`server/tests/browser_host_screencast.rs:1474-1516`) checks commands/geometry, not post-resize native frame credit.

4. **High — dropping a start future leaves a permanently half-started producer.** `server/src/browser_host/screencast.rs:1822-1847,1869-1907`. `Starting` and `current_run` are installed before awaited Page setup/native start; no cancellation owner restores/poisons the run transition. **Scenario:** cancel `start_screencast_run` while attach or `Page.startScreencast` awaits its response. Native start can already have succeeded, but the frame receiver and future are dropped before drain/ACK tasks spawn. Next start returns the existing UUID immediately because state is `Starting`, even if Page setup is poisoned. No supervisor exists to detect lost credit. Stop has a related early-transition hole: cancellation while awaiting retirement locks precedes poison installation (`:1935-1959`); its `Stopping` retry branch (`:1927-1932`) can report success without completing retirement. **Fix:** operation ownership must survive caller cancellation, or a transition guard must schedule fail-closed cleanup before another start/stop can reuse state. The existing cancellation test aborts only after the native stop was sent (`server/tests/browser_host_screencast.rs:2084-2102`).

5. **Medium — relay text forwarding has an uncovered second payload.** `server/src/browser_host/cdp_gateway.rs:893-909,955-963`. `_resident` reserves one `t.len()`, but `t.as_str().into()` creates another owned text payload while incoming `t` remains alive across send. **Scenario:** large text message admitted with room for only one copy, downstream write stalls; two application-owned payloads coexist under one charge. **Fix:** forward shared/moved text storage where supported, otherwise reserve the outgoing copy before conversion. Binary forwarding moves its buffer and does not have this copy.

6. **Medium — ingress retains unbounded metadata under fixed/no charge.** `server/src/browser_host/cdp.rs:1633-1665` retains the entire metadata object, charging a flat 1024-byte overhead; the over-budget branch drops only base64 and still broadcasts metadata without any reservation. **Scenario:** a CDP peer supplies required numeric fields plus a large extra metadata member within the 4-MiB wire cap; broadcast/candidate holders retain that member outside the global accounting, including rejected frames. **Fix:** project only supported numeric metadata before retention, or account for retained metadata; rejected frames should carry only bounded ACK identity. This is peer-input robustness, not a demonstrated ordinary-Chromium exploit.

### Explicit acceptance verdicts
- **ACK/native credit:** over-budget normal current-run frames enqueue ACK before payload drop; enqueue/backlog/timeout failures trigger recovery. Nevertheless credit **can remain stranded**, notably warnings 3 and 4.
- **Lifecycle gate:** **no direct gate re-entry or operation/state/page_setup lock cycle found in inspected paths.** Internal callers use ungated helpers; recovery releases state around fresh setup and rechecks afterward. Mutex ownership itself drops safely, but native/state transitions do not (warning 4). This is not an exhaustive whole-repository deadlock proof.
- **Memory ceiling:** shared ingress Arc and decoded/packed reservations fix the intended ordinary base64+JPEG+BHJF overlap; decoded buffer drops before its guard, ingress reservation survives candidate holders, packed reservation transfers to tracked frame. **An absolute resident-payload ceiling is still not enforced**: warnings 2, 5 and 6. CommandReservation local/global rollback and final release show no double-count/leak defect in inspected code.
- **Client:** BigInt comparisons avoid Number precision loss; changed-owner attach retires bitmap/header/hit rectangle and blackens canvas. Both logout call sites retain generation/token checks and now fence before disconnect. No additional cross-owner stale-pixel path established in these scoped changes. Server transitional-epoch publication can still poison the new client high-water mark (warning 1).

### Suggestions
- `packages/ui/src/browser-host/stream-controller.ts:281`: test same-owner reconnect after epoch N, followed by epoch N-1, plus epochs above 2^53. Current code preserves cached presentation but resets the epoch floor; a regressed server cache can therefore repaint older geometry. Preserve the floor for unchanged owner identity unless a documented reset contract requires otherwise. Existing new test covers only 1→2 in one attachment (`stream-controller.test.ts:462-505`).
- `server/src/browser_host/cdp.rs:2434-2458`: add failed growth of an already globally charged reservation, not only first growth of empty `b`; assert prior bytes survive unchanged and all bytes/slots release after drop. Existing test verifies the empty-reservation failure branch; `held.adjust(target)` failure is a distinct branch.
- `server/tests/browser_host_screencast.rs:2084-2102`: extend cancellation coverage to native start and earlier retirement awaits; add barrier-driven epoch-check/publication overlap and streaming resize followed by a changed native ID. These reject the concrete defects above without relying on timing-only sleeps.
