## Critical issues
- **C1 — Ordinary Browser launches cannot create a target.** `packages/ui/src/os/BrowserStreamKeepAliveHost.tsx:347-357` sends `creationKey: win.id`; normal IDs are `browser-<8hex>` (`OsShell.tsx:667-692`, `action-executor.ts:479-480`). Backend rejects non-UUID creation keys (`server/src/browser_host/session.rs:257-259`). Failure is console-only (`BrowserStreamKeepAliveHost.tsx:375-380`), leaving a blank viewer. Correction: capture a separate full UUID per explicit launch, retain it through ambiguous retries, and display failed/pending creation. Confidence: high. Product-breaking; no demonstrated critical security exploit.

## Warnings
1. **High — Pause has no resume path.** `BrowserStreamKeepAliveHost.tsx:231-245,419-426` invokes visibility/privacy setters, but the attachment effect does not depend on visibility/privacy and never remints on restore. The setters close sockets; `setVisibility(true)` only changes status (`stream-controller.ts:502-585`). Minimize/desktop switch/Cognito therefore leaves an attached viewer disconnected after restoration. Reconcile effective demand with a fresh matching ticket/socket pair on resume, preserving canvas/controller and target. Confidence: high.
2. **High — Input identity is permanently stale; explicit text focus is absent.** `BrowserStreamKeepAliveHost.tsx:289-313` constructs the controller once with getters closing over the initial `win`; later dependency changes do not recreate/rebind it. URL-only launches retain empty session/incarnation and viewport epoch 0 after create (`:367-374`). Pointer mapping rejects current frames (`input-controller.ts:118-121`); later viewport changes are stale too. The text proxy ref is only assigned (`:182,521-524`), never focused by a canvas tap or explicit action. Read the current captured-owner/session runtime through a ref and wire deliberate text focus/blur. Confidence: high.
3. **High — Lease owner differs from attachment owner and lease is never renewed/released.** Control acquisition uses `window.id` (`BrowserApp.tsx:260-274`), whereas ticket minting generates a distinct UUID viewer ID (`browser-host-client.ts:436-444`). Backend teardown releases only the attached viewer's lease (`server/src/browser_host/media.rs:914-925`); these identities never match. Neither changed component calls renew/release, despite the 30s TTL/5s renewal contract (`architecture-contracts.md:43,126`). Held state/control can outlive this viewer, while the UI continues showing Controlling after expiry. Use one runtime viewer identity, bind acquisition/renewal/release to its lifetime, and fence late acquisition before publishing. Confidence: high.
4. **High — Navigation controls always start stale and discard authoritative results.** `BrowserApp.tsx:169,213-258` defaults navigation revision to 0 and ignores returned DTOs. Creation does not publish navigationRevision (`BrowserStreamKeepAliveHost.tsx:367-374`); backend starts at 1 and rejects stale revisions (`session.rs:330,459-463,489-493,523-527`). Populate/update the independent navigation revision, URL/title and viewport identity from authoritative DTOs, without unnecessary media reattachment. Confidence: high.
5. **High — Persisted sessions cannot be adopted after SPA reload.** Persistence correctly drops incarnation/epoch (`persistence.ts:56-61`), but reconnect directly mints tickets with fabricated incarnation `"1"` and profile epoch 0 (`BrowserStreamKeepAliveHost.tsx:319-327,384-392`). There is no authenticated session list/get reconciliation or explicit missing/restarted-target Restore flow. `logicalSessionId` is persisted but never consumed. Re-list/get the exact logical session before attachment; expose explicit new-key Restore only when missing/restarted. Do not persist runtime authority to mask this. Confidence: high.
6. **High — Privacy/input lifecycle is incomplete.** Effective demand only includes slot visibility and Cognito (`BrowserStreamKeepAliveHost.tsx:228-245`); PIN, document.hidden and shell/modal suppression are absent. Initial layout privacy/visibility effects run before controller construction (`:231-253`), so a viewer mounted already private/hidden starts with controller defaults and may attach anyway. Cognito detaches sockets *before* releaseAllHeldInput (`:234-236`), and hide never releases held input locally. Initialize suppression before attachment; aggregate required signals; release original held state/lease before disconnect; keep privacy blackening synchronous and late work fenced. Confidence: high.
7. **High — Root ownership is not generation-reactive; explicit close loses failure/cancellation state.** Root owner memo only depends on profile ID and component key only on window ID (`BrowserStreamKeepAliveHost.tsx:197-203,583-586`), so reconnect never refreshes it. Conversely close resolves the *current* generation rather than the runtime's captured owner (`window-store.ts:153-171`). Closing during create has no session ID to finalize; aborting HTTP cannot guarantee backend cancellation, and a late committed target has no reconciliation owner. Existing close removes the window before DELETE succeeds and only logs failure. Retain a captured owner/session/creation-operation finalizer through close and ambiguous outcomes, with visible truthful failure; qualify sibling checks by owner, not bare session ID (`:162-166`). Confidence: high; late-create leak is a static race finding, not exercised.
8. **High — Popup/dialog acceptance is not implemented end-to-end.** Host event handling has no popup projection/overflow notice (`BrowserStreamKeepAliveHost.tsx:256-279`; no session-list reconciliation). Dialog is a custom div (`:97-165`), not the required shared Radix modal: no focus trap or shell modal registration. A view-only viewer also presents actionable dialog buttons, and responses are fire-and-forget without rejection handling (`:442-471,525-530`). Implement bounded popup projection and controller-qualified, focus-trapped modal lifecycle; retain/show response failure instead of silently dismissing. Confidence: high for missing UI paths; backend popup delivery not qualified here.
9. **High — Green tests do not establish the claimed lifecycle/input behavior.** New lifecycle tests check store/DOM removal rather than backend DELETE or surviving target state (`host-browser-lifecycle.browser.tsx:61-173`); the test named unmount persistence only switches desktops (`:175-233`). Continuity marks the canvas dataset, not live page DOM/controller/session state (`os-lifecycle.browser.tsx:232-329`). Privacy checks CSS only (`os-input-isolation.browser.tsx:203-239`); unsupported state is manually injected (`os-lifecycle.browser.tsx:367-389`). Add connected-boundary coverage for UUID create, ticket identity, input, pause/resume, exact DELETE, failed/late operations, reload adoption and real frame-denying page continuity. Confidence: high.
10. **Medium — Reparenting moves a React-owned host node.** `BrowserStreamKeepAliveHost.tsx:217-225,428-440,498-509` appends/removes the node that React rendered as a child of the parking host. This violates the requested ownership-safe portal boundary; teardown/reconciliation reliability is unproved. Reuse Monaco's imperatively owned host + stable React portal pattern (`MonacoKeepAliveHost.tsx:182-207,247-266`). No teardown exception claimed from the passing tests. Confidence: high on contract divergence, runtime failure not reproduced.
11. **Medium — Capability errors are swallowed for test accommodations.** `BrowserStreamKeepAliveHost.tsx:342-344,375-403` explicitly special-cases mock/test environments through production catch-and-continue/log-only behavior. Capability version/engine compatibility is not checked. Surface disconnected/unsupported/error/pending states and fail Browser closed on unknown compatibility; keep test accommodations in tests. Confidence: high.

## Suggestions — KISS/DRY/performance
- Keep a small typed runtime snapshot per owner + logical session + viewer, rather than loosely cast appState fields, duplicate refs/state and captured getter closures. No second protocol/framework needed.
- Centralize URL-only recipe projection currently repeated at `recipe-engine.ts:250-253` and `schema.ts:293-300,431-436`. Avoid copying credential-bearing appState only to immediately discard it.
- Share the identical browser:open/browser:preview launch implementation (`OsShell.tsx:667-696`). Give optional Browser action URL an explicit request type instead of probing cast records (`action-executor.ts:516-524`).
- Add the required holder-authorized viewport update integration; current canvas resize only rescales the local backing store (`canvas-view.tsx:45-84`) while host onGeometryChange is a no-op (`BrowserStreamKeepAliveHost.tsx:255`).
- Maintain existing bounded decoder/transport; no new per-frame React state introduced. No performance measurements or allocation benchmarks were run.
