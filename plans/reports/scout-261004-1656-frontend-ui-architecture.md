# Frontend UI Architecture, Components, and State

Scope: current `packages/ui/src` checkout, package metadata, and frontend/native-Advisor architecture guides. `packages/ui` is shared by the browser and Tauri hosts.

## 1. Application architecture

- **Shared React shell:** `packages/ui` owns `DamHopperApp`, routes, workspace shells, components, stores, hooks, API client, styles, and tests. `apps/web` and `apps/native` perform host startup/migration, create an ordinary TanStack Query `QueryClient`, install host providers, and render the shared UI. The shell remains mounted when profiles are disconnected or unavailable.
- **Stack:** React/React DOM 19 peers; TanStack React Query 5.67 for server state; Zustand 5 for client/persisted UI state; Tailwind CSS 4 imported from `src/index.css`; Radix Dialog, Context Menu, Label, and Select primitives; xterm.js 6 with fit/search/Unicode/WebGL addons; Monaco 0.55, `react-arborist`, and `react-resizable-panels` for editor/tree/layout surfaces.
- **Component layering:** atoms and molecules compose into organisms, pages, and templates. `IdeShell` and `TerminalWorkspaceShell` own layout/panel placement; `WorkspacePage` composes surfaces and modes. Tailwind classes coexist with shared CSS and `.native-advisor`-scoped styles.

Evidence: `packages/ui/package.json`, `packages/ui/src/index.css`, `packages/ui/src/embed/dam-hopper-app.tsx`, `docs/frontend-components.md`, `docs/frontend-components/terminal-and-ide.md`.

## 2. WsTransport and API client

- **Typed API:** `createApiClient(owner, transport)` exposes typed workspace/project/Git/terminal/filesystem/host/Advisor methods. `channelToEndpoint` maps channels to REST method/path/body. `WsTransport.invoke()` fetches against the profile base URL, attaches that profile's bearer token, uses `credentials: "omit"`, supports abort/timeout, parses JSON/text, and reports structured HTTP errors. Owner-qualified project targets are checked against the client owner and projected to wire DTOs without `profileId`.
- **Per-profile ownership:** `connections.ts` maintains one runtime per server profile. A captured `ConnectionRef` is `{ profileId, generation }`; connect/disconnect/replacement advances generation, stale owners are rejected, and the bound API/transport are tied to that profile runtime. Each `WsTransport` captures endpoint/token/generation for its lifetime.
- **WebSocket:** one persistent socket per `WsTransport` connects to `ws://host/ws` or `wss://host/ws` (token in query when present), carries PTY input/output, attach/replay, filesystem subscriptions/events and binary protocols, and dispatches push events. It reconnects with backoff capped at 30 seconds. Terminal replay is reconciled by offsets and incarnation; stale owners/incarnations are fenced and stdin waits for replay synchronization.
- **Regular/encrypted binary writes:** regular uploads use `fs:upload_begin`, 128 KiB binary chunks with sequence acknowledgements (four in flight), then `fs:upload_commit`. `use-encrypted-write` performs OPAQUE registration/login for an owner/project-scoped session, encrypts with Web Crypto, and sends the encrypted blob through `fs:put_*` binary frames with the same chunk size/window and commit/ack flow (`fs:put_save` is a JSON header plus one binary frame). The passphrase is not sent to the server; writes are fenced against connection or encryption-state changes.
- **Host-resource SSE:** `WsTransport.openHostResourceEvents()` GETs `/api/system/resources/v1/events` with bearer auth, `Accept: text/event-stream`, and a streaming reader. `HostResourceSseParser` handles chunked UTF-8/SSE framing and bounds event sizes. `HostResourceStreamCoordinator` is keyed by exact `ConnectionRef` and QueryClient, arbitrates SSE against owner-scoped REST fallback, and commits snapshot/metrics as a paired frame.

Evidence: `packages/ui/src/api/{transport.ts,ws-transport.ts,client.ts,connections.ts,ownership.ts,host-resource-stream-coordinator.ts,host-resource-sse-parser.ts}`, `packages/ui/src/hooks/use-encrypted-write.ts`.

## 3. Key UI organisms

| Surface | Architecture and responsibility |
|---|---|
| **IDE shell** | `IdeShell` composes top navigation, left/right activity bars, resizable top tool windows, center editor, and bottom tool panels. Panel selection and rail widths/heights persist in local storage; bottom maximize is session-only and keeps terminal content in place. `WorkspacePage` chooses IDE, terminal, or compact presentation while preserving mounted surfaces where needed. |
| **Terminal** | `TerminalPanel` owns an xterm instance and Fit/Search/Unicode addons, with optional WebGL renderer; registry/keep-alive hosts preserve the same PTY view across shell changes. It binds to the owning profile transport and subscribes to output/lifecycle/exit/buffer events, replays offset-based buffers, checks terminal incarnation, and forwards input only after replay gates permit it. Suggestions intercept only configured accept keys; normal xterm input stays byte-preserving. |
| **Git page / workspace Git** | `GitPage` aggregates profile-qualified projects and has persisted multi-project selection; bulk actions fail closed for unavailable selections. For one selected project it composes shared `useGitHistoryView`, history actions, status and editor diff opening. `WorkspaceGitPanel` uses the same history controller for a project/worktree, exposing VCS root and branch selection, commit log/details, diffs into the editor, and owner/scope-fenced history mutations, squash, and leased push flows. |
| **Files / editor** | `FileTree` uses `react-arborist` and owner/worktree-scoped filesystem subscription/ops/upload hooks; it supports lazy expansion, hidden/language filtering, Git decorations, path reveal, CRUD/context actions, regular and encrypted upload. `EditorTabs` routes target-qualified tabs to lazy Monaco/Markdown/HTML hosts or large-file, binary, image/video and diff viewers. `useEditorStore` persists tab metadata/view state, but tabs rehydrate clean and without file contents; content freshness and saves are re-read/fenced, with conflict and encrypted-save handling. |
| **Host resources** | No component named `HostResourcesPanel` was found; the surface is `HostResourcePopover`, composed with fleet deck, glance, diagnosis and incident details. With multiple configured profiles and no explicit owner it presents Fleet, then drills into connected profile owners; disconnected entries remain status-only. Snapshot, alerts, metrics, idle-suspend and storage controls use that owner. `useMultiHostResources` and the coordinator provide SSE-first paired readings and REST fallback/status presentation. |
| **Ports** | `PortsPanel` consumes `usePorts`, which queries ports and tunnels under per-profile/generation cache keys and merges entries within each profile. Rows show detected state/tunnel status and expose create/stop tunnel, QR/copy, optional embedded Browser handoff and terminal-session kill actions; the panel also supports a custom port and cloudflared installation flow. |
| **Cognito privacy mode** | Zustand active/shortcut/style state drives `CognitoModeOverlay`, a focusable portal to `document.body` that masks the full viewport. Heavy-blur uses translucent `rgba(148,163,184,.12)` plus `blur(16px) saturate(180%)`; unsupported blur and reduced-transparency preferences fail opaque to black; black-screen is the explicit alternative. The app content boundary becomes `inert` and `aria-hidden`; a window-capture guard blocks pointer/touch/wheel/drag/clipboard/input/composition and ordinary keys while active, allowing the configured dismiss chord, and restores prior focus on exit. |

## 4. State management and hooks

- **Profile configuration/runtime are separate:** `api/server-config.ts` persists multiple server profiles and endpoint-bound profile auth; `api/connections.ts` owns the in-memory runtime/status/generation and bound transport/API per profile. Project, worktree, and terminal identities carry profile ownership; terminal instances additionally include incarnation.
- **Independent selections:** `useWorkspaceStore` persists a qualified `{profileId, project}` selection. `useWorkbenchSelectionsStore` separately persists preferences source/snapshot, Settings target, and Browser Debug target; project focus does not switch these. `useProjectTargetStore` scopes selected/unavailable worktrees by project identity. `useGitHistoryStore` persists root/branch choices and qualified Git-page selections.
- **Profile-scoped query cache:** one ordinary host QueryClient; server state remains memory-only. Canonical keys use `profileQueryKey(owner, ...parts) = ["profile", profileId, generation, ...parts]`, with target keys adding project/worktree/path. Owner/generation are part of cache identity rather than a global active-profile hash. Connections register QueryClients so SSE coordinators are shared only for the same client identity and exact owner.
- **Editor state:** the persisted Zustand editor store keys tabs by profile + project + worktree + path (and diff identity); it persists tab metadata/view state, not content or dirty edits. Async loads/saves carry request generations and reconcile stale scoped file versions.
- **Terminal input and prompt detection:** `TerminalInputBuffer` is a standalone line reconstruction utility (printables, backspace, Ctrl+U/Ctrl+W, escape-sequence tracking), with no runtime callsite in the searched UI source. `PromptDetector` is an explicit legacy no-op: PTY silence is not accepted as proof of an editable prompt. Current suggestion/prompt awareness consumes server-validated `TerminalLifecycleEvent` in `TerminalPanel`/`useTerminalSuggestions`; only verified editing/submitted/opaque boundaries change controller state, and ambiguous input disables suggestion inference rather than changing PTY bytes.
- **Other key hooks:** `useGitHistoryView` centralizes Git history scope/search/paging; `useMultiHostResources` aggregates profile resources; `usePorts` aggregates profile ports/tunnels; `useAdvisor` gates Advisor status/visibility and cache by owner.

Evidence: `packages/ui/src/api/{server-config.ts,connections.ts,query-client.ts,ownership.ts}`, `stores/{workspace.ts,workbench-selections.ts,project-target.ts,editor.ts,git-history.ts}`, `lib/{terminal-input-buffer.ts,prompt-detector.ts,terminal-suggestion-controller.ts}`, `hooks/{use-terminal-suggestions.ts,use-git-history-view.ts,use-multi-host-resources.ts,use-ports.ts,use-advisor.ts}`.

## 5. Native Advisor UI

- **Native subtree:** `WorkspaceAdvisorHost` mounts `AdvisorPanel` directly in the shared React workspace—no iframe, MessagePort, plugin SDK, or nested React root. `NativeAdvisorProvider` adapts a captured owner-bound `ApiClient.advisor`; requests have IDs/AbortControllers and stale provider/context responses are discarded.
- **Views/state:** `AdvisorPanel` uses a reducer/selectors for `Overview`, `History`, `Configuration`, and `Evaluations`, with tab roving focus, history filters/paging/detail, and owner/context-epoch fencing. History is manually refreshed from server snapshots; summary/page requests follow refresh, and policy/evaluation reads are separate operations.
- **Model selector is routing configuration:** in Configuration, `PolicySummaryCard` edits primary and backup backend/model/effort routes. Editing lazily calls `POST /api/advisor/models` for catalogs; `RouteFieldset` offers catalog select plus custom model input, effort choices, harness/fallback/unavailable badges, and warnings. Routing validation normalizes values, checks backend/model/effort rules and duplicate full route triples; policy PATCH is revision/CAS fenced and exposes reload/cancel/conflict states. This is not a per-consultation model picker.
- **Advice/checkpoint review:** History lists persisted consultations and opens `HistoryDetail`, which shows status, route, elapsed time, checkpoint digest, task goal/question, attempts, outcome, recommendation/rationale, must-fix items, cautions and success checks. Detail detects changed/missing revisions and avoids presenting stale record data. These are reviewable stored checkpoints/results, not a live generation transcript or approval workflow.
- **Important boundary:** the current native Advisor frontend API is REST history/policy/model-catalog/evaluation calls. No live advice-token stream or consultation-generation transport is present in these requested UI targets; `AdvisorDataProvider.subscribe()` reports provider lifecycle/availability events, not streamed model output.

Evidence: `packages/ui/src/advisor/{AdvisorPanel.tsx,native-advisor-provider.ts,advisor-data-provider.ts,app-state-reducer.ts}`, `advisor/views/{HistoryView.tsx,HistoryDetail.tsx}`, `advisor/components/{PolicySummaryCard.tsx,RouteFieldset.tsx}`, `docs/architecture/native-advisor.md`.
