## Key Insights

- Current preflight reads only `/etc/dam-hopper/dam-hopper.toml`, expands `~` as root/current process homes, and adds `/etc/dam-hopper/sessions.db`. The manager process environment is not the API path contract.
- During copy-once migration, an old daemon may still hold the legacy DB while the new daemon targets canonical state. Discovery must union safety candidates; canonical remains the only startup authority.
- Unsafe existing config must fail closed. Treating malformed/unreadable/link state as absent would skip holder protection and allow service switch.
- Bootstrap installer currently creates and repairs root-owned legacy TOML before staging. That conflicts with sole provisioning authority and API-user atomic updates.
- Reset uses root `sed -i`, which can replace an API-owned inode with root-owned output. It must preserve exact final ownership/mode and atomicity or refuse.
- Rootless smoke's explicit temporary `--config` is intentionally not production systemd behavior and must remain unchanged.

## Requirements

### Preflight Contract

- Run daemon-config SQLite discovery only when candidate/active role includes Server. Web-only install/preflight must not read, create, or infer API state.
- Inspect canonical first and any extant legacy source second using their Phase 01 `Layout` accessors. Open no-follow, then `fstat` regular type; bound reads to 64 KiB before UTF-8/TOML parsing.
- Unsafe presence is fatal even if the other file is valid: symlink, non-regular, unreadable, oversized, invalid UTF-8/TOML, or inspection error. Missing is the only absence state.
- Each valid config contributes its effective `server.session_db_path`; missing key contributes the schema default `~/.config/dam-hopper/sessions.db` for that file, not an arbitrary fallback.
- Match API process semantics: `~/...` and `~` resolve against fixed API HOME `/var/lib/dam-hopper`; plain relative paths resolve against fixed API `WorkingDirectory=/var/lib/dam-hopper`; absolute paths remain unchanged. Reject unsupported `~user` forms instead of interpreting them as relative.
- If neither TOML exists, include `/var/lib/dam-hopper/.config/dam-hopper/sessions.db`, matching the seed/default that Phase 01 will establish.
- During the migration window, retain `/etc/dam-hopper/sessions.db` as one explicit compatibility candidate. Do not treat it as config authority. Remove this fallback only in a separately reviewed legacy-retirement change.
- Stable-deduplicate normalized candidate paths before invoking existing `verify_no_foreign_sqlite_holders`; for each candidate, that function continues checking DB, `-wal`, and `-shm` handles.
- Return only sanitized fixed config-path errors and bounded parser diagnostics; never log config bytes or arbitrary symlink targets.
- Preflight performs zero filesystem mutation and completes before quiesce/service stop/switch.

### Installer and reset contract

- Delete the installer block that creates `/etc/dam-hopper/dam-hopper.toml`, writes a default, or chmods it. Do not replace it with `/var/lib` `mkdir`, `cp`, `tee`, `install`, `chown`, or `chmod`.
- Server/Both install remains pending and does not create API state. First explicit `start` invokes the Phase 01 provisioner after final unit identity resolution; Web install never invokes it.
- Keep `deploy/release/dam-hopper-install.sh` as source of truth. Generated `artifacts/final/dam-hopper-install.sh` is regenerated by the existing package flow, not hand-maintained as an independent source.
- Change reset's default/help to `/var/lib/dam-hopper/dam-hopper.toml`; retain explicit `--config` and dry-run behavior.
- Replace root-owned `sed -i` with a same-directory atomic edit executed as the exact non-root User/Group parsed from the installed API unit. Before editing, refuse absent/link/non-regular or wrong UID/GID/mode; after replacement, verify regular API UID:GID `0600`, parseable TOML, `enabled=false`, and sync file/parent. Never repair mismatch.
- Preserve reset's handoff warning, helper stop/disable/removal, foreign RTC preservation, and helper/timing audit retention. Do not delete canonical/legacy config or either server audit.

## Architecture

```text
install (Server/Both) -> stage only; no daemon TOML mutation
start preflight
  -> read canonical candidate ---------+
  -> read extant legacy candidate ------+-> stable DB union -> DB/WAL/SHM holder gate
  -> neither: canonical default --------+
  -> success -> quiesce/switch -> Phase 01 prestart -> API canonical ExecStart

running API/reset-as-API -> same-dir atomic replace of canonical TOML -> API UID:GID 0600
```

Canonical is startup authority; legacy inspection is temporary safety coverage and copy source only. The preflight function discovers DB paths but never provisions files. Phase 01 provisions fixed state. The API performs content updates. These boundaries prevent shell/Rust duplication and root-owned replacements.

4. Add a seam or focused process-holder fixture proving every returned DB reaches existing DB/WAL/SHM holder verification; avoid tests that merely assert vector length.

6. Change reset default/help. Resolve final unit identity with the same exactness as runtime policy, validate canonical metadata no-follow, and perform the TOML edit through an API-identity same-directory temp + sync + atomic rename + parent sync. Keep dry-run observation-only.
7. Add security smoke assertions for exact canonical template `ExecStart`, absence of legacy TOML operand, exactly one privileged provisioner, and absent `StateDirectory*`.
8. Expand protected Fedora smoke with isolated reset-hook scenarios from the matrix. Record bytes, inode, UID/GID/mode before/after; assert systemd inactive on refusal and health after success/manual repair.
9. Exercise authenticated config PUT through the real running API using existing protected credentials/fixtures; assert write succeeds as service user and restart validates the replacement. 10. Exercise foreign holder fixtures for canonical and legacy configured DB, WAL, and SHM before switch. Verify allowed current API PID handling remains unchanged.
11. Run reset dry/live scenarios only after proving no in-flight handoff; verify disablement, metadata, audits, and foreign RTC state.
12. Regenerate/compare release output through existing package flow. Update architecture and operator docs from observed behavior; remove stale production `/etc` TOML/audit claims while retaining explicitly historical format-2 references.

## Risk Assessment

- **Missing old DB holder:** union canonical and every extant legacy candidate plus WAL/SHM; deduplicate only after semantic path resolution.
- **Preflight race:** open no-follow, validate the opened descriptor, bound/read one descriptor; any inspect/open mismatch fails closed.
- **Reset changes ownership:** perform replacement as parsed API identity and validate final metadata; never root `sed -i` or post-hoc repair.
- **Installer/start ordering:** assert pending has no config and explicit start provisions before API executable.
- **Protected smoke damages host:** retain root, snapshot, and root-owned-hook guards; each scenario begins from reset snapshot.
- **Legacy residue mistaken as authority:** canonical unit and docs state sole authority; preflight labels legacy as safety-only; retirement requires separate review.
- **Docs overclaim:** update only after actual runtime proof and record legacy audit preservation limitation.

## Security Considerations

- Parsing is bounded and no-follow; malformed or unsafe presence blocks instead of silently selecting a default.
- DB candidate resolution uses the daemon's fixed HOME/working directory, never manager/root ambient environment. No unbounded alternate path discovery or directory scan.
- Installer loses privileged content mutation. Reset privilege is narrowed to service orchestration; config bytes are replaced as final API identity with exact postconditions.
- Smoke verifies refusal by absence of API start and byte/stat invariants, not only error strings.
- No credentials, config contents, symlink targets, terminal data, or arbitrary path values enter logs/evidence.
