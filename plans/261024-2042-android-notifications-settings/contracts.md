### C2a1. Proposed awaited registry retirement barrier — G0 freeze, G2 consumption

**Not existing capability:** current ConnectionRegistry exposes only synchronous retirement listeners; adding suspend barriers to that existing class is planned G0 work, not a second runtime/helper. Keep existing synchronous listener APIs separate and unchanged. Exact signatures to freeze in ConnectionRegistry.kt:

```kotlin
suspend fun addRetirementBarrier(barrier: suspend (ConnectionRef) -> Unit): Long
suspend fun removeRetirementBarrier(token: Long): Boolean
suspend fun retireConnection(ref: ConnectionRef): ConnectionRef
suspend fun removeProfile(profileId: ProfileId): ConnectionRef?
suspend fun recoverRetirement(ref: ConnectionRef): Unit
suspend fun admitCurrentOwner(ref: ConnectionRef, commit: () -> Boolean): Boolean
```

Barrier token is opaque registry-local monotonic Long, never a generation/callback equality key; remove returns true only for removed registration, false for unknown/already removed. Add/remove serialize under registry Mutex; add returns only after registration is effective. Removal affects future captures only: already captured callbacks remain strongly retained and awaited, including explicit recovery. Existing getOrCreateConnection/getCurrentConnection/isCurrentOwner/assertCurrentOwner and connectionsState keep their signatures; all must honor transition fencing below. No new ProfileRepository public API.

**Atomic start:** under registry Mutex, retireConnection(N) revokes usable N immediately, removes it from connectionsState, preserves monotonic watermark, reserves successor >N without making it usable, records profile RETIRING/unavailable transition and one shared completion keyed by profile+retired generation; capture barrier list and synchronous observer list in registration order. removeProfile captures/revokes identically, with remove disposition and no successor publication. Initial removal of an absent profile returns null only when no transition exists. Same-generation concurrent retirees/removers join the same completion, never stale-ref/no-op bypass; remove joining retirement upgrades final disposition to removed, retire joining removal cannot recreate it. A retire caller whose joined disposition is removed receives ConnectionOwnerError(OWNER_MISMATCH), not synthetic successor authority. Requests for another generation while pending/failed reject; stale retire after completed successful transition may return the real current successor only, never fabricate/resurrect absent authority.

**Fence while pending/failed:** getCurrentConnection returns null; connectionsState omits profile; getOrCreateConnection throws ConnectionOwnerError(OWNER_MISMATCH), never waits-and-creates or increments again. isCurrentOwner=false; assertCurrentOwner throws; admitCurrentOwner=false without commit. This applies equally to guessed/reserved N+1. Profile API/WS creation, auth/profile publication, VM binding/runtime/readiness publication deny pending/failed transition and discard suspended stale results. An old already-admitted effect may finish only as work being drained, not as new authority.

**Drain/finalization outside registry lock:** once atomic revocation starts, the **whole remaining protocol** runs NonCancellable (drain, aggregate, state finalization/shared-completion delivery, synchronous observer dispatch), not just callback invocation. Attempt **every** captured barrier once per attempt in registration order even if one throws, including CancellationException from a callback. Barrier receives exact old ConnectionRef; it awaits provider.invalidate with prune/cancel/audio cleanup, no network. Strict **transitive** prohibition: barrier, cleanup, effect callback and any work awaited by them must not reenter profile/registry or await any work needing those locks. ProfileRepository may hold profile Mutex throughout drain. No external callback under registry Mutex; provider effect gate may not acquire those locks.

After all barriers finish, keep the transition RETIRING/unavailable while invoking captured synchronous observers in registration order, outside the registry lock; profile lock may remain held. **Observers also obey the transitive no-profile/no-registry-reentry and no-wait-for-lock-dependent-work restriction.** G0 inspects/migrates existing listeners and callers for this restriction, not merely signatures; I1 wires only compliant VM callbacks. Observers are best-effort, once per original retirement success/failure; recovery does not redispatch them.

After observers finish, acquire registry Mutex and **seal disposition, finalize authority and settle the shared completion in one non-suspending critical section**. Remove requests registered before sealing may upgrade the pending disposition. Success exposes reserved successor or finalizes removal; failure aggregates barrier failures as ConnectionOwnerError(OWNER_MISMATCH) with suppressed causes and remains unavailable. No successor is usable before observers finish or while original completion is pending. After sealing, a new remove retires the actual successor through its own barrier cycle; it never retroactively changes N's finalized disposition or uses N's cleanup for N+1. Original same-generation retirement waiters observe the original result. No external callback under registry lock.

Future race regression: pause synchronous observer, concurrently remove and attempt N+1 lookup/create/admission/publication; none activates N+1 before sealing and a pre-seal removal finalizes removed. A post-seal removal must drain actual N+1 independently. Exercise observer no-reentry/no-lock-dependent-wait behavior through real existing listener registrations.

**Cancellation:** cancellation before atomic start makes no transition. Capture initiating caller cancellation independently of NonCancellable; cancellation observed after start but before finalization is a failed/unavailable terminal transition even if cleanup succeeds. Finish all barriers/finalization/observers and settle shared result, then propagate caller CancellationException (retaining aggregate cleanup failures as suppressed); never swallow cancellation into success. A canceled joining waiter also waits NonCancellable for shared cleanup, then propagates its own cancellation without publishing identity. Joining waiter cancellation does not cancel shared drain. After successful drain, ProfileRepository/VM still check caller activity before replacement identity publication; no canceled caller commits a binding/auth/credential replacement. Later ordinary calls after failed/canceled transition remain fenced; transition never left unresolved.

**Failure/recovery:** retire/remove fail and keep unavailable latch; ordinary lookup/create/admission/retire/remove cannot clear failure, allocate a generation or rerun callbacks. `recoverRetirement(ref)` is an explicit owner/operator-directed **one bounded local cleanup attempt** for exact failed old ref: original captured barriers/disposition/reserved watermark, attempt all once, share completion among concurrent recoveries; pending original or wrong/nonfailed ref rejects ConnectionOwnerError(OWNER_MISMATCH). Recovery uses the same full NonCancellable drain/finalization/caller-cancellation rules, but no observer redispatch. No network/new identity/implicit retry loop. Failure/cancellation stays latched; success releases only original successor/removal after drain, never rolls back N or writes profile/auth/credentials. No resuming canceled identity mutation; later replacement requires separate uncanceled explicit existing-profile operation.

**Lifetime/ownership:** I1 VM registers barrier/token **before** any watcher/readiness/effect/collector eligibility. Registration failure/cancellation leaves producers ineligible/bindings unavailable; no synchronous-listener/detached fallback. Barrier calls C4's **planned** suspend coordinator.retire(oldRef)→provider.invalidate(oldRef), attempts all exact-old-owner prune/sink cancel/audio despite failures and propagates aggregate. Audio stop scoped/serialized: delayed N cannot stop N+1/another owner. No profile/registry query in callback chain. Final close disables producers and NonCancellable drains all owned refs, including retained pending/failed retirement refs (not merely current connectionsState); only after successful drain remove token/release resources. Failure preserves unavailable fence and captured cleanup resources/registration until explicit bounded recovery/drain, then unregister; captured callbacks survive removal, no missed window.
