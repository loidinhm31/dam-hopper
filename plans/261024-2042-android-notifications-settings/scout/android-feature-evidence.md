- The active Android root is Profile Login → Project List → focused Terminal/Files/Editor workspace. It has no Settings entry and does not mount `WorkbenchScreen`; existing Compose settings and notification modules are unreachable. Preserve the native root and no-WebView invariant.

## Architecture and current reachability

`AppFlowState` has only `PROFILE_LOGIN`, `PROJECT_LIST`, and `TERMINAL`; `DamHopperMobileApp` dispatches those stages and passes `preferencesStore`, not SettingsRepository or NotificationSink. The focused workspace has only inline Terminal/Files/Editor navigation. Architecture docs explicitly say the Workbench/PanelHost shell is unmounted and unreachable.

`NativeWorkspaceViewModel` owns an `AndroidNotificationSink`, but `MainActivity` does not pass it into the active root. Existing `SettingsScreens` is hosted by dormant `WorkbenchScreen`; its `SettingsRepository` is created there, not retained/injected into the guided root.

Native `TerminalRepository.agentStatusChanged` is collected in Workbench and passed to `AgentStatusReducer`. The reducer fences epoch/revision, deduplicates attention IDs, and avoids historical/replayed alerts, but does not call the notification sink. A native source search found no active-root `postNotification` producer; `NotificationsView` posts only its synthetic test alert. No transfer/idle-suspend publisher was found. Native `VtTerminalEngine.kt:177` drops BEL; no OSC 777/99 parser was found.

`NotificationSink` defines three channels: terminal attention, transfers, and idle suspend. The Android sink checks notification permission, uses private channels and immutable PendingIntents, and provides a generic public lock-screen version. `MainActivity.handleDeepLink` only checks profile/generation (and only rejects a mismatch when a connection exists); it does not validate or route epoch/terminal/incarnation/revision or consume extras once. Exact-target routing remains a gap.

The Activity lifecycle adapter maps start/stop to foreground/background and only detaches on destroy. Profile-retirement notification cancellation is wired in dormant Workbench. Background delivery depends on a live runtime connection; the source does not establish a reliable background guarantee. After-process-stop delivery is out of scope.

## Persistence, security, plans, and ownership

- `AndroidPreferencesStore.kt:10-58` serializes settings/source-target state to app-private ordinary SharedPreferences (not encrypted); credentials are separately stored by Keystore-backed `AndroidCredentialVault`. The manifest disables backup.

Remote endpoints include `/api/config` GET/PUT, `/api/config/projects/{name}` PATCH, `/api/global-config` GET, `/api/global-config/ui` POST.
