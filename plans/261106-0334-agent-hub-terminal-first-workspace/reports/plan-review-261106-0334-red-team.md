## Findings

### F1 — High: retired-editor reuse relies on a retirement fence that does not exist
- **Plan:** `P/phase-02-float-file-open-and-stacking.md:25,29,101–105,114`; `P/plan.md:63`.
- **Source:** `S/os/window-context.tsx:42–45,83–95` derives the owner generation from the **current snapshot**, not `window.ctx.generation`; `S/os/apps/EditorApp.tsx:286–296` claims with that owner. `S/stores/editor.ts:409–423,1234–1266` captures the current transport at save time; its post-await check does not prevent a write already sent. Reconciliation explicitly skips dirty tabs (`:2005–2027`).
- **Failure:** dirty document opened under generation G remains in a canonical editor; profile reconnects/rebinds to G+1; a valid G+1 Hub file request reuses it unchanged. Keeping the old `ctx.generation` does not keep it retired/read-only: the old buffer can save through G+1. A matching remote path/mtime makes accidental overwrite possible. This contradicts the stated no-cross-owner-save mitigation and AC1.
- **Confidence:** high, static call-chain evidence; no exploit executed.
- **Smallest correction:** remove the unsupported retirement assumption; define and implement an actual original-owner/endpoint fence for reused documents and saves, preserving dirty model/undo and failing closed on retired ownership. Amend ownership beyond the handler-only restriction where required; add reconnect/rebind + dirty-buffer save-denial acceptance. Merely choosing reuse versus replacement does not supply this fence.

### F2 — High: Hub cleanup can disable the successor terminal, with no composable presentation-input contract
- **Plan:** `P/phase-03-hub-terminal-mount-and-attach-gate.md:30–33,52,56–58`; `P/phase-04-shared-terminal-launch-lifecycle.md:26–27,75`.
- **Source:** `S/lib/terminal-input-policy.ts:22–41` directly changes shared xterm stdin/textarea state. `S/os/apps/TerminalsApp.tsx:331–378` only reparents/fits on acquisition; `S/lib/terminal-host-attachment.ts:35–62` never clears suppression. `S/components/organisms/TerminalPanel.tsx:294–314,568–588,931–943` has a separate replay/global suppression calculation, unaware of Hub presentation ownership.
- **Failure:** Hub releases a claim during project/desktop switch; a waiting standalone presenter acquires/attaches the same retained xterm. R7a protects only **parking** with the parent check, while the old pane still resets its key handler and suppresses/blurs that shared terminal. The successor can become noninteractive; on a quiet PTY no acquisition path restores stdin. Conversely, later panel replay/global recalculation can clear a pane-only suppression reason.
- **Confidence:** high; competing writes and missing handoff are explicit in the proposed contract.
- **Smallest correction:** freeze one owner-scoped presentation-input reason/token composed with panel replay/global guards. Make acquisition and release symmetric for Hub and standalone; guard **all** late cleanup mutations, not just DOM movement. Allocate the needed P01/P03/P04 interfaces/files before concurrency. Test Hub→standalone handoff both before/after old cleanup, quiet stdin recovery, and replay completion while no presenter owns input.
