## Approach
1. Preserve stopped open terminals as explicit UI items.
   - In `packages/ui/src/lib/terminal-auto-attach.ts`, change `deriveTerminalAutoAttachState` so a dead session is never auto-opened, but an ID already present in `openTabs`/`mountedSessions` remains until `handleCloseTab` or another explicit removal path removes it. Hydrate retained entries from the full `sessions` map, including `alive: false` and `exitCode`, rather than only `liveById`; continue honoring `ignoredSessionIds` so a just-closed live terminal is not reattached during the kill/query race.
   - Keep `handleCloseTab` in `packages/ui/src/hooks/use-terminal-manager.ts` as the sole normal close path: pinned tabs remain non-closable, an allowed close kills the PTY, removes both tab and mounted records, and suppresses auto-attach. `handleSessionExit` continues to invalidate `terminal-sessions`; the refreshed dead `SessionInfo` now updates the retained tab instead of deleting it.
   - Rename misleading derived field `tabsWithLiveSession` to `terminalTabs` with a clean cutover in `TerminalManagerDerived`, the returned object, `WorkspacePage` destructuring/render/dependency sites, and the `WorkspacePage.test.tsx` manager mock. No alias remains.

2. Share Runtime's activity presentation with Traditional terminal items.
   - Add `packages/ui/src/components/atoms/TerminalActivityIndicator.tsx` because no shared terminal-status primitive exists. Export `TerminalActivityIndicator({ sessionId, alive })`, subscribing through `subscribeToTerminalOutputActivity`/`getTerminalOutputActivitySnapshot` and preserving the current Runtime mapping and accessible labels exactly: dead → `Stopped`/danger; stream unavailable → `Output unavailable`/muted; recent output → `Receiving output`/success; ready without recent output → `Quiet`/warning. Keep the existing `h-1.5 w-1.5 rounded-full` geometry, semantic color tokens, `title`, and screen-reader label.
   - Also export `TerminalRunningIndicator({ running })` from the same terminal-specific atom for project aggregation: `running === true` renders success green plus `status-glow-green` and label/title `Running terminals`; false renders warning yellow plus `status-glow-orange` and label/title `No running terminals`.

Render the same component before each label in the active Traditional `DraggableTab` in `TabBar.tsx`; make the label button a flex row with a gap without changing drag, pin, close, or diagnostics behavior. 3. Build a deterministic Traditional project grouping model.

A non-empty `MountedSession.project` always belongs to that named project even for a `free:` session; only an empty project uses the synthetic `free-terminals` group labeled `Free terminals`. Ignore an orphan `TabEntry` until the manager supplies its mounted record, because it has neither a renderable xterm host nor a reliable project/layout target.
   - Set `hasRunningTerminal` only when at least one grouped tab has `tab.session?.alive === true`; stopped, failed, unknown, and pending-only groups remain yellow. Configured projects with no open tab never enter the input and therefore never appear.

This prevents a keyed remount from duplicating sessions from restored split panes into the focused pane. Continue pruning against the selected group's complete mounted-ID set so corrupted/stale IDs and empty splits collapse through existing helpers.
   - Render `MultiTerminalDisplay` with `key={selectedGroup.id}`, the group's v2 storage key, and only that group's `terminalTabs`/`mountedSessions`. The shared xterm host remains outside this keyed subtree, so project switches reparent existing terminal DOM nodes instead of recreating terminal processes. Because only one project's tabs and drop targets exist in the mounted split tree, existing drag-to-edge docking can split/reorder within that project and cannot produce a cross-project pane; leave `SplitLayout` and `terminal-layout-docking.ts` semantics unchanged.

## Assumptions & contingencies
- Unassigned terminals use a synthetic `Free terminals` project tab; a `free:` terminal carrying a non-empty project remains under that named project.
- Exited terminal items remain open until explicit close; this shared tab-lifecycle rule allows both Traditional and the unchanged Runtime renderer to display stopped metadata.
- Project navigation follows `terminalAutoSwitchProjectEnabled`; it always changes the Traditional terminal surface, but changes Files/Git/global project only when that setting is enabled.
- Compact/mobile Traditional mode uses a `Projects` bottom sheet rather than omitting the navigator.
