### Proposed contract and ownership

- Retain **Git presentation state** per `WorkspaceFileOwner` (section, nested route, selection/scroll) separately from runtime. Bind the existing Git repository/controllers to exact owner plus current `ConnectionRef` generation; stale requests/callbacks must not update the new view. Keep `EditorTabsState`, `ProjectTerminalState`, and `TerminalRepository` as their existing owners.
- Host callbacks: `openWorkspaceFile(relativePath)` routes through existing editor tabs; `requestWorktreeSwitch(target)` uses the dedicated guard/revalidate/commit path; `preflightRemoval(target)` aggregates retained dirty docs plus fresh target-qualified terminal inventory; `refresh(reason)` covers entry/foreground/manual/mutation. Mutations refresh Git and clean editor/tree state, never overwrite dirty docs.
- **Proposed new paths:** `shared/src/commonMain/kotlin/dev/damhopper/nativeapp/features/git/GitWorkspaceState.kt` (presentation state), `.../features/git/GitWorkspaceRuntime.kt` (owner/generation-qualified bundle of existing Git runtime); `androidApp/src/androidTest/kotlin/dev/damhopper/nativeapp/NativeGitWorkspaceJourneys.kt` (real active-root journey with disposable Git fixture). These are proposals, not existing files.
- **Sequential shared-host integration write set:** `ProjectWorkspaceState.kt` + `AppFlowNavigation.kt` (state/transition contract) → `NativeWorkspaceViewModel.kt` + `DamHopperMobileApp.kt` (runtime binding and preflight callbacks) → `ProjectWorkspaceScreen.kt` (reachable Git tab and UI callbacks). Serialize ownership/handoffs; recovery/sidebar plans touch the same paths. Add/update tests and docs after host contract stabilizes.
- **Intentionally not in that host write set:** `ProjectTargetStore.kt` already has target/discovery/revision APIs; sync it only after the guarded flow commit. `MainActivity.kt`, `ProjectTerminalScreen.kt`, `ProjectTerminalState.kt`, `EditorTabsState.kt`, and native editor host should remain unchanged unless a concrete integration gap is demonstrated. Git UI/repository/controller files such as `GitPanelScreen.kt` remain with the Git-feature owner.
