## Graph algorithm constraints

Build a pure layout from commit OIDs, ordered parent OIDs and refs; do not infer ancestry from timestamps or adjacent rows. The server’s log output does not promise a topological row order. Parent OIDs absent from the current result must remain unresolved/off-page lanes, not connect to a nearby row. Appending pages should deduplicate by OID and resolve those lanes when a parent arrives; filtered search must not draw invented edges through commits omitted by the filter. The current API has offset pagination but no frozen snapshot guarantee, so refresh/reconciliation is required if history changes between pages. For squash, validate the selected oldest-first sequence by actual parent links and single-parent eligibility, not displayed row adjacency. [repository.rs:1627-1688](../../../server/src/git/repository.rs), [GitHistoryController.kt:82-140](../../../native/android-app/shared/src/commonMain/kotlin/dev/damhopper/nativeapp/features/git/GitHistoryController.kt), [git.md:214-256,476-523](../../../docs/api/git.md). **[INFERENCE]** Recompute a pure layout from the deduplicated visible OID set after page append/search change; render with Compose without doing graph calculation per draw.
