## Key Insights
- `input-controller.ts:401-419` silently truncates UTF-8 text to 4096 bytes; `text-input-proxy.tsx:164-175` clears clipboard staging regardless. Coordinator-selected default: bounded whole-paste admission, UTF-8-safe ordered insertText chunks, explicit rejection/interruption feedback—not a larger server record or clipboard wire protocol.
- `input.rs:13-15,441-481`: 4096 raw UTF-8 bytes/insertText, 128 reliable records and 256KiB estimated queued bytes; `media.rs:55-58,1620-1636`: 16KiB serialized control message and enforced 100 text messages/s. The declared burst200 is not additional receive allowance. JSON escaping can make a valid 4096-byte text record exceed 16KiB.
- Canvas-only handlers miss mouse-up outside its bounds (`canvas-view.tsx:92-105`, host `:2012-2066`). Capture fixes local delivery; native PointerCancel is currently a no-op (`media.rs:1985`), exclusively repaired by upstream `enforce-paired-input-lifecycle`.
- Wheel forwards raw deltas despite its normalization comment (`input-controller.ts:332-357`). Rust enum-level camelCase does not rename variant fields: `input.rs:64-69` reads `delta_x/delta_y`; duplicated TS camelCase fields are not server authority.
- Control select polls updates ahead of receive (`media.rs:1563-1609`); no measured starvation. Inline CDP dispatch bounds/failure propagation (`:1646-1668`) remain upstream; only ready-branch ordering changes here.

## Requirements
- Initial total paste cap **16KiB raw UTF-8** (tunable DoS bound, not a server maximum). Above cap: reject entire paste before enqueue/send and show a content-free visible message. At/below cap: preflight all chunks and available existing queue record/byte capacity atomically; if unavailable, reject whole paste visibly before the first chunk. Preserve the existing 16KiB serialized handoff budget; it may reject a paste below the raw cap when escaping or other typeahead consumes capacity—say busy/too large, never truncate or silently expand that budget.
- Split only at Unicode scalar/UTF-8 boundaries; each insertText ≤4096 raw bytes **and** complete serialized InputMessage ≤16384 bytes, accounting for JSON escaping and actual bounded envelope/counter widths. Re-split escape-heavy chunks if needed. A 16KiB paste needs normally four records, at most seven with escape-aware splitting and the current small envelope; preflight actual counts/bytes rather than relying on this estimate. Raw queue charge is text bytes +8/record, comfortably below server 128-record/256KiB ceilings in isolation; existing queued work still counts.
- Admit chunks as one ordered batch in the existing paced discrete queue/handoff, not a new FIFO; later typing cannot overtake its tail. Allocate sequences only at send, keep ≤80 normal records/s combined and upstream cleanup headroom beneath server100/s. Preserve original socket/lease/owner/subscription/viewport fences on every send. Do not queue an unauthorised paste except the existing explicit gesture handoff.
- Rejection and mid-paste cancellation/lease/socket/native-failure status must reach existing visible owner-qualified feedback, never only console. Clear staging only after explicit accepted/rejected handling. If interrupted after any chunk, cancel unsent tail and warn that remote text may be incomplete; never auto-replay. Existing insertText has no application acknowledgement/transaction: local admission/send is not proof of full native insertion; do not promise atomic remote paste or fabricate success.
- Capture pointerId on accepted down only: already-held lease dispatch accepted, or existing provenance-fenced click-to-acquire gesture accepted locally. Pending acquisition capture conveys no remote authority. Release on matching up/cancel; unexpected lostpointercapture follows the existing cancel path. Mark normal completion before release so resulting lostpointercapture cannot double-cancel. Capture failure cancels accepted gesture safely. Privacy/modal/hidden/owner/lease loss and unmount cancel/release original capture without retargeting; never capture rejected/letterbox gestures.
- Normalize before wheel coalescing to CSS pixels: pixel mode ×1; line mode ×**16 CSS px** (tunable convention, not remote computed line-height); page mode ×current trusted remote CSS viewport width/height per axis (not JPEG/backing/DPR). Use existing authoritative geometry via controller options/host bridge. Reject nonfinite/unknown-mode or unavailable-page-geometry input; clamp each normalized event and accumulated outgoing axis to **±4096 CSS px** (tunable safety bound), preserving sign/fractional pixel deltas below the bound. Emit only canonical `delta_x/delta_y`; remove redundant TS camelCase members/accumulation and migrate affected consumers, no server alias or wire rename.
- Fairness only: preserve mandatory initial control snapshot and outer biased cancellation/absolute-auth-deadline priority. After initialization, alternate update-vs-input preference when both are ready; a continuously ready update cannot win two consecutive arbitration turns over ready input, nor can continuous input indefinitely suppress updates. Retain latest watch slot, existing bounded write/auth deadlines and upstream dispatch ordering/failure rules. No additional worker/queue, throughput target or starvation/performance claim.

## Architecture
Text proxy → existing controller bounded batch admission → Phase 02 sequenced/paced discrete path → existing control socket → upstream validated/ordered native dispatch. Reuse content-free onError/current host alert; queue reservation is local all-or-nothing, not remote transaction semantics. Measure bounded UTF-8 length before allocating encoded chunks; avoid copies of the entire paste per record and discard cancelled buffers promptly.
Host owns accepted/pending gesture provenance and DOM capture identity; CanvasView forwards lostpointercapture to the same cancellation owner. Geometry/controller bridge supplies CSS page dimensions; normalized wheel records use the existing coalescer. Control-session loop retains outer priority safety branches and a small rotating preference for its two ordinary ready branches, not wholesale media writer/dispatch restructuring.

## Implementation Steps
### preserve-bounded-paste
1. Inspect delivered paced queue/handoff and content-free status bridge; preflight total UTF-8 size, escaping-aware chunks and aggregate existing queue capacity without sending a prefix. Use 16KiB tunable total, not a server limit increase.
2. Admit ordered chunks together; retain send-time sequence/authority checks and unified budget. Surface size/capacity rejection and interrupted/unknown-completion warning, discard unsent tail on cancellation; proxy cannot silently clear a rejected or truncated transaction. Keep IME transaction dedupe upstream unchanged.
3. Add consumer-visible full multibyte paste/oversize rejection and interruption regressions; include control-character escaping and handoff capacity boundaries. Native DOM content, not concatenated outgoing mocks alone, proves the full-paste claim.
### capture-accepted-pointer
4. Bind capture to accepted down/pointerId in actual host+canvas path, including accepted asynchronous acquisition; route matching up/cancel/lost capture through one idempotent completion/cancel owner. Release on suppression/disposal and preserve current last-valid-coordinate up behavior outside image bounds.
5. Rely on upstream native cancel/release implementation; assert actual remote mouse-up after outside-canvas release and cancellation, not just a setPointerCapture spy. Rejecting a gesture or becoming private/modal must not dispatch/retain capture.
### normalize-wheel-units
6. Normalize all three delta modes before accumulation; use CSS page dimensions and bounded finite axes. Remove only duplicate camelCase wire fields and migrate TS event consumers; Rust snake_case/CDP translation stays unchanged.
7. Assert line/page/pixel remote scroll displacement on a deterministic scroll fixture, including DPR/downscaled JPEG independence, signed fractional pixels and bound behavior. Do not test for a comment/function name or general performance gain.
### arbitrate-control-input-fairly
8. After upstream dispatch repair, change only ordinary ready-branch preference after the initial snapshot. Keep cancellation/deadline first and rotate fairly after serviced update/input; preserve bounded watch-write and dispatch semantics.
9. Deterministically hold updates and a real queued input ready, churn session snapshots, observe native input before another ready update can repeatedly preempt it; reverse workload proves updates still flow. Ready cancel/deadline must prevent further input even under churn. No benchmark or rewritten dispatch owner.

## Risk Assessment
Queue admission is not remote transaction commit: interruption can leave a prefix; warn and never retry ambiguously. Escaping/handoff overhead can reject below raw cap, so preflight actual bytes and show the truthful reason. Releasing capture emits lostpointercapture; identity/idempotence prevents double cancel or successor damage. A16px line convention may differ from site line-height, but provides stable CSS semantics;4096px clamp intentionally bounds pathological events. Fair arbitration cannot preempt an in-progress write/CDP await; those bounds remain upstream, no claimed latency fix. Rollback: drain pairs, revert only matched Phase06 changes while preserving remediation/pacing/security; disabling affected input is safer than restoring silent truncation or unsafe release.

## Security Considerations
Paste is private user data: never log clipboard text/chunks, tokens or raw input; visible errors are content-free and owner-qualified. Total-size/queue/message/rate bounds are DoS protection, not permission to expand server ceilings; bound length scan/allocation and discard cancelled buffers. Pointer capture cannot bypass Cognito privacy, modal input isolation, visibility, trusted hit geometry, current lease/pair or original-channel cleanup. Wheel normalization does not grant authority; only existing authenticated input path. Fairness preserves cancellation/auth deadlines and no unauthenticated surface/new protocol kind.
