# Native editor/explorer implementation contracts

Authority: [plan](plan.md); approved [brainstorm](../reports/brainstorm-261023-1351-native-editor-file-explorer.md). These are intended contracts, not implemented APIs or qualification results. PascalCase Kotlin filenames match existing repository conventions. All file actions continue through existing FileRepository/ApiClient/WsConnection. No backend schema/runtime/flags/scheduler or parallel file API.

## C1 — Logical owner and revocable authority

- `WorkspaceFileOwner`: captured profile ID **plus normalized endpoint and authenticated account identity**, project and normalized optional worktree. Account identity = server-returned `AuthSession.user` from `AuthStatus.Authenticated` (`features/profiles/AuthState.kt:45`); loopback `--no-auth` reports constant `dev-user`, valid only for that endpoint. Labels and `ServerProfile.username` are not identities. If `user` proves absent/unstable on a supported auth path, phase02 escalates a design revision rather than guessing or disabling all writes. Do not compare only profile IDs/project names. Preserve server path casing; normalize separators and reject traversal/root misuse, not case-fold remote paths.
- A document identity is `(logicalOwner, relativePath, tabIncarnation)`. Use structured identity internally; presentation key serialization must not create delimiter collisions. Incarnation is monotonic in retained owner, never reset on reconnect or close/reopen. Rekey after confirmed rename changes path, not document/undo/incarnation.
- `FileAuthority`: exact logical owner, ConnectionRef generation, live SocketInstanceRef and retirement token. Bind ApiClient and WsConnection to the same ConnectionRef/endpoint; assert ProjectTargetRef owner before request and after suspension. No ambient active-profile fallback. REST completion uses captured connection/owner; WS completion additionally uses socket.
- Socket origin must come from transport dispatch, not sampling current WsState when a buffered raw message is collected. Phase02 adds a bounded local `SocketBoundMessage`/socket-qualified observer and expected-socket request/send seam to existing WsConnection; no wire message/schema, new transport runtime, scheduler or filesystem API. All scoped file read/write/watch consumers migrate to captured origin/expected-socket calls. Existing legitimate non-file raw consumers retain their unchanged exported API; no deprecated alias or broad unrelated transport rewrite. If an existing exported message signature must change instead, stop and enumerate/migrate every caller under revised exact ownership before proceeding.
- Expected-socket dispatch atomically binds the expected SocketInstanceRef, captured writer and request correlation under existing transport serialization; a suspendable lookup/check followed by an unguarded send is insufficient. Socket replacement cannot redirect an already captured file request/commit/unsubscribe to the new writer. Do not hold document/arbiter locks or wait for server response inside transport dispatch serialization. Test replacement between authority check, writer selection, queueing and dispatch; classify cancellation after possible mutating submission conservatively.
- Retire authority synchronously on profile/account/endpoint change, auth loss, disconnect or socket replacement; cancel authority jobs and subscriptions. Keep detached documents under original logical owner. Reconnect rebinds only exact logical owner after stat/current-server reconciliation; never retarget drafts. Identical paths across two profiles, projects and worktrees must remain independent.
- Every async load/reload/range/save/error/diagnostic callback captures owner/authority, tab incarnation, operation ID and applicable document revision/range-request epoch. Revalidate **all** before publishing or disposing listeners; key equality alone insufficient. A late callback cannot clear loading/saving/error state of a replacement operation/tab.

## C2 — One document authority and platform bridge

Hard prerequisite: phase01 proves exact pinned Sora APIs can satisfy this contract. Names below define common facade intent, not claims about Sora signatures. Phase02 freezes concrete common signatures and records exact verified mapping before 03/04/05 start.

- `EditorDocument` is the sole interactive text/undo owner. Android implementation holds the qualified native Content/undo object without an Activity/widget reference. `EditorSession` holds metadata, owner, baseline revision/mtime, save state and document handle only. Remove shared StringBuilder, shared full-text undo snapshots, Android prototype StringBuilder/undo/session duplication and Compose TextField editing authority.
- Facade includes document ID; revision/length/undo availability/read-only/view-state flows; incremental `applyEdit`; commands undo/redo/find/next/previous/selection; `replaceFromLoad`; explicit `snapshotForSave`; attach/detach widget binding and close. Session/tab/close-intent/conflict/save-outcome/dirty-guard ports consumed by explorer and presentation are frozen in phase02 `EditorSessionPorts.kt`; consumers never read removed EditorTab/EditorSession fields. Preserve existing in-file replace behavior through document commands if retained in UI; no second string-based implementation. `EditorDocumentFactory` is injected from Android, with a **test-only** faithful document double for shared state tests, never a production TextField or fake fallback.
- All document/metadata/UI mutation serialized on the retained UI dispatcher (Android main). IO only transports immutable captured inputs/results. No lock held across UI prompt or network await. Listener registration/removal and document events run on same dispatcher. Apply delta once; user command and native callback cannot both apply it. Use explicit source token/suppression for programmatic load/reload; emit one ordered replacement event after native replacement, reset undo intentionally and advance revision. Recomposition never calls setText.
- Native text delta updates revision, dirty/length/selection metadata without copying whole text. A save snapshots text once on owner dispatcher into immutable submitted bytes/revision, then releases dispatcher. Do not mirror content/savedContent/submittedContent strings in EditorTab/StateFlow; only metadata plus bounded range content for read-only views. Baseline uses document save-point/revision identity (including undo to a save point), not full string comparison. In-flight submitted bytes exist only for save/reconciliation and are released when settled; no full document snapshots on keystroke/recomposition/diagnostic debounce.
- Load/reload bytes are immutable ingress data consumed once by document replacement. Native syntax highlighting runs incrementally. Active focused editor does not start TS/LSP/blame/rich preview services. Retained dormant diagnostic publications, if any, obey C1 and cannot trigger full-text per-edit copies; migrate their callers without introducing semantic parity.
- Detach saves cursor/selection/scroll, deterministically finishes or cancels active IME composition (no duplicated/lost text; uncommitted composition is not retained), removes listeners/focus/input and releases Activity-bound widget. Retain Content/undo/view state in non-Activity owner. New widget reattaches same document; no reloading/resetting history on panel switch/rotation. True owner close frees Content/resources; Activity configuration destruction does not. Failure to qualify this is a design blocker, not permission for duplicate undo.
- Bounded retention: measure native Content/undo allocation in phase01/08; explicit finite tab/document byte+undo budgets in one policy (no arbitrary new file-tier thresholds). Count live documents and submitted snapshots; limit undo using native bounded policy only. At budget, evict clean inactive docs with metadata/restoration, or refuse further opens with actionable notice; never silently evict dirty/unresolved docs. No process-death draft guarantee. Normal/degraded tier limits unchanged.

## C3 — Reads and file tiers

- Binary/media classification precedes size. `<1,048,576` bytes normal; `1,048,576 .. <5,242,880` degraded editable with expensive features disabled; `>=5,242,880` read-only range view. Unsupported media/binary shows bounded noneditable notice/probe, not full Base64/hex/preview load. Invalid UTF-8 is unsupported, never editable/saveable; no replacement-character recovery followed by save.
- Always issue explicit offset **and** len for bounded WS/REST reads. Editable ingress requests bounded to tier ceiling/probe, rejects actual bytes at/above read-only cutoff before document creation, restats/reclassifies growth; no stat-only trust or unrestricted fallback. Inspect Base64 encoded length before decode; reject oversize decoded bytes. Add bounded streaming byte receive helper to existing ApiClient for REST fallback, retaining auth/redaction/owner/redirect safeguards. Do not use bodyAsText for strict file bytes. Reject excess bytes before materializing unbounded response. Existing server response casing/DTOs remain unchanged.
- Range window is at most 65,536 requested bytes, plus at most three carried UTF-8 boundary bytes; no whole-file assembly. Strict decoder retains incomplete trailing sequence, distinguishes malformed middle/EOF, advances transport offset by actual received bytes and logical display boundary by consumed bytes; carries join next sequential range without skip/duplicate. Keep bounded previous window start metadata for Back; arbitrary initial offsets align safely or reject, never lossy-decode. At EOF an incomplete sequence is invalid. Guard window callbacks by range-request epoch and C1; no save command for range/binary/invalid/unavailable paths.
- WS failure fallback only for eligible read transport failures and same captured owner/offset/len/byte limit. No fallback on auth/retired owner, malformed/oversize response or semantic server rejection; cancellation propagates. REST binary JSON marker is interpreted as a marker, not editable JSON text. No widening on fallback.

## C4 — Save outcomes and conflicts

- Normal save uses last observed server mtime, preserving its actual wire unit. Submit captured revision/bytes/path/owner; edits after snapshot remain dirty after success. Serialize overlapping saves via C5; no unrelated-project lock. Failed save never discards buffer or navigates away.
- Conflict offers Reload / Explicit overwrite / Cancel. Reload requires explicit discard consent and revision guard. Explicit overwrite does fresh stat then conditional write with that observed mtime; another race still conflicts. No unconditional expected_mtime bypass. New user edits before reload publication invalidate discard consent/revision; reprompt rather than erase them.
- Local operation result separates `NotSubmitted` (mutating op/commit provably not attempted), `Rejected` (definite authoritative server rejection), `Confirmed` (matching server success), and `Unknown` (mutating dispatch may have occurred; include stage/op ID). Begin/chunk failure before commit is not a post-commit unknown file write; retain temporary-write cleanup/disconnect semantics without inventing abort messages. Mark Unknown **before** attempting commit or fs:op send unless lower transport proves no enqueue; send exceptions alone cannot prove unsent. Cancellation after dispatch also preserves Unknown. Existing server DTOs gain no fields.
- Unknown save keeps submitted bytes/revision/baseline and reservation. Reconcile fresh stat **and bounded current bytes** against submitted/baseline state, exact owner and relevant path; mtime/existence alone not proof. If current bytes equal submitted bytes, adopt observed baseline for submitted revision, preserving newer edits. If remote content differs, present conflict/unresolved state without retry. Release submitted buffer only after settled or explicit informed local abandonment (never re-enable original path writes while outcome remains unresolved).
- `encryptedRequested` is existing explicit client mode, not inferred project policy. Missing/invalid/retired owner-bound crypto session rejects before plaintext submission. No new enrollment/key transfer; active UI must not advertise encrypted readiness absent qualified prerequisites.

## C5 — Save/mutation arbitration and identity transaction

- `FileOperationArbiter` is retained per logical owner. Conflict relation is path equality/ancestor-descendant over normalized segments, never raw prefix (`a` must not reserve `ab`). Mutation reserves source subtree and destination subtree **atomically** before dirty resolution; saves reserve their exact path. Existing conflicting save must settle before exclusive reservation proceeds; if Unknown, mutation remains blocked, not queued to blind retry. No global lock or background retry scheduler.
- Holding reservation is a token/state, not a suspended mutex. Dirty prompts run unlocked. Save action inside a mutation uses child capability of reservation for affected paths, avoiding self-deadlock. While prompt is open, block new saves/mutations and destructive identity actions on reserved subtree; freeze affected interactive edits during final dirty decision/dispatch, preserving focus restoration on Cancel. Revalidate dirty revisions before proceeding. Save must confirm all affected current snapshots; Discard consent applies to captured revisions only. Capture rollback view state; no text destroyed until corresponding close/delete/explicit discard commits.
- Before dispatch, cancellation/failure releases token and leaves identity/buffers unchanged. Definite server rejection likewise releases after errors published. Confirmed rename/move commits one owner-dispatcher transaction: descendant tab keys/paths, sessions, active selection, loaded tree paths and watch demands rekey together; invalidate obsolete async path callbacks while preserving document incarnation/undo. Collision with open destination tab must be resolved before dispatch; never overwrite another buffer silently. Confirmed delete makes affected docs unavailable (dirty text retained when remote deletion is external/forced), disables save/recreate, removes tree/watch demand appropriately. Client never recreates a remotely deleted file just by saving preserved text.
- Unknown fs:op retains reservation and **original local identity**, displays unresolved operation, disables retry/conflicting actions; still preserves affected buffers. Reconcile captured source and destination metadata/listings plus bounded content where applicable against pre-op evidence. Directory moves lack server operation IDs/inodes; existence, matching names/mtime/content alone may be ambiguous with external writers. A late matching ACK on original authority can confirm; otherwise publish a new identity only when the existing protocol provides sufficient evidence, and keep unresolved when it cannot. Do not label inference as confirmation. Allow informed local Discard/exit without claiming the remote operation failed; retained quarantine remains for return to that owner until reconcilable. No automatic duplicate create/move/delete.
- Existing fs:op root/containment/.git rejection authoritative; never send force_git to bypass it. Streamed writes use different backend protection and do not inherit fs:op's .git guard. Document this current limitation; client checks are usability only, not server security enforcement.

## C6 — Shared nonrecursive watches and listing watermarks

- `FileWatchDemand` represents root/expanded directory and open-document parent consumers. One active subscription per `(owner,socket,directory)` reference counted across explorer/editor. Collapse drops explorer demand only; open-parent demand remains. No recursive assumption.
- Listener begins before subscribe; bounded early/event queue (finite count and bytes, constants with tests) receives transport-origin socket envelopes and routes by owner+SocketInstanceRef+subId and subscribe-request incarnation. Sampling current socket on raw-message receipt is insufficient. `subId` reuse on another socket cannot route old events. Never use raw absolute path/from when target-relative fields absent; invalidate/refetch instead. Unsubscribe uses expected origin socket only; no stale cleanup on replacement socket.
- For each loaded directory: monotonic listing request epoch and received event sequence. Capture event watermark on request; publish listing only if request current and owner/socket/subscription current. Replay bounded events newer than watermark in order, or discard response and refetch if history incomplete/ambiguous. A slow snapshot cannot overwrite a newer event/list. Snapshot + buffered early events follow same barrier. Coalesce invalidations, not silently drop required baseline changes.
- Server overflow drops subscription. Client overflow too invalidates baseline: retire subscription, **recreate it**, then refetch relevant loaded directories/open-doc metadata. Do not refetch against dead non-null subscription. Reconnect/socket replacement recreates all current demand; stale callbacks ignored. Background cancels watches/jobs and retains tree/docs; foreground subscribes first and reconciles loaded listings + open docs before enabling writes. Clean modified docs reload with revision guard; dirty docs mark stale. Deleted dirty docs become unavailable, never silently recreate.

## C7 — Retained active root, navigation and terminal

- Keep login → project list → project workspace. A focused `ProjectWorkspaceScreen` owns Terminal/Files/Editor local panel state and single project header/nav row above IME, one visible content area on phones/tablets. Open file selects Editor. Hide focused Files search/replace actions and editor preview/blame/unsupported crypto actions without deleting unrelated dormant modules.
- Android ViewModel/non-Activity runtime owner retains profile registry/repository, auth/transport runtime, navigation, workspace/doc/tree/terminal owners and coroutines; Android services use applicationContext only. Lifecycle adapter for each Activity forwards foreground/background, not final document destroy on configuration change. ViewModel onCleared/explicit resolved workspace destroy owns final teardown. Process death not durable recovery.
- Reuse ProjectTerminalScreen + current VtTerminalSurface, atomic snapshots, replay/incarnation checks, bounded FIFO input, sessions, pinch/font preferences (10..32sp; font+4sp metrics), resize and diagnostics controls. Extract its controller/map/queue/view state lifetime; do not mount WorkbenchScreen or swap to old terminal. Every branch setting isPanelActive=true (replay/session attach/reconnect/reactivation included) AND dispatch path checks panelVisible && lifecycleForeground && current owner/input policy. Hiding a panel removes focus/IME and blocks keyboard/paste/hidden TextField; terminal output/session state may continue bounded.
- Voluntary tab close, Projects, system Back, profile/project change, deep link changing owner, explicit exit: one retained departure guard captures action/dirty revisions **before** navigation/session clearing. Save/Discard/Cancel; Save must succeed and no newer edits remain before commit. Cancel/failed save keeps route/PTY/tab. Concurrent exit requests coalesce without double dialogs. Phase07 migrates all callers, including MainActivity BackHandler and terminal header's selectSession(null) path.
- Forced auth/transport loss cannot wait for Save: revoke writes/input first, detach buffers under original owner, transition auth UI without disposing them. Reauth exact owner reconciles; another profile cannot adopt drafts. User-visible unavailable/detached state and explicit discard remain reachable; no false promise of process-death recovery.

## Gate decisions and rollback

Phase01 blocks downstream contract freeze if pinned native document/undo/language/version APIs cannot satisfy C2. Phase02 freezes the concrete facade before parallel ownership. Any signature/path change after freeze stops affected workers and revises dependencies/callers, not a compatibility shim. Runtime gate failures block acceptance/release; do not change tiers, silently upgrade or use a basic-text fallback. Roll back unreleased cutover as one coordinated feature change, preserving current terminal and unrelated modules; never destructive Git or backend changes. Unresolved server-side outcome remains explicit even when UI integration is rolled back.
