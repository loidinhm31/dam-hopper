# Session changes — frozen implementation contract

Status: selected design, pending implementation and independent review. Authoritative scope: [approved design](../reports/design-261030-0043-session-changes-panel.md); evidence: [repository](reports/repository-evidence.md), [OMP](reports/omp-lifecycle-evidence.md), [UI](reports/ui-evidence.md). `S1`–`S12` below are acceptance references, not deployed capabilities. Changes to this contract stop consumers; sole integration owner reconciles dependent tasks before resuming. No new daemon, timer service, port, environment variable, feature flag, database schema or production dependency.

## S1. Identity, scope and authority

Tracking key = `(serverEpoch, terminalId, terminalIncarnation, ompSessionId, canonicalRootIdentity)`. Server epoch and baseline ID are random opaque UUIDs generated by server; incarnation and comparison revision travel as canonical unsigned decimal strings, never JS numbers. OMP session ID is exact, nonempty, at most 200 UTF-8 bytes; reject invalid/oversized IDs rather than truncate/collide. Registration/nonce/request/turn IDs are opaque, nonempty ASCII tokens <=200 bytes. Browser owner = existing `ConnectionRef` profile+generation, then `TerminalInstanceRef`; not a server authorization credential.

The producer credential is existing collector bearer; derive terminal/incarnation from `authenticate_bearer`. A producer cannot submit an authoritative terminal, project, worktree or arbitrary root path. Producer may submit `rootId` (default `.`) and `cwdHint`; resolve these *within* the server-bound launch target. Exactly one selected root per OMP identity; a changed root returns `rootMismatch`, never overwrites the original. Switching to a different OMP identity creates/reuses its own record; switching back reuses original bytes. Explicit from-now may establish a separate origin after failed/missing original, not relabel it.

**Current-source binding decision:** `api/terminal.rs:96-118,152-237` resolves project/worktree and validates cwd before `PtyCreateOpts`; `manager.rs:1512-1524,1700-1744` reserves then activates incarnation credential. Bind a service-owned immutable launch descriptor at this same publication boundary, before credential activation; it contains server metadata project/worktree/canonical launch cwd, target identity and workspace-context generation. For configured root terminals re-resolve `ProjectTargetRef {project, worktreePath:null}` and sandbox-validate launch cwd. For linked worktrees re-resolve the exact registered `worktreePath` and sandbox-validate it; `cwd` cannot promote to another worktree. Revalidate current workspace target/generation and canonical root before capture, refresh and publication. Never hold manager/domain locks over async or blocking filesystem work.

Untargeted terminals currently accept arbitrary cwd without project sandbox validation (`terminal.rs:181-184,240-255`). For tracking only, map canonical server launch cwd to exactly one currently configured project sandbox root containing it; zero/ambiguous matches => `targetUnavailable`. Do not discover unrestricted HOME repositories or registered external worktrees from producer cwd. A project-associated free terminal follows its bound project target. This preserves terminal usability and approved inside-validated-project scope; no change to free-terminal launch authorization. Use only direct canonical `resolve_vcs_root` containment semantics (`git/vcs_roots.rs:141-172`) behind the bounded preflight below; never `resolve_git_request_root`, `discover_vcs_roots`, Git status or nested discovery for authorization. Reject aggregate `*`, traversal, root outside target or root not containing the validated hint. No nested repository/submodule traversal when capturing selected parent root; gitlinks and nested roots have explicit unsupported coverage.

### Bounded direct root preflight (Q2)

`session_changes/root.rs` accepts one caller-selected relative root ID (default `.`), never discovers a root list. Before canonicalization: each target/cwd/root path <=4,096 UTF-8 bytes, <=64 components; reject empty components except canonical `.`, parent traversal, absolute root IDs, NUL and aggregate `*`. Canonicalize only authoritative target, requested root and optional validated cwd hint; use direct `resolve_vcs_root` validation, then descriptor-safe/no-follow metadata checks for the selected directory and its `.git` marker. A regular `.git` file or directory is a marker only; no marker contents, config/status, Git output or recursive directory discovery is needed for authorization. A false/malformed marker fails later bounded inventory, never broadens filesystem authority. Recheck canonical containment/identity on publication. Existing helper's `is_dir/is_file` checks alone do not replace secure entry/ancestor validation.

Root preflight shares the two global blocking permits and accounting/cancellation reservation **from its first filesystem operation**, <=1s monotonic included within capture10s/compare5s, <=128 metadata operations, <=64KiB transient path/metadata storage. Untargeted containment checks at most128 currently configured candidate roots and <=512KiB aggregate input path bytes; over-limit/ambiguous => targetUnavailable/rootLimit, not discovery or unlimited fallback. Candidate iteration also counts against metadata/time/storage caps (may refuse below128 if exhausted). Budget exhaustion/unstable ancestry fails closed before content capture; blocking I/O may hold permit until exit but cannot publish late. No `.output()` subprocess, collect-all status, recursive width scan or unbounded root helper outside these budgets. Existing project/worktree resolver supplies the authoritative registered target only; it is not permission to enumerate Git roots during this feature preflight.

Public endpoints use existing authenticated-account middleware and its loopback-only no-auth exception. Existing repository has no per-user PTY ACL: do not invent one or claim account isolation stronger than server policy. Check exact terminal/incarnation and validated target on every query. Source bytes never enter private collector/status frames, logs, notifications, query keys, browser persistence, analytics or evidence intended for production diagnostics.

### Ordered root-interactive barrier

1. Async `session_start` / `session_switch` run only root interactive `hasUI:true`, main agent. Establish exact identity and a per-attempt monotonic live token **before any await**. Keep adapter session map across switches; session transition cancels only an unactivated in-flight attempt for the old identity. Reconnect does not retry a failed original. Hook catches all failures, continues terminal/model operation, reports only safe failure metadata.
   Freshness is explicit, not inferred from absence of a server record. OMP `shared-events.ts:30-49` initial start has no reason, switches have `new|resume|fork`; `ReadonlySessionManager` exposes getEntries/getSessionFile (`session-manager.ts:726-747`), local session files are lazy until assistant/ensureOnDisk (:3219-3231). Initial `capture/initialFresh` allowed only when local allocated session file is absent, loaded metadata has no user/assistant conversation entries, and this adapter has no prior attempt. Inspect role/type/existence only, never source/prompt/transcript text or session-file contents; do not transmit or log the session path/history. Missing/remote/unverifiable capability => lookup/unknown. Switch `new`/`fork` may capture distinct identity before its first new turn; `resume` and persisted/history-bearing initial sessions use lookup only. Server lookup returns existing record or explicit originalUnavailable/missing, never capture; unknown/restarted original requires explicit from-now. Conservative unavailable for ambiguous startup preserves terminal usability and honest AC7 rather than retroactive reconstruction.
   Adapter retains at most32 identity-attempt entries without eviction. On map saturation, permanently refuse capture for further unknown identities in that adapter lifetime (known identities still lookup/reuse); do not forget failed attempts to reclaim slots. No transcript retention; S12 qualification verifies local freshness provenance on actual installed OMP, and ambiguity must remain unavailable rather than guessed fresh.
2. Producer `prepare`: unique registration ID, local wall expiry now+10s (same-host sanity only); overall adapter barrier maximum **12s measured monotonic**. Server rejects already-expired arrivals, clamps future expiry to 10s, then uses monotonic accepted deadline <=10s for inventory/read/publication. One reservation per exact identity; duplicate same request is idempotent, other original requests do not recapture. The clock sanity check is **not** the correctness barrier.
3. Engine can publish only **PREPARED** immutable bytes/manifest with one-use random nonce. PREPARED is never public `ready`, even with complete capture. Preparation TTL **15s monotonic from accepted reservation**, including capture, activation and receipt; checked on access and existing collector lease tick, no new scheduler. Deadline/cancellation invalidates publication reservation; `spawn_blocking` may finish later but cannot install prepared/ready bytes. Keep scan permit until actual blocking work finishes.
4. Adapter validates full prepared identity/nonce/root/epoch and monotonic live token after await, then sends `activate` while its awaited hook is still live. Activation names *only those immutable bytes*, never recaptures. Server rechecks credential/incarnation/target/reservation/TTL and returns an exact activation receipt; public state remains initializing, `acknowledgment:'pending'`.
5. Adapter must receive and validate that activation receipt **while live, before hook returns/model starts**. This is capture-readiness acknowledgment. Only then does it send `receipt` carrying exact receipt ID; public server may promote that same baseline to `ready`/`incomplete` with `acknowledgment:'received'`. Await receipt submission only within remaining 12s; a missing *receipt submission response* is acknowledgment-delivery uncertainty, not permission to recapture. The adapter already received capture readiness. Idempotent receipt resubmission is allowed later, with exact immutable identity; it performs no filesystem capture. Public state stays initializing/unavailable until receipt is received; it cannot infer success from activated state alone.
6. Failure before valid activation receipt latches original attempt failed for that OMP identity; cancel token before aborting fetch, issue best-effort `fail`, never send receipt or activation from late Promise continuations. Server failure tombstone dominates prepared/activated states and prevents resurrection. If failure notification is lost, PREPARED/activated TTL expires unavailable. Even a delayed prepare arriving after a hook failed open cannot become ready: no live adapter activation/receipt exists. A delayed receipt can promote only bytes already acknowledged by the live adapter before first turn, never newly scanned bytes. Wall-clock shifts cannot change this ordering proof.
7. `before_agent_start` checks session identity, monotonic pending state and latched failure/success; it does not start/restart original capture. Unexpected hook/runner 30s fail-open cannot manufacture receipt: every continuation tests token/liveness. Hook callback rejection is caught internally; missing/unloaded/unsupported adapter means no acknowledgment and public unavailable. No claim to block model execution on OMP extension failure.
8. Lost prepare/activation response: no receipt, no ready; preserve failure, no automatic original retry. Lost final receipt response: exact acknowledged baseline may be active or pending delivery, authoritative status reconciles without capture. On reconnect, an existing received record returns `ExistingReceipt`; unknown server epoch or missing record is explicit missing/restart, never automatically prepare an original for an already-started session. New/forked OMP identity gets its own first attempt; root/session switches cannot overwrite records.

A prepared baseline may be incomplete; acknowledged incomplete is useful verified subset, never called complete. Failure after activation but before receipt invalidates attempt. Successful receipt is the only original-ready transition. No filesystem read occurs in activate/receipt/fail. Trust boundary assumes bundled root producer is honest about lifecycle, as existing agent reporting does; protocol is not proof against a malicious bearer holder.

### Origin-qualified status invariants (F2)

Freeze these exact combinations in both Rust/TS valid and invalid vectors; reject cross-origin combinations, not legitimate user fallback:

| Origin/state | acknowledgment | Baseline/coverage requirements |
|---|---|---|
| sessionStart initializing | pending | reservation may have null baseline/coverage, or exact prepared/activated ID; never source-ready |
| sessionStart ready/incomplete | received | nonnull immutable ID/time/coverage; ready iff original capture complete, incomplete iff gaps; only live producer receipt authorizes this transition |
| sessionStart unavailable | pending or received | pending = failed/unacknowledged attempt; received only for already acknowledged original temporarily target-unavailable; baseline fields reflect retained material, no fabricated receipt |
| fromNow initializing | notApplicable | explicit authenticated user intent accepted; capture pending, no producer acknowledgment claim |
| fromNow ready/incomplete/unavailable | notApplicable | ready/incomplete require nonnull immutable ID/time/coverage; same coverage rules; never first-turn/session-start provenance |
| null origin + missing/unavailable | notApplicable | no original baseline ID/time/coverage; explicit reason; capture must not start on read |

No other origin/state/acknowledgment combination is valid; failed originals are unavailable, not null-origin ready; missing with a known old baseline is an error/restart response, not an active Status. From-now may replace missing/failed intent but never clears original failure latch. Add valid fromNow ready/incomplete and invalid fromNow+received/sessionStart-ready+notApplicable/null-ready cases. A producer lookup may adopt fromNow with notApplicable without pretending it acknowledged pre-turn bytes.

## S4. Inventory and immutable baseline fidelity

Capture actual raw regular-file bytes, not HEAD/index hashes, clean/smudge output or normalized newlines. Inventory tracked paths + nonignored untracked paths for selected root; never write user index or invoke stash/reset/commit. Missing tracked files become known-absent only with the bounded directory-entry absence proof below; complete eligible-set membership alone never proves absence. Fresh current inventory is unioned with baseline manifest so staging/committing, ignoring a formerly tracked path or deleting an untracked original cannot erase baseline membership. New paths are added only from eligible current inventory. Unknown/excluded original is not inferred absent; changed-file list includes explicit unknown coverage entries and global gaps, never fabricate add/delete/zero changes.

Reuse `fs::secure_path::read_regular_snapshot` (secure pinned ancestors/no-follow regular file checks), bounded metadata inventory and final revalidation. Record file type/mode/digest/size and before/after identity. Re-enumerate bounded name/type/metadata inventory after capture; drift or changed entries mark original permanently incomplete. Retain verified subset, mark uncertain paths unknown; subsequent comparison cannot repair historical gaps. No atomic repository snapshot or attribution claim. Observe ignore/index metadata changes as inventory drift. Mode-only changes visible with zero line counts where content equal and both sides known. Binary (NUL) and invalid UTF-8 are distinct reasons, null text/counts, honest raw equality if captured. Empty file is present with `content:''`; absent side is `content:null,presence:'absent'`. EOF-newline and CRLF differences remain changes. Non-UTF8 path names excluded with inventory coverage reason `nonUtf8`, never lossy-collided path identity. Symlinks (including in-root), gitlinks, nested roots, devices/FIFOs/sockets never followed/read; explicit unsupported entries/coverage.

### Historical absence proof, not eligible-set nonmembership (F3)

Chosen representation: a private **bounded namespace metadata trie** captured with original inventory, implemented in `session_changes/absence.rs`; no ignored source bytes. For each traversed directory, record exact raw child names/kinds plus a `childrenComplete` certificate only after bounded no-follow enumeration and before/after directory identity/metadata and child-set revalidation agree. Deduplicate namespace paths with manifest paths. Record present ignored files and pruned ignored directories as `excludedAtCapture`/opaque prefix markers only, without opening their content or listing their descendants. `.git`, symlink, nested-root, special and nonUTF8 paths are opaque blocked prefixes; never follow. Directory permission/error/drift/truncation leaves that directory uncertified; preserve previously verified certificates only where ancestry remained valid.

For a path appearing only in current eligible inventory, walk its components against the original trie: (a) an earliest missing child under a certified complete original parent proves the whole path absent then (`originalPresence:absent`, `originalProvenance:absentInVerifiedDirectory`), so a genuinely new current-eligible file can be an added row with counts; (b) a recorded excluded file/prefix, uncertified/missing parent, changed ancestry, or truncated provenance => originalPresence unknown, provenance excludedAtCapture/unproven, change unknown, null original text/counts and absenceUnknown reason. **Never treat complete eligible inventory alone as negative proof.** An originally ignored present `secret.txt` later unignored or force-added is unknown, not an addition; a truly absent sibling under certified root can be known-added. A new descendant of a formerly ignored/pruned directory remains unknown even if it was actually absent; no historical content reconstruction is possible.

Trie shares baseline metadata cap8MiB and10,000 total distinct metadata nodes/manifest paths (no separate unlimited negative index), path4,096 bytes/depth64 and the same10s reservation/two permits. Directory enumeration streams fixed-size entries; no collect-all unbounded sort; stop before path/node/accounting insertion beyond cap. Ignored subtrees are pruned after storing their existing prefix; tracked eligible descendants may be captured directly, but absence proof beneath a pruned prefix stays unknown unless that particular directory was fully enumerated/certified within budget. No capture of ignore-rule history is needed for this presence proof. No ignored metadata trie is returned as a file list; expose only provenance for a path already current-eligible, and aggregate coverage.

`inventoryComplete` describes eligible-set inventory only; `absenceProofComplete` describes namespace certificates for traversed scope, false for blocked/pruned/truncated regions; `provenanceEntries` is accounted metadata-node count. `provenanceLimit`/absenceUnknown remain permanent original coverage gaps; a later refresh cannot repair them. Per-path verified absence may remain useful even when overall coverage incomplete; additions/deletions/countsComplete never imply broader coverage. Revalidate observed child-name/kind sets before publication, so drift invalidates affected proof; this remains non-atomic observed-stability evidence, not transactional absence against arbitrary writers. Required real fixtures: initially ignored file later unignored, initially ignored force-add, excluded subtree later eligible, genuinely absent eligible sibling, truncated parent proof, and mutation while certifying children.

## S5. Comparison revision fidelity

Decision: retain **one immutable current revision's admitted raw bytes + manifest** per record in private storage, not reread mutable working files during detail. Build next candidate privately; only swap if original identity/root/epoch and scan generation still current. Old revision stays usable while candidate builds. Revision is monotonic decimal u64, increments only on successful publication (including incomplete current scan); no partial mix. If new candidate cannot fit, keep old revision, report refresh failure/stale timestamp, not fictitious fresh counts. Detail/list compare exact pinned revision both before and after acquiring a bounded lease; if replaced before response publication return `refreshRequired`. Bytes/counts/list are from same retained revision; later disk edits appear only at next refresh. Pending response to old owner cannot update new owner. Immutable read leases count globally until release; admission reserves candidate + old leased bytes before scan. No unbounded old revision history.

Line counts from raw UTF-8 logical lines without stripping CR/newline changes; compute bounded line-sequence diff with existing git2/in-memory primitives if adequate, not HEAD/index. Bound both line count and algorithm work; unknown counts are null and `countsComplete:false`, including unsupported/missing coverage. Raw equality alone decides unchanged. Monaco may display its own bounded visual diff, but server counts/coverage remain authority. Renames delete+add, no similarity search. Changed-file count is known rows only; coverage gaps are separately visible. Zero rows with incomplete coverage means “No known changes; coverage incomplete”, never “No changes”.

## S6. Lifetime and no silent recapture

Normal OMP exit, status credential revocation, semantic lease expiry, browser close/reload/reconnect/profile-generation replacement **do not delete** original. Server record preserves terminal incarnation/session selector for exited terminals even when semantic row disappears. Status query can retrieve a bounded retained-session selector via `/status` with session omitted only for listing identities: returns `{version:1,serverEpoch,terminalIncarnation,sessions:[{ompSessionId,rootId,baselineId,origin,state,capturedAtMs}]}`; max32 entries, no source. Exact session is mandatory for all other operations. UI selects current semantic session when available, otherwise explicit retained session, never silently switches owner.

`manager.rs:2866-2918` existing 60s dead-session TTL eventually invokes actual `remove_with_expected`: this is terminal metadata removal and releases its baseline. **Do not alter/pin/extend existing terminal retention or introduce keepalive flags.** Normal process exit/status retirement preserves baseline while terminal metadata remains retained; expiry/removal becomes explicit missing/unavailable, never replacement capture. Explicit `remove_with_expected`, incarnation replacement publication, durable workspace destruction/dispose and server shutdown release records/storage. `kill_internal_impl:2929-2963` keeps dead metadata: retains baseline until actual removal. `reader_thread:3453-3454` only removes status: retains baseline. `evict_identity_after_durable_removal:2623-2666` and `dispose_internal` destroy identity: release exact identity after durable success. Failed durable removal keeps record. Replacement invalidates old pending scans and old records only when new incarnation wins; stale old cleanup cannot remove new records. Workspace switches that actually destroy terminals release; target unavailable alone returns unavailable, not recapture. Server restart stores nothing; restored terminal scrollback is not a baseline. Never use status `remove_terminal` as generic deletion hook. After removal, public status returns typed terminalMissing/baselineMissing as applicable; no unbounded archive of removal tombstones.

## S7. Settled refresh and UI invalidation

Use existing 250ms `handleSettledEnd`, for every completed/blocked/error/aborted/unknown settled outcome with exact `(session,baseline,turnId)`; continuing, retrying, compaction do not emit settled work. Dedup by last accepted turn ID plus bounded 64-entry recent ID set per record (IDs <=200 bytes); no lifetime-unbounded turn history. Same in-flight turn returns duplicate; failed/busy refresh leaves dirty hint and next open/manual refresh reconciles. One in-flight scan per identity; at most one dirty latest-turn marker coalesces while busy, no unbounded queue or new timer. After current scan releases, process at most that marker within a fresh bounded operation; subsequent pressure remains dirty for next explicit control/open, not a polling scheduler.

Existing adapter semantic `TurnOutcome` is `ended|interrupted|error|unknown` (`omp-agent-status.ts:22`), not the new private settled enum. Explicit control-only mapping: blocked state => blocked; otherwise error => error, interrupted => aborted, ended with idle state => completed, otherwise unknown. Keep public semantic WS enum/schema unchanged. Every mapped outcome can include edits; no success inference.

Producer settled control refreshes retained current revision even while panel hidden when admission available. Existing semantic row turn/state changes are browser invalidation hints only, not readiness proof or generic attentionRevision. While panel visible, invalidate/refetch status then refresh/list on settled identity change; coalesce duplicate in-flight requests. Hidden panel does no source fetching, polling or Monaco mounting. On open/reconnect/visibility return, authoritative status + bounded refresh regardless of missed status frames. Manual refresh supported for external editors. Never infer attribution/task success from changed files or completion status.

### Private lookup/adoption of explicit from-now (Q1)

A failed-original adapter keeps two independent fields: immutable `originalAttempt` success/failure latch and mutable metadata-only `activeReview` pointer. Blocking I/O is not forcibly cancellable by Tokio timeout. Use cancellation tokens/reservation generations and cooperative checks between inventory/files/diff blocks; invalidate deadline on async timeout and refuse publication later. Hold permits and reservations until actual task exit; genuinely stuck I/O can exhaust two permits and tracking becomes busy/unavailable, terminal remains usable. No unbounded detached retry jobs. Bounded lazy expiry and existing collector lease tick reclaim prepared reservations; original records have no TTL. Receipt/failure validation is cheap, never waits for blocking permit. Ensure failed metadata/cancel tombstones also obey32-record bound; capacity-refused sessions stay adapter-latched unavailable without allocating unbounded server tombstones.
