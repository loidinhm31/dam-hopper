## Key Insights
- `connections.ts` creates `WsTransport` with immutable profile URL/token/generation, already fences owner via `isCurrentConnection`; `destroy()` currently aborts REST controllers, not an independently owned response reader. Token rotation callback checks `entry.intent` **after** `disconnectProfile` sets false.
- `transport.ts` exposes `invoke(...,{signal})`; browser `WsTransport.invoke` already binds external abort and narrowly maps REST authentication codes to `onDrop`. `use-sse.ts` is an existing **WS bridge**, not an SSE parser. `getApi(owner)` routes exact bound client; ambient transport is unsuitable.
- Producer's data is a full `{snapshot,metrics}` pair; immediately preceding matching status is required before **each** data event. A periodic status may describe newer server revision while an older frame remains displayed; 200/heartbeat/status alone cannot establish live or fresh.

## Requirements
- `GET /api/system/resources/v1/events`; captured bearer header, `Accept: text/event-stream`, `credentials: 'omit'`, `cache: 'no-store'`, `redirect: 'error'`; no cookies, token URL, Last-Event-ID, replay, per-observer socket, new collector, new client field or new cadence.
- Native only when actual owner-bound transport can supply cancellable authenticated streaming; otherwise exact bound REST. Do not invoke browser-global fetch as native fallback.
- Streaming UTF-8 parser; byte/event/framing caps data 256 KiB, status/error 4 KiB. Strict full DTO/status validation and safe rejection **before** cache writes; no parser dependency.
- Preserve seven prescribed modes `STOPPED/STARTING/LIVE/RETRY_WAIT/REST_ONLY/AUTH_BLOCKED/PAUSED`, attempt and source-generation fencing, six total attempts at most before exhaustion; no WS recreation for SSE faults.

## Architecture
- `connections.ts` owns registration/disposal at connection lifecycle boundaries. A registry indexed by `connectionKey(owner)` **and QC object identity** tracks interested observer counts; concurrent fleet+detail on same QC share one coordinator; repeated app roots registering same QC are reference-counted. No stream without connected/current owner, registered QC, visible document and positive interest. Registry QC attachment happens in phase 04; phase 03 supports it without ambient QC fallback.
- Transport private/authenticated fetch → bounded parser (named events plus non-dispatched comment marker for adjacency) → DTO decoder → coordinator. The transport owns fetch controller **and reader**, provides a single idempotent close/cancel handle; coordinator owns retry timers, visibility/pagehide listeners, attempt/source fences and mode subscriptions. All callbacks check captured owner, QC, current attempt, sourceGeneration before acting. No profileId in HTTP target.
- Public feature-local API for phase 04: `registerHostResourceInterest(owner: ConnectionRef, qc: QueryClient, kind: 'fleet'|'detailSnapshot'|'detailMetrics'): () => void`; `getHostResourceSource(owner,qc): {mode: SourceMode; sourceGeneration: number; switching: boolean; freshness: ProjectionFreshness}`; `subscribeHostResourceSource(owner,qc,listener): () => void`; `captureResourceSource(owner,qc): number`; `isResourceSourceCurrent(owner,qc,sourceGeneration): boolean`; `canUseResourceRest(owner,qc): boolean`. The shared REST predicate means current connected owner + registered exact QC + visible interested owner + mode `STARTING|RETRY_WAIT|REST_ONLY` + `!switching` + no `AUTH_BLOCKED` latch; use it for snapshot/metrics requests and WS resource writes/invalidation/catch-up, alongside sourceGeneration checks on completions. These are **local** observer categories and state, not wire fields or additional source modes; `detailMetrics` exists only while detail requests metrics. `ProjectionFreshness` records server ages/null, local monotonic receipt, TTL, epoch/revision and section availability; `LIVE` means data authority, not fresh sampler.
- One phase-04-facing handoff `switchToHostResourceFrame(owner,qc,sourceGeneration,decodedFrame,matchedStatus)` (coordinator + query integration owner): validate attempt, synchronously publish `switching:true` and increment sourceGeneration **before the first await** → cancel exact two queries → revalidate captured attempt/owner/QC/new fence → batch two owner-key writes → publish LIVE and `switching:false` in that turn. While switching, no new snapshot/metrics REST or WS resource write/invalidation/catch-up, even though mode remains STARTING or fallback. On canceled/failed handoff, only the still-current switching attempt may fence/clear its own flag and publish a permitted fallback/blocked/paused state; old-attempt finally callbacks cannot clear a newer attempt's flag. No production LIVE until phase 04 wires actual queries; on leave-LIVE fence before enabling REST and coalesce one catch-up per owner/QC.

## Implementation Steps
1. **03-T transport, independently executable.** Owner: Transport worker. Paths (2): `packages/ui/src/api/ws-transport.ts`, `packages/ui/src/api/ws-transport.test.ts`. Input: captured `{baseUrl,profileId,generation,authToken}` from constructor. Output discriminant `openHostResourceEvents(signal: AbortSignal): Promise< {kind:'stream'; response:Response; reader:ReadableStreamDefaultReader<Uint8Array>; close():void} | {kind:'finite'; status:number; code:string|null; retryAfter:string|null; close():void} | {kind:'unsupported'; close():void} >` plus feature-local capability predicate on the **bound instance**, not ambient/global transport. Fetch only fixed relative route; `buildAuthHeaders()` uses captured token. Transport owns fetch controller **and the only body reader, including the finite path**: read at most 4 KiB of finite JSON bytes plus one-byte overflow detection, bounded decode/parse `{code,error}` once; never expose raw finite body or let coordinator re-read it. Preserve finite status and raw `Retry-After` header, not untrusted error text; absent/invalid code is null. Acquire and own stream reader, register both paths in transport lifetime, link caller abort (including already aborted), cancel reader + abort fetch on close/destroy, release listener/lock in finally; do **not** reuse `invoke` JSON/text decoder or its default 30s timeout. A successful SSE response lacking an actual owner-bound readable/cancellable streaming body returns `unsupported` with no nullable stream reader; a readable body with malformed/missing SSE content type is a transient bad-protocol error, **not** native unsupported. Bound native capability failure may return `unsupported` without issuing I/O. Coordinator alone maps unsupported to generation-sticky REST_ONLY unless auth latch already blocks REST. Transport alone notifies `onDrop` for finite 401+`MFA_REQUIRED`→4403 or 401+`SESSION_EXPIRED|SESSION_REVOKED|AUTH_REQUIRED`→4401 (once per response). Unknown 401/403 stays terminal SSE-only; `AUTH_UNAVAILABLE` never drops WS. Acceptance: bound target/header, 4 KiB+1 finite limit, abort awaiting headers/reader.read, destroy teardown, narrow auth notification exactly once, unsupported vs malformed-content-type classification. Non-goal: retries, host cache, generic transport API. Handoff: discriminated result/close/auth notification to 03-I.
   Output error handoff: transport exposes `reportHostResourceErrorControl(code: string): void` to coordinator **only after** bounded post-header `host-resources-error` decoding; transport alone owns recognized-auth notification, deduplicated per attempt against finite classification, only while captured owner is current (`MFA_REQUIRED`→4403, `AUTH_REQUIRED`→4401). Coordinator never invokes `onDrop` or reparses a finite body; it classifies `finite.status/code/retryAfter` before generic 5xx scheduling. No SSE errors use generic REST `invoke`/WS disconnect semantics.
2. **03-P byte parser, independently executable.** Owner: Parser worker. Paths (2): `packages/ui/src/api/host-resource-sse-parser.ts` [new], `packages/ui/src/api/host-resource-sse-parser.test.ts` [new]. Input: `push(chunk: Uint8Array): ParsedPiece[]`, `finish(): void` (discard unterminated EOF); output named `{event:'host-resources'|'host-resources-status'|'host-resources-error',data:string}` or a comment marker with no cache effect, solely so coordinator can detect an interleaved heartbeat before paired data. One streaming fatal `TextDecoder` preserving split multibyte UTF-8; recognize LF/CR/CRLF even across chunks, SSE `data:` multiline join `\n`, optional one space after colon, blank dispatch, comment ignored as event. Bound **raw complete event bytes including event lines and framing** before retaining; data ≤262144, controls ≤4096; until event type known enforce provisional data cap then enforce control cap retrospectively; reject unknown/missing event names and overlong comment/line without unbounded buffering. Track byte activity before parsing even for comments; one chunk may contain many legal events, not one chunk-sized cap. EOF mid-event discarded and treated transient upstream; malformed UTF-8/protocol raises bounded failure. Acceptance: split CRLF, multibyte, multiline, comments, exact boundary and +1, many events/chunk, huge prefix before `event:`; no JSON decoding here. Non-goal: retry/cache. Handoff: parsed pieces to 03-I.
3. **03-D schema/freshness decoder, independently executable.** Owner: Decoder worker. Paths (2): `packages/ui/src/api/host-resource-sse-codec.ts` [new], `packages/ui/src/api/host-resource-sse-codec.test.ts` [new]. Input: parser's named `{event,data}`. Output `decodeHostResourceEvent(event): DataFrame | StatusFrame | StreamError` with data `{schemaVersion:1, serverEpoch, revision:string, snapshot:HostResourceSnapshotV1, metrics:HostMetrics, lightSampleMs}` and status `{serverEpoch,revision,snapshotAgeMs:number|null,metricsAgeMs:number|null,freshnessTtlMs}`. Require exact top-level data keys, UUID epoch, canonical decimal unsigned 64-bit revision validated using `BigInt` (never Number for sequencing), actual clamped light interval, nonnegative finite integer ages/TTL; validate **existing** nested snapshot/metrics shapes including availability discriminants, relevant section arrays, alert `currentAlerts`, `sampledAt`, numeric and enum ranges, not merely schemaVersion. Optional existing additive fields stay optional; no fabricated precision or JSON schema package. Error controls allow only the architecture codes/safe bounded text; reject malformed or oversized before mutation. Provide monotonic-age helper: `age = serverAge + max(0, performance.now()-receivedAt)`, null remains unknown; same-revision updates may only age/invalidate, never reset observations on receipt; respect explicit section availability. Acceptance: malformed snapshots/metrics/ages, >u64/leading zeros/Number precision loss, degraded flags, unknown code all rejected. Non-goal: cache writes, extra wire fields. Handoff: typed frames to 03-I.
4. **03-I ownership integrator (single named owner of shared files).** Owner: **Frontend integration owner**. Paths (5): `packages/ui/src/api/host-resource-stream-coordinator.ts` [new], `packages/ui/src/api/host-resource-stream-coordinator.test.ts` [new], `packages/ui/src/api/connections.ts`, `packages/ui/src/api/connections.test.ts`, `packages/ui/src/api/connections-mfa.test.tsx`. Inputs: discriminated 03-T result, 03-P/D outputs, `ConnectionRef`, exact QueryClient, connected entry. Implement no consumer/hidden/unsupported STOPPED/PAUSED/REST_ONLY with cached last known; STARTING REST sole writer only when `canUseResourceRest` and `!switching`, until **valid paired full data**, never status/comment/200. Per attempt keep immediately preceding matching pre-data status, clear on interleaved control; a newer periodic status cannot freshen old consumed data; reject data without matching adjacent status. BigInt sequencing: reject same-epoch revisions older than last consumed even on reconnect; allow **equal** revision once as initial full baseline of a new current attempt with fresh adjacent status (then dedupe duplicate/backward frames within that attempt); new epoch full baseline only within current attempt. Fence sourceGeneration/attempt on drop/replacement/reset/disconnect/endpoint/token removal, pagehide/hidden; visible/pageshow resumes current owner with remaining budget. Registry refcounts same-QC roots, distinct-QC isolation; never open second stream for fleet+detail or offline auto-connect. Token callback snapshots reconnect intent before `disconnectProfile`, reconnects new generation only with new token and intended profile. Acceptance: stale owners/attempts/timers cannot write/reopen; equal-revision hidden/resume baseline succeeds; two observers one socket. Non-goal: alter WS retry/host actions. Handoff: source snapshot/REST predicate and atomic paired switch to phase 04; no production LIVE until wired.
   Integration interfaces: replace the unused `setConnectionRegistryQueryClient` setter with `registerConnectionRegistryQueryClient(qc: QueryClient): () => void`. Returned disposer decrements **that QC's** refcount and removes it only at zero; a stale root's disposer must not delete a newer/different QC. A parsed comment/heartbeat or any other event after a pre-data status clears adjacency (comments still have no cache event); a newer periodic status may be retained as informational only until a matching **later validated data** arrives.
5. **03-I retry and exit algorithm (same owner/paths as 03-I; not a parallel file edit).** Arm 10 s deadline for first **data** from attempt start and 45 s byte-idle since last actual body byte; stop both on abort. Transient network/EOF/429/other 5xx/bad protocol/timeouts → RETRY_WAIT, max **five retries** after first attempt with positive jitter base 1/2/4/8/16 s (≤30 s); 429 `retryAfter` bounded ≤60 s. Budget resets only after 60 s stable **with advancing revisions**, not heartbeat/rerender/visibility. Finite `status/code/retryAfter` (already bounded/parsed by 03-T) or decoded post-header control: 404/405, coded HTTP 503 `FRAME_TOO_LARGE`/control and unsupported native → generation-sticky REST_ONLY; unknown 401/403 → terminal REST_ONLY without token/WS change; `AUTH_UNAVAILABLE` → AUTH_BLOCKED with snapshot **and metrics** in-flight REST fenced/canceled, including from STARTING, and history REST disabled while capped SSE retries proceed. An auth-blocked latch survives retry backoff, retry fetch, hidden/resume and status-only/heartbeat: when visible mode stays `AUTH_BLOCKED` throughout retry fetch (never expose `STARTING` while latched); when hidden mode is `PAUSED` but latch persists and resumes to `AUTH_BLOCKED`. `canUseResourceRest` remains false throughout; only valid authenticated paired full data of the current attempt (after atomic LIVE handoff), or explicit new connection generation, clears latch. Exhaustion stays blocked until new generation. Recognized 401 auth/control uses 03-T's sole `onDrop` notification. EXIT from LIVE fences callbacks, bumps sourceGeneration, cancels reader/timers before REST enable/pause; one catch-up only when shared predicate permits. Acceptance: no duplicate timers, six attempts maximum, coded 503 wins over generic 5xx, 429 bounded delay, STARTING auth failure aborts both in-flight REST requests; no blocked REST on retry/resume. Non-goal: query cadence (phase 04).
   Error precedence: current-owner/attempt cancellation first; recognized MFA/session auth notification from 03-T; `AUTH_UNAVAILABLE` sets persistent latch; coded `FRAME_TOO_LARGE` and `kind:'unsupported'` stay REST_ONLY **unless already latched, in which case keep AUTH_BLOCKED until a new generation**; 404/405 and unknown 401/403 terminal SSE-only but never unlock existing auth block; malformed success content type and other 429/5xx/network/EOF/protocol/timeouts consume retry budget. The coordinator receives the **finite discriminant**, not `response.body`; no second finite parser. If current switch cancellation fails, release `switching` only after fencing both query sources and checking switch token; old-attempt cleanup must never release a new switch. Bound one retry timer to remaining generation budget.

## Risk Assessment
- Browser/native streaming support varies: detect actual owner-bound response body/cancel ability; unsupported native retains REST. Slow readers may retain up to event cap per connection; abort on owner loss. Byte-limit counted before JSON to avoid large hostile frames; finite error body capped.
- Status racing data: require adjacent matching pre-data status, keep age separately from transport liveness. REST overwrite and UI consumers remain phase-04 gating; never report phase 03 alone as end-to-end SSE.

## Security Considerations
- Never export profile tokens or retain them in parser/coordinator logs; transport uses captured bearer, never ambient/global fetch or token query params. Unknown 401/403 cannot invoke `onDrop` or clear credentials. `AUTH_UNAVAILABLE` blocks REST metrics/snapshot/history even on retry or resume until a current authenticated paired full-data handoff or explicit new connection generation; retry independently with cap. Reject malformed DTO and unauthenticated cross-profile callbacks before any UI mutation.
