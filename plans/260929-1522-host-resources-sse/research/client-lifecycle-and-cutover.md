# Client lifecycle and cutover research

## Current ownership and request path
- `ConnectionRef` is `{profileId, generation}`; snapshots expose the owner, status, intent and server URL (`packages/ui/src/api/connections.ts#L90-L118`). `captureConnection` only returns a connected owner; `isCurrentConnection` fences both profile and generation (`#L642-L657`). Use that owner as the local stream identity: one module/runtime coordinator entry per `profileId@generation`, never the active profile alone.
- Connect resolves the configured profile URL and token by profile ID, checks URL/protocol and same-origin support, validates auth/workbench protocol, then builds `WsTransport` with immutable base URL/profile/token/generation (`connections.ts#L382-L455`, `#L447-L529`, `#L533-L545`). `WsTransport` binds the token for its lifetime and has bearer-header construction (`packages/ui/src/api/ws-transport.ts#L1527-L1536`, `#L1757-L1789`). Its REST helper uses `fetch`; its WebSocket uses `?token=` (`ws-transport.ts#L3-L7`, `#L1953-L1958`). Do not copy the WebSocket query-token pattern to SSE; authenticated SSE needs an explicit fetch-based transport using `Authorization: Bearer`, not an assumed `EventSource` header feature.
- The resource REST call is `getBoundApiClient(target.owner).system.resourceSnapshot()` at `packages/ui/src/hooks/use-multi-host-resources.ts#L96-L113`; the same owner-scoped cache key is `profileQueryKey(owner, "system", "resource-snapshot")` (`#L100`). This client seam does not name the HTTP route or SSE event schema. Do not invent a route or wire format; backend contract/route is an integration prerequisite.
- No public connection API exposes the profile token or URL as a pair. Token access in `connections.ts` is a private wrapper (`#L23-L46`); `ConnectionSnapshot.serverUrl` is public, but no token (`#L90-L99`). Prefer create/own the stream from the connection lifecycle, where the token is already available, rather than exporting a general token getter or using active-profile defaults.

## Lifecycle, auth, abort and existing push paths
- Connect is coalesced per profile (`connectProfile`, `#L351-L380`). On replacement/drop/disconnect/removal/reset, the entry invalidates, increments generation, unsubscribes and destroys its transport (`#L271-L289`, `#L428-L445`, `#L611-L640`, `#L735-L788`). Add stream abort/disposal to those same owner transitions; late frames must pass `isCurrentConnection(owner)` before cache writes. Token/profile changes are observed at `#L841-L879`; capture `intent` before `disconnectProfile` if reconnecting there: `disconnectProfile` sets it false (`#L619-L624`), so the subsequent `if (entry.intent)` in the change callback cannot preserve the previous intent (`#L863-L866`). This existing seam needs correction for reliable token rotation.
- REST auth policy is narrower than “any 401”: `WsTransport` maps only 401 with `MFA_REQUIRED` to drop code 4403, and 401 with `SESSION_EXPIRED`, `SESSION_REVOKED`, or `AUTH_REQUIRED` to 4401; otherwise it throws `ApiRequestError` without that auth drop (`ws-transport.ts#L2596-L2625`). Connection drop makes MFA required terminal; AUTH_REQUIRED clears that profile token and makes login required; other drops retry only when intent remains (`connections.ts#L290-L330`). Reuse the exact recognized codes for SSE; never clear credentials or force login on an unrecognized status. The current REST request tracks `AbortController`s and `destroy()` aborts them (`ws-transport.ts#L1536`, `#L1908-L1919`, `#L2559-L2560`, `#L2653-L2654`). SSE needs its own controller/body-reader cancellation tied to the same owner; transport destruction will not cancel a separately created fetch unless explicitly wired.
- Existing retry is a connection policy: 1s initial, doubles to 30s (`connections.ts#L120-L125`, `#L251-L269`), with auth outcomes stopping generic reconnect (`#L290-L316`). Keep SSE retry independent; do not call `connectProfile` for a stream fault or create a second WebSocket.
- `use-sse.ts` is currently a WS event bridge/listener bus, not an SSE client: `subscribeIpc` routes global or profile listeners (`packages/ui/src/hooks/use-sse.ts#L115-L175`); `installTransportBridge(owner, transport, qc)` subscribes to WS channels and dispatches with owner (`#L435-L445`). Existing channels include `host:alertChanged` and `host:alertsInvalidated` (`#L184-L203`). Owner-scoped handling applies alert deltas and invalidates owner-scoped snapshot/alert keys (`#L474-L498`); `useIpc` also installs active/global alert handling (`#L660-L672`). Preserve these validators and alert presentation paths. If SSE carries alert events too, choose one source per host event type (or define protocol IDs for dedupe); do not subscribe both feeds and rely on timestamps to deduplicate.
- Multi-profile fleet chooses each connected/auto-connect profile, derives owner, and checks current generation after REST response (`use-multi-host-resources.ts#L66-L113`). Keep this owner routing and `profileQueryKey`; never use `getApiClientForProfile()` without the profile ID or global cache keys for per-profile SSE data. Native query routing currently goes through `getBoundApiClient(owner)`; keep it intact and enable SSE only for a platform/transport with a real supported fetch stream. Do not replace native scope routing with browser-global fetch.

## Recommended state machine and cutover
1. **STOPPED** until an owner is connected and current. One coordinator owned by `connections.ts`/a transport module, not React hook effects; `use-sse.ts` only fans validated events to existing subscribers. This avoids one stream per fleet/detail observer. Use the captured profile URL/token/generation; profile ID stays local, not a backend target.
2. **CONNECTING → LIVE** only after HTTP success and the frozen SSE contract’s valid initial/ready event. Start with existing REST as sole snapshot writer. On LIVE, populate the existing `profileQueryKey(owner, "system", "resource-snapshot")` cache from SSE and stop *all* observers’ snapshot polling, including fleet 15s and detail 1s. Keeping the current key avoids split fleet/detail state; changing only this hook is insufficient if another observer still polls. The REST option/query path must consume the same per-owner source mode.
3. **PAUSED** on document hidden/pagehide: abort the stream, retain cache, do not disconnect the profile/WebSocket. On visible/pageshow, reopen only if owner is still current and do a REST catch-up before accepting live writes. No page-lifecycle seam appears in these target paths; implement it once in the coordinator, not per hook.
4. **RETRY** transient network/stream-close/429/5xx failures with one in-flight attempt and capped exponential delays; cap attempts (recommend five retries, delays capped at 30s), then enter **REST_FALLBACK** for this owner generation. Re-enable existing polling and invalidate once on transition so cached data catches up. Retry again only on a new owner generation or explicit coordinator restart; no tight loops and no subscriber-driven polling.
5. **COMPAT_FALLBACK** on an explicitly unsupported endpoint/protocol response (e.g. route/method not available per frozen backend contract): stop SSE and use existing REST. **AUTH_BLOCKED** on recognized MFA/session auth codes: invoke the existing profile auth transition and abort; unrecognized 401/403 is non-retryable for SSE, must not clear tokens, and leaves normal REST error handling intact. Malformed event payload: reject it and do not mutate cache; treat repeated stream failure under the bounded retry rule.
6. Every transition out of LIVE disables SSE writes before enabling REST; every transition into LIVE waits for handshake/catch-up before disabling polling. On abort/drop/profile removal/reset, unregister all listeners and reject late generation frames. Hide/show and reconnect must be idempotent. Keep existing WS alert handling when SSE does not carry alert events; avoid parallel duplicate host-alert subscriptions if it does.

## Host-load considerations and change map
- Baseline supplied for this assignment: monitor owns cached collection (5s light, 15s process, 60s PSS; bounded jitter; 150ms process deadline; snapshot wait 500ms; blocking syscalls may outlive timeout). SSE must read/publish the already-collected snapshot; never trigger collection per subscriber. A single stream per connected profile/runtime bounds duplicate sockets and serialization; hidden-tab pause and shared lifecycle prevent React observer count from amplifying host or network work.
- `connections.ts`: own coordinator start/stop beside connect success, `handleDrop`, token rotation, disconnect/remove/reset; preserve intent during token rotation; generation-fence every callback.
- `ws-transport.ts`: expose/reuse only the minimal profile-bound authenticated streaming/response-classification seam if implementation requires it; reuse active abort cleanup or explicitly register stream controller. Do not put host sampling in this generic transport.
- `use-sse.ts`: keep current IPC bus/validation; add owner-aware SSE event ingress and reuse existing host alert invalidation/apply logic. Avoid duplicate WS/SSE host event processing.
- `use-multi-host-resources.ts` plus the detail snapshot observer: retain the exact shared owner query key; make REST polling mode depend on the same per-owner SSE coordinator state in both observers.
