## Key Insights
- `router.rs` currently applies `require_auth` to the entire protected router and applies `build_cors` outermost only when configured. `CorsLayer` makes preflight/browser CORS headers but **does not reject disallowed GET execution**. Existing `AppState::origin_is_allowed` checks exact allowlist or same-origin host and rejects multiple Origins; an absent Origin must be allowed only with bearer verification (or explicit `--no-auth`). Axum route layers wrap in **reverse** order of addition; targeted GET/OPTIONS route tests must prove actual order.
- `require_auth` currently runs `Next.run(request)` after `evaluate_claims`, so placing `timeout` around that middleware also times downstream first-frame/serialization and mislabels delays `AUTH_UNAVAILABLE`. Factor its authentication/policy stage into one shared helper, reusing existing decisions; wrap **only** that helper's future in the feature's 2 s deadline, then run Next outside. `AuthService::evaluate_claims` reads session+user (2N/5 DB reads/s; 32 →12.8/s). The actor omits `iat`; retain complete verified `AuthClaims` for independent policy checks. Bearer middleware's plugin wording must not leak into SSE.
- Installed Axum 0.8.8 `serve::Listener` supports custom IO/Addr, but direct `Connected<IncomingStream<'_, ForceCloseListener>> for SocketAddr` is **not legal** under Rust orphan rules. Installed `connect_info.rs` already implements generic `Connected<IncomingStream<'_, TapIo<L,F>>> for L::Addr`; use `ListenerExt::tap_io` zero-work closure around custom listener to preserve peer address. Axum spawns connection tasks and awaits all after graceful shutdown; dropping outer serve or cancelling SSE bodies cannot bound blocked HTTP drain. `main.rs` awaits serve before host-monitor and PTY cleanup.

## Requirements
- Route feature-local path, no profile ID in wire target. GET `Accept: text/event-stream` (server must not require it for bearer CLI), `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: private, no-store, no-transform`, `X-Accel-Buffering: no`; no HTTP/2-invalid `Connection` header or transparent compression/buffering. No cookie SSE auth except explicit no-auth/dev actor, no query token, event ID, replay, sampling in reader, or legacy sampler modification.
- GET order: outer configured CORS/preflight → global permit (32, before DB) → explicit present-Origin admission → feature 2 s authentication **stage only** → bearer mechanism → per-subject slot (4, `dev-user` in no-auth) → handler. Configured allowed-origin preflight is handled by outer CorsLayer with expected headers; empty allowed-origins installs **no** CorsLayer, ordinary GET-only OPTIONS is **405**; neither OPTIONS case reads auth or reserves a permit. Global/per-subject 429 JSON `{code:"HOST_RESOURCE_STREAM_LIMIT",error:"..."}` with `Retry-After: 30`; Origin denial 403 JSON; 2 s expiry exact **503** `{ "code": "AUTH_UNAVAILABLE", "error": "Authentication backend unavailable" }`. Completed auth decisions retain existing finite status/code; feature must never add raw DB diagnostics. Error and timeout drop global reservation.
- Initial status immediately after admitted headers, latest full pair, then pre-data matching status immediately before every selected data with no control interleaving. Periodic at least every 15 s uses `HostResourcePublisher::current_status_basis()` (**metadata-only**, no `read_stream_pair()`/per-reader full projection clone); keepalive `: keepalive\n\n` within 15 s otherwise. Status ages/TTL from immutable selected frame for data; periodic may name newer revision. Check lease after each await/before each yield; queued wire/proxy bytes cannot be recalled.
- Before headers, finite JSON for oversize **HTTP 503 `FRAME_TOO_LARGE`** distinct from generic 5xx; recheck latest pair/revision before deciding. Post-header best-effort bounded `host-resources-error` control `{code: MFA_REQUIRED|AUTH_REQUIRED|AUTH_UNAVAILABLE|FRAME_TOO_LARGE,error:"safe reason"}`, then revoke eligibility/close if writable. Any other unexpected publisher error must fail closed without unbounded output. Paired status/data use phase-01 `encode_control_event` ≤4 KiB and shared pre-encoded frame ≤256 KiB. No snapshot serialization per body.
- Body retains leases; supervisor **not** polled by body. Verified `AuthClaims` (`v,sub,sid,authVersion,credentialVersion,iat,exp`) retained without bearer material; every 5 s `evaluate_claims(&claims)` with 2 s timeout, fail closed on unavailable/invalid/MFA. Independent timer revokes at earliest actor MFA due/absolute expiry/claims expiry even if body unpolled; recheck valid lease immediately before any yield. On revocation set no-emit state first, best-effort error/close later; Drop cancels supervisor and releases limits once. Shutdown revokes/ends all feature streams/publisher before HTTP drain, bounds cleanup.

## Architecture

- `server/src/api/auth.rs`: extract `pub(crate) async fn authenticate_request(state: &AppState, jar: &CookieJar, request: Request) -> Result<Request, Response>` from existing `require_auth` and keep its single JWT decode/policy evaluation/decision mapping. Only successful signed auth inserts `VerifiedAuthClaims(AuthClaims)` with actor/mechanism; no token retained, dev actor intentionally has no signed claims. Existing `require_auth` calls helper then `Next.run` **outside** helper, preserving REST behavior. Feature-only `authenticate_stream_request` calls `timeout(Duration::from_secs(2), authenticate_request(...))`, returns exact safe 503 AUTH_UNAVAILABLE on expiry, then calls `Next.run` outside timeout. Never duplicate auth reads or wrap `require_auth`'s Next/publisher work.
- `server/src/api/resource_events.rs` (new): handler can take `Request` to access extensions plus `State`. `HostResourceAdmission` owns 32-slot semaphore and `Mutex<HashMap<String,usize>>` (max 4/verified subject). Outer layer inserts clone-safe `#[derive(Clone)] AdmissionPermit(Arc<Mutex<Option<OwnedSemaphorePermit>>>)`; `http::Extensions::insert<T>` requires Clone+Send+Sync, so raw `OwnedSemaphorePermit` is invalid. Only `take()` moves the **one** owned permit to `BodyLease` held by `Body::from_stream`; cloned extensions share Option, double take returns None; error/timeout/request Drop releases unused permit, Body Drop returns owned permit/subject and removes zero-count entries. Never release slot at handler return.
- `HostResourceEvents` feature runtime lives in `resource_events.rs`, stored in `AppState`; `.start()` starts publisher once after monitor; `.revoke_emission()` synchronously rejects admission and flips no-emit on all bodies. Async `.shutdown()` uses one shared absolute **≤2 s feature-cleanup budget measured from OS signal onset** for publisher shutdown and tracked supervisor/task cleanup; abort/reap laggards by that same deadline. No body-owned supervision timer, detached uncapped tasks or DB read per event. Route subtree merges beside protected REST; root configured CORS outermost. Reverse feature layer order: subject → bearer → feature auth helper → Origin → global permit; test constructed router.
- `server/src/http_shutdown.rs` (new binary module): `ForceCloseListener { listener: TcpListener, force: CancellationToken }` implements Axum 0.8.8 `serve::Listener` with `type Io = ForceCloseIo`, `type Addr = SocketAddr`, accepted `(wrapped TcpStream, peer SocketAddr)` and delegated `local_addr`. **No custom Connected impl**; `main.rs` imports `axum::serve::ListenerExt` and passes `ForceCloseListener.tap_io(|_: &mut ForceCloseIo| {})` (purposeful zero-work **type adapter**, not missing implementation). Axum's installed generic `Connected<IncomingStream<'_, TapIo<L,F>>> for L::Addr` yields original peer `SocketAddr`; retain `into_make_service_with_connect_info::<SocketAddr>()`. `ForceCloseIo` stores stream, cloned global token and two **independently pinned** owned cancellation futures (`read_cancelled`, `write_cancelled`) from token clones. Check token `is_cancelled()` then poll read waiter in `poll_read`, write waiter in `poll_write`/`poll_flush`/`poll_shutdown`; on force return `ConnectionAborted`, else delegate to pinned TcpStream. Separate read/write waiters preserve both wakers on split upgraded WS. No per-I/O spawned task or new dependency. Test peer ConnectInfo, blocked read/write/flush/shutdown wake and split WS halves.
- `main.rs` declares `mod http_shutdown;`, wraps bound listener through `tap_io` adapter above and retains `router.into_make_service_with_connect_info::<SocketAddr>()`. On OS signal start independent HTTP force timer for `Instant::now()+10 s` immediately, synchronously revoke feature emissions, and shut down publisher/tracked feature tasks against the same signal-time absolute ≤2 s cleanup deadline (abort/reap laggards before graceful signal resolves; no outer timeout dropping shutdown before abort). Axum then stops accepting and drains until global token force wakes blocked read/write sides, including WS; await `serve` before unchanged later cleanup. Dropping outer serve cannot stop Axum connection tasks; HTTP drain bounded at signal+10 s with scheduler tolerance, **not** total process termination if collector or later cleanup blocks.
- Supervisor binds retained signed claims to verified actor subject/session/version/deadline at admission and stores only nonsecret claims; dev actor needs no DB supervisor but obeys shutdown/body lease. For authenticated stream, start independent `tokio::select!` loop over cancellation, 5 s persisted check+2 s timeout and pinned nearest deadline; use `state.auth_service.clock()` for policy clock and compute monotonic sleep at admission to avoid wall-clock jumps granting more time. Map `MfaRequired` → `MFA_REQUIRED`, `Unavailable`/timeout → `AUTH_UNAVAILABLE`, `FullLoginRequired` → `AUTH_REQUIRED`, deadline appropriately; use bounded fixed safe reasons, never raw DB errors. If revocation races an awaited body write, check lease again after await and before next yield. No DB lookup per event/status/heartbeat.

## Risk Assessment
- Axum reverse layers and absent CorsLayer must be tested on constructed router. Raw permit fails `Extensions::insert` Clone bound; cloned Arc/Mutex<Option> transfers once. `Body::from_stream` Drop—not handler return—owns lease. Backpressured wire cannot guarantee final control, but force token must wake IO polls by signal+10 s. Axum-spawned connection tasks make dropping outer `serve` insufficient. Blocking monitor collector and post-serve cleanup are outside HTTP drain deadline.

## Security Considerations
- Origin check enforced even dev/no-auth when `Origin` present, fail malformed/multiple Origin closed; never trust arbitrary forwarded host headers to enlarge allowlist. Preserve bearer-only mechanism for real authenticated GET, no cookies/query token. Signed complete claims retained only server-side, not token. Safe no-store/no-transform responses and bounded frames; auth unavailable revokes delivery and browser must block metrics REST per frozen contract. MFA/absolute expiry both independent of body polling; timed-out auth future dropped, no headers until auth/admission success.
