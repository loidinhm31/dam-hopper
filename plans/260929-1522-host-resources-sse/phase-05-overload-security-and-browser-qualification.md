## Key Insights
- Ten **collector-only** full scans: mean 47.075 ms CPU, largest deep snapshot 7,505 B, 518 PIDs, zero deadlines. Excludes legacy sampler, shared encoding, auth DB, SSE, browser and proxy. Not a whole-monitor or SSE benchmark.
- Default cadence light/process/PSS 5/15/60 s with default 150 ms cooperative process deadline and 500 ms wait deadline; blocking syscalls/legacy sampler remain outside those limits. No remediation via extra collectors, retry workers or invented freshness.
- At 32 bodies × 256 KiB / 5 s, **modeled** payload ≈1.6 MiB/s (1 s stress ≈8 MiB/s), plus controls/network buffering. Two persisted auth reads per 5 s per admitted body on successful checks: at 32 ≈12.8 reads/s, plus admissions/WS/REST. Neither is an observed measurement.

## Architecture and evidence producers
- `server/src/api/resource_events.rs::tests::live_host_resource_qualification` is an opt-in ignored **library unit** harness, not an integration test of private `#[cfg(test)]` state. It boots one real `HostResourceMonitor` and Axum router on ephemeral 127.0.0.1 with an isolated workspace/Mongo namespace and eight authenticated actors. Test-only run-scoped hooks span `resource_stream.rs`, `monitor.rs`, `resource_events.rs`, and `auth/store.rs`; they add no production telemetry or sampling.
- The harness creates a mode-0700 output directory, mode-0600 credentials and signing secret, and a mode-0600 `ready.json`; tokens and secret bytes are not written to ready/log output. `--retain-fixture-for-release` retains the isolated database and local credential material for the release process.
- `HOST_RESOURCE_QUAL_CONFIG` is honored by the test when explicitly set. The current CLI does not pass or compare that config for harness/release parity; matching configurations are therefore not established by the runner.
- Current `--mode harness` opens authenticated SSE readers and consumes body chunks. The recorded short smoke sampled N=0/1/32 with 1 s warmup, 2 s measure, and no soak. It did not run N=4/16, assert the admitted count before measurement, gather enough successful encodes, or exercise target-duration thresholds. At N=32, the 33rd and actor-fifth probes both run while the global limit is full; the latter is not independent evidence for the per-subject limit. The separate C13 HTTP fixture tests four bodies for one subject while global capacity remains.
- Current timeline identity fields are digests: authentication targets, admission subjects, and cleanup details are SHA-256 hashed. The pre-fix local smoke artifact containing raw identifiers was removed; verify the current schema before sharing any future run.
- Runner `summary.json` currently hard-codes top-level `status: "pass"` and reports only a subset of planned metrics. It can report pass with zero serialization samples or a blocked browser; it is not a qualification verdict. The release mode starts the release server, makes an unauthenticated endpoint probe, then terminates it; it does not run the matched client workload or capture release PID CPU/RSS.
- The browser instructions below describe the required future producer, not an implemented runner feature. The Node runner has no Playwright driver; C37/C41 live preview, paired visible-frame timing, calibration, and screenshot evidence remain blocked.
- Proposed evidence provenance remains: use same-run optimized-harness JSONL for test-only monitor/publisher/auth counts, external 1 Hz observations for the exact harness PID, and a separate authenticated release PID under a matched workload for production CPU/RSS. Current smoke output is insufficient for these claims.
- The named-host, proxy, browser, and shutdown scenarios below remain release gates. In particular, there is no real active unread HTTP/WS signal test proving the +10 s listener cutoff, no 30-minute soak, and no named reference/weak host or deployed-proxy evidence.

## Runner interface and artifacts (implemented partially; target qualification remains future)
- `node scripts/qualify-host-resource-sse.mjs --mode harness` accepts workspace, Mongo URI file, output, warmup/series/soak durations, sample interval, client counts, browser origin, and optional fixture retention. Current defaults are 5 s warmup, 10 s series, and no soak. It launches the ignored test, starts authenticated body-draining clients, samples basic harness PID CPU/RSS, and writes `process.jsonl` and `summary.json`; it does not configure/validate a preview or enforce the target durations by default.
- The harness receives `HOST_RESOURCE_QUAL_BROWSER_ORIGIN` and fixture-retention settings. Its test creates credentials/signing material privately, but the runner does not verify Mongo URI file mode, ping Mongo before launch, confirm preview reachability, or enforce matching harness/release configuration.
- `--mode release` accepts a binary/config/ready file and starts a real release server with the retained database and signer. Current code only performs an unauthenticated endpoint probe and sends SIGTERM; it does not authenticate actors, open the N-client workload, sample release PID CPU/RSS, compare configuration, or clean up through a finally-safe owner.
- Current `summary.json` contains a hard-coded top-level pass, basic series, encode p95, 33rd/fifth HTTP status codes, and an explicitly blocked browser metric. Its admission result depends only on the 33rd status; it lacks the planned metric schema, failure/blocked exit mapping, evidence paths, and reliable population gates. Current timeline hooks SHA-256 hash auth targets, admission subjects, and cleanup details; these deterministic, linkable digests are not anonymous. The pre-fix smoke artifact was removed.
- Target harness command remains the 60 s warmup/300 s per-series/1,800 s N32 soak invocation below, on named reference and weak Linux hosts. It is not completed by the short local smoke; separate release-PID, proxy, real-browser, and phase-00 whole-monitor producers are required. ## Risk Assessment
- Bounded watch does not bound slow TCP/proxy queues; inspect backpressure and retained in-flight frames, not just watch length. Absolute process RSS need not fall after Drop; structural counters must.
- Weak-host procfs/mount/legacy startup may block: record elapsed and CPU separately, treat collector stall as stale/unavailable; never add background retries to hide it.
- Chromium HTTP/1.1 origin cap and HTTP/2 flow control change observed throughput; do not extrapolate loopback results to deployment. DB/test environment unavailable is *blocked*, not green.

## Security Considerations
- Isolate temporary DB/fixture data and loopback listeners; use distinct short-lived actors; scrub auth headers, JWTs, subjects, hostnames/path values and snapshots from artifacts. No production DB, host actions, or ambient host mutation. Current hooks hash auth targets, admission subjects, and cleanup details with SHA-256; these digests are deterministic/linkable, not anonymous, so screen future artifacts before sharing. The pre-fix smoke artifact was removed. Verify Origin rejection, auth/session/MFA/absolute-expiry fail-closed behavior, and REST metrics blocked on `AUTH_UNAVAILABLE`.
