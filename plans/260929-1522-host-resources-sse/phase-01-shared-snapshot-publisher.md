## Key Insights
- `run()` calls `update` from pending-deep-worker deadline path **and** regular successful/deadline result. `update` has separate observed (`transition.is_some()`) and degraded branches; both assign `cache.latest` and `cache.legacy`. New revision/notification belongs **once after either commit**, before/independent of WS alert sends; alert/history semantics unchanged.
- Initial `HostResourceMonitor::new` synchronously samples legacy while deep snapshot starts unavailable. Existing monotonic `started_at`/`observed_at_ms` for alert engines must be preserved, not conflated with successful-observation `Instant` for wire freshness. A deadline snapshot advances `sampled_at` and marks stale but must retain last **successful** deep instant. Successful legacy sample independently updates metrics instant even when deep times out; blocked legacy stalls all commits.
- `reconfigure` normalizes config first. If effective clamped freshness inputs (`light_sample_ms`, `snapshot_deadline_ms`, `jitter_ms`) change, commit a **metadata-only new revision** atomically with those inputs and unchanged cached snapshot/metrics/alerts and both successful-observation instants. No sampler/alert transition or synthetic success. Identical effective inputs make no freshness revision (other non-freshness config changes retain existing behavior). Pre-data and periodic TTL then always agree for a given epoch/revision.

## Requirements
- Random `serverEpoch` UUID once per monitor lifetime; initial pair revision `0`, `u64` increments exactly once per later full observed/degraded commit **or effective freshness-config change metadata-only commit**; no revision from status, heartbeat, unchanged clamped config or uncommitted failure. On overflow retire stream epoch, never wrap/reuse revision in same epoch.
- Copy full snapshot + metrics + monotonic observation instants + active light/deadline/jitter configuration atomically under **one short cache read lock**. Never call `snapshot()` and `legacy_metrics()` separately to assemble an SSE frame. Preserve full V1 snapshot/`HostMetrics` JSON, currentAlerts and availability; no extra sampling, retries, alert changes, cache-size growth driven by reader count.
- One feature-local Tokio task, interested readers share immutable `Bytes` frame via latest-only watch. Encode once at most per revision while interested; skip intermediate commits, no new encoding at zero interest, retain ≤1 encoded frame at zero readers and reuse unchanged revision on renewed interest. Protect wake/interest/Drop races; slow consumers skip unbuffered intermediate frames, no per-client JSON or deep clone.
- A **complete** framed `event: host-resources\ndata: {..}\n\n` ≤262,144 bytes. Bounded `serde_json::to_writer` sink rejects before extending buffer, prefix+suffix included; do not `to_string` then check length. Oversize yields typed `FrameTooLarge` state (not truncation) for 02's bounded error control/503; re-evaluate newest revision before failing new admission. Small control event encoding ≤4,096 bytes including framing, with bounded safe reason. No new crate required; `axum::body::Bytes` and existing `uuid`/Tokio available.

## Architecture
- `server/src/system/monitor.rs`: `CachedHostResourcePair { server_epoch: Uuid, revision: u64, snapshot: HostResourceSnapshotV1, metrics: HostMetrics, snapshot_observed_at: Option<Instant>, metrics_observed_at: Option<Instant>, light_sample_ms: u64, snapshot_deadline_ms: u64, jitter_ms: u64 }`; `StreamStatusBasis { server_epoch: Uuid, revision: u64, snapshot_observed_at: Option<Instant>, metrics_observed_at: Option<Instant>, light_sample_ms: u64, snapshot_deadline_ms: u64, jitter_ms: u64 }`. Async `read_stream_pair(&self) -> CachedHostResourcePair` clones both projections **once** under one read; async `current_status_basis(&self) -> StreamStatusBasis` copies **only scalars/Instants** under one read and never calls `read_stream_pair()`/`snapshot()`/`legacy_metrics()`. `subscribe_stream_changes(&self) -> watch::Receiver<u64>` notifies on every real observed/degraded or changed-freshness revision. Initial legacy instant exists only on successful initial sample, initial deep is `None`. In `reconfigure`, synchronize existing config generation with cache lock (update's generation retry remains valid); compare normalized effective freshness inputs with cached values, update inputs and advance one revision **under the same cache lock**, notify after unlock; preserve projections/instants and do not call alert engines or source.
- `server/src/system/resource_stream.rs` (new): immutable `PublishedFrame { bytes: Bytes, server_epoch: Uuid, revision: u64, snapshot_observed_at: Option<Instant>, metrics_observed_at: Option<Instant>, light_sample_ms: u64, freshness_ttl_ms: u64 }`; `HostResourcePublisher::new(monitor: HostResourceMonitor) -> Self`, `.start()`, `.subscribe() -> StreamSubscription`, async `.shutdown()`, async `.current_status_basis() -> StreamStatusBasis` delegates to monitor's **metadata-only** read. `StreamSubscription::{latest,changed}(&mut self) -> Result<Arc<PublishedFrame>, FrameTooLarge>` are async; Drop decrements interest and wakes publisher. Latest-only watch transports Arc or typed oversize (epoch/revision, never partial JSON). `encode_control_event(name: &'static str, payload: &impl Serialize) -> Result<Bytes, ControlTooLarge>` caps complete control at 4 KiB. `frame.status_at(Instant::now())` uses captured revision-bound TTL/instants; periodic `basis.status_at(now)` uses the latest metadata-only basis.
- Publisher observes interest and monitor revision watch, reads latest pair on wake while interested; never skip a **new metadata-only revision** just because snapshot/metrics are unchanged. Subscription registers interest before bootstrap read, borrow-and-update watches for changed revisions and deduplicates duplicates; zero interest performs no new encode, retains at most one last shared frame, invalidates on new revision on renewed demand. No cache/watch/interest lock across JSON, await, OS read or socket I/O. No per-client encoder, async scheduling must not starve monitor; coalesce newer revisions if encode races a newer commit.

## Implementation Steps
1. **B01-A — cache pair (owner: monitor worker; ≤2 paths):** `server/src/system/monitor.rs` (modify), `server/src/system/config.rs` (read only). Expose `CachedHostResourcePair`, metadata-only `StreamStatusBasis`, async `read_stream_pair`, async `current_status_basis`, `subscribe_stream_changes`. Capture real deep/legacy success `Instant` (including initial legacy), preserve alert elapsed-ms logic; retain deep instant on deadline/error/reaped late worker, commit both projections/instants/config atomically in observed and degraded branches. On normalized changed freshness config, metadata-only new revision without sample or alert; unchanged effective config no revision. Keep config generation/cache locking race-safe and notify after unlock; tests must compare periodic/pre-data TTL at same revision, decreased cadence that makes age stale without a new sample, unchanged config, no extra sampling/alert.
2. **B01-B — bounded encoder/publisher (owner: publisher worker; ≤2 paths):** `server/src/system/resource_stream.rs` (new), `server/src/system.rs` (modify). Consume B01-A pair/watch/metadata seam; expose published frames, subscriptions, typed oversize, bounded controls and metadata-only periodic status as above. Encode complete framed JSON ≤256 KiB, schema/epoch/decimal string revision/full snapshot+metrics/lightSampleMs; no per-reader clone or JSON. Revision comparison includes metadata-only config commits: encode exactly once when interested; skip at zero interest and invalidate older retained frame on next demand. Provide private test-only counters for later SAME-process qualification without production telemetry; unit tests for zero-reader reuse, old-frame paired status, metadata-only TTL transition.
3. **B01-I — integrator owns `server/src/system/monitor.rs` + `server/src/system.rs` overlap and integration:** after both workers land, reconcile imports/types, monitor lock ordering (`reconfigure` vs `update`), watch wake/lost-wake and payload serialization; arrange one module owner for shared paths if workers overlap. Workers: **edit only; skip gates, builds, tests, formatters**. Integrator alone runs gates after all land and shares frozen `PublishedFrame`/subscription signatures with 02; no implementation code in 03's frontend files.

## Risk Assessment
- Cloning large cached pair once per revision costs memory but moves one copy outside lock; do not clone once per reader. Watch and owned old frames can coexist in slow bodies; application in-flight bound is ~`(N+1)*256 KiB`, not a promise about TCP/proxy buffers. Blocking encoder could delay publisher: measure p95 in 05. Fake source cannot prove blocked syscalls cancel; monitor retains existing single pending-worker logic.

## Security Considerations
- Raw snapshots may contain host paths; no debug dumps or unbounded serialization; status controls contain only epoch/revision/ages/TTL and safe reason. Publisher has no auth role and MUST be consumed only by phase 02's authenticated route. No query-token or profile ID field.
