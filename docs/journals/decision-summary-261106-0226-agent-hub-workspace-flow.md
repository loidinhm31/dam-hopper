# Agent Hub workspace flow — approved design

- **Mode:** decision-summary
- **Problem & outcome:** Current status-inventory Hub separates project/agent navigation from terminal work. Initial embedded-editor wireframe rejected. User requires the familiar Projects/Agents navigation, embedded terminals, expandable per-project file trees, and files in independent floating OS panels outside Hub.
- **Design status:** **Approved** by explicit design-specific selection, including vertical project tabs and the floating-window reuse policy. Authority: [approved design report](../../plans/reports/ui-ux-designer-261106-0226-agent-hub-workspace-flow.md). Wireframe exports linked there; original review filenames retained.
- **Decisions & trade-offs:** Restore separate Projects and cross-project Agents sections in a hide/show, resizable sidebar. Project names select terminal workspaces; separate chevrons independently disclose their scoped file trees; agent rows select their owning project/session. Main stage remains terminal-only with existing tabs/splits. Inline trees consume sidebar height; separate scroll areas preserve agent visibility. Zero-terminal projects support browsing without launching a PTY.
- **Floating files:** Reuse existing format-appropriate standalone editor/viewer windows and canonical document state. A Hub file click restores the existing window to float and brings it to Hub's current desktop, rather than duplicating buffers or switching away. Project switches leave file windows intact. Capture ownership from the clicked tree, never Hub's fleet context.
- **Boundaries:** Keep standalone apps. No new backend APIs, generic IDE, nested window manager, or batch termination through project close. Projects with live terminals remain listed; only zero-terminal workspaces can be dismissed. Preserve live xterm lifetime, editor dirty buffers/undo, and profile/generation/worktree isolation.
- **Evidence & limits:** Completed UI/UX designer and read-only scout reports; repository inspection of legacy navigator, terminal composition, file intents, resource hosts, and window routing. Revised SVG rendered and PNG visually inspected; PNG/JPG exports produced. No application code changes, builds, lint, tests, or runtime qualification. Prior redesign qualification gates not closed by this brainstorm.
- **Planning consent & result:** User explicitly selected **Defer planning**. Central router not invoked; new plan path: **none**. No implementation authorized or performed.
- **Journal execution:** Entry written directly with the available file tool. Native `/evc-cmd-journal` execution and journal-writer terminal-response gate unavailable through this session's tool surface; not claimed complete.
- **Next step:** Retain approved design for separately authorized central-router planning; no automatic implementation.
