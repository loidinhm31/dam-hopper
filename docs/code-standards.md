# Code Standards

These standards describe the current Rust backend, shared React UI, and profile-aware transport model. The retired plugin platform is not normative; see the [roadmap](./project-roadmap.md) and [Retired Plugin Platform Archive Record](./archive/retired-plugin-platform.md) for retirement status.

## Repository structure

| Path | Responsibility |
| --- | --- |
| `server/src/api/` | Axum route registration, handlers, auth, and WebSocket/API transport |
| `server/src/{auth,config,crypto,fs,git,pty,workflow,agent_status,session_changes}/` | Backend domain boundaries and services |
| `server/src/state.rs` | Shared server `AppState` and service ownership |
| `packages/ui/src/api/` | Owner-bound API clients, connections, DTOs, transports, and query keys |
| `packages/ui/src/components/`, `hooks/`, `stores/`, `lib/`, `os/` | Shared React UI, OS window management, and client-side domain behavior |
| `apps/web/` | Vite browser host (former desktop Tauri host `apps/native/` retired in Phase 02) |
| `server/tests/`, colocated Rust tests, `packages/ui/browser-tests/` | Backend and browser-level behavioral coverage |
| `native/android-app/` | Kotlin Multiplatform + Jetpack Compose Android client; current root flow is Profile Login → Project List → Project Terminal |

## Cross-cutting rules

### Ownership and asynchronous work

- Capture `{ profileId, generation }` before an asynchronous operation. Route it through that owner's `ApiClient`/transport and owner-qualified query keys.
- Recheck captured ownership after every `await` before publishing a result, changing state, or cleaning up a remote resource.
- Never route a failed or unavailable qualified target through an ambient client, first-connected profile, another transport, or project root fallback.
- Bind subscriptions, events, cancellation, and unsubscribe to the transport that created them. Retire state by the exact owner/resource key.
- Keep project selection, Settings target, preferences source, and Browser target as distinct selections.

### Rust backend

- Keep HTTP parsing/authentication in API handlers and domain behavior in the owning service/module. Share bounded DTOs and typed errors rather than duplicating policy in handlers.
- Use typed error enums with `thiserror` at domain boundaries; map them to stable, non-sensitive HTTP/WebSocket responses at the API boundary.
- Validate request size, identifiers, limits, and authorization before expensive work or state mutation. Use checked arithmetic and explicit limits for files, scans, pages, channels, and queues.
- Do not hold synchronous locks across `.await`; keep blocking I/O and external process work outside hot locks. Revalidate state before publishing work completed outside a lock.
- Treat persistence and filesystem replacement as transactions: validate the target, use atomic publication where required, preserve unrelated data, and fail closed on stale revisions or unsafe paths.
- Keep secrets, authentication material, prompt text, terminal content, and private paths out of logs. Reuse the shared redacting logger and bounded diagnostics.
- **Database Path Isolation**: Neutral SQLite database path resolution (`server/src/utils/db_paths.rs`) enforces canonical path resolution and collision detection across subsystems (e.g. `auth.db` vs `sessions.db`). Startup checks prevent path aliasing, identical canonical targets, or hardlink collisions across distinct datastores.

### React and TypeScript

- Use shared components from `packages/ui/`; keep the web host thin and avoid duplicate application state.
- Keep server state in owner-qualified TanStack Query keys and local interaction state in the narrowest appropriate component/store. A single ordinary QueryClient per host is not a substitute for owner-qualified query keys.
- Use typed API methods and DTO decoders at transport boundaries. Normalize once at the boundary; avoid loosely typed response branches in components.
- Cancel superseded requests when supported and discard late results when request ID, provider, target, or owner generation has changed.
- Keep effects and listeners paired with deterministic cleanup. Browser APIs and terminal input must not bypass current mode/owner guards.
- Present disconnected, unsupported, loading, unknown, and error states explicitly; do not fabricate success or silently select another profile.
- **React 19 Radix UI Patch Invariant:** Maintain the pnpm patch `patches/@radix-ui__react-compose-refs@1.1.2.patch`. This patch stabilizes `useComposedRefs` via `useRef` to eliminate infinite ref callback loops under React 19. Do not assume or introduce unverified patches (such as react-slot).
- **Root OS Routing & Legacy Path Translation Invariant:** Both root `/` and `/os` route directly to `OsShell` via `AuthenticatedOsRoute` under React Router `BrowserRouter`. Obsolete templates (`WorkspacePage`, `IdeShell`, `TerminalWorkspaceShell`, `MobileWorkspaceShell`, `AppLayout`, `TopNav`) are deleted. Legacy paths (`/workspace`, `/terminals`, `/ide`, `/git`, `/settings`, `/devices`, `/agent-store`) must translate through `translateLegacyRoute` into qualified OS deep links (`open=terminals|git|settings|agent-store|editor`). Missing legacy qualification displays actionable upgrade guidance rather than falling back to an ambient profile.
- **Zero-Network Retirement Boundary Invariant:** Navigation to permanently retired routes (`/usage`, `/ssh-forwarding`) must be intercepted at the outer router boundary: `AppContentRouter` subscribes to `useLocation()` above `DamHopperAppInner` and checks `isRemovedRoutePath(location.pathname)`, rendering `RemovedRouteScreen` / `RemovedFeatureNotice` with zero mounted network hooks and zero mutations across initial loads and browser Back/Forward history navigation.
- **Generic Terminal Input Policy Invariant:** All web mobile virtual keyboard modules (`MobileTerminalAccessoryBar`, `MobileTerminalCustomKeyboard`, `android-chrome-input-policy`) and coarse-pointer layout hooks are retired. Terminal stdin suppression must be generic via `syncTerminalInputSuppression` (`packages/ui/src/lib/terminal-input-policy.ts`), synchronizing xterm's hidden textarea (`inputMode = "none"`, `tabIndex = -1`, `blur()`) and `disableStdin = true` across Cognito Privacy Mode, disconnected server profiles, and modal dialog focus trapping.
- **OS Resource Continuity & Keep-Alive Reparenting:** Multi-window OS window state transitions (tile, float, maximize, restore, minimize, desktop switches) must preserve underlying runtime instances without unmounting or re-attaching. Resources must reside in root keep-alive hosts (`TerminalKeepAliveHost`, `MonacoKeepAliveHost`, `OsBrowserKeepAliveHost`) inside `OsResourceHost` and attach imperatively to visible window slots (`attachTerminalsToHost`, `attachMonacoToSlot`). UI components must coordinate visible slot exclusivity through `ResourceRegistry` (`useResourceClaim`) to prevent concurrent visible slot conflicts (noting warning W2 for imperatively owned Monaco attachment boundaries). Intent consumers in `OsShell` query `useWindowStore.getState().session.windows` dynamically; unknown terminal targets return `{ status: "unhandled", reason: "terminal-not-found" }` without spawning duplicate windows or mutating active layouts.
- **OS Input Arbitration & Generation-Fenced Services Invariant:** In the OS desktop shell, keyboard input routes through `arbitrateKeyboardEvent` using a 5-tier precedence (`cognito-blocked` > `ime-passthrough` > `os-shortcut-handled` / `os-palette-handled` > `frame-focused-handled` > `app-passthrough`). Configured OS global shortcuts govern dispatch. Window action controllers and topic subscriptions must be strictly generation-fenced: `WindowContextProvider` provides `fencedAction` (pre/post snapshot and generation verification helper; caller integration across app mutations remains open), `globalTopicBroker` isolates by `(profileId, generation)` and scopes unsubscribe to the originating owner generation, `useOsNotificationStore` enforces a bounded 50-entry FIFO log with immediate Cognito field redaction, and `exportOsEnvelope`/`importOsEnvelope` support 4 namespaces under `dam-hopper:os:v1:*` with allowlisted view sanitization and non-executable imported commands.

### UI Selection Contrast & Adaptive Typography Invariants

- **Selection System (`.workbench-selection`):** Active row/list items must use the high-contrast semantic selection tokens (`--color-selection`, `--color-selection-border`, `--color-selection-text`, `--color-selection-hover`) via the shared `.workbench-selection` utility. Left indicators use inset box-shadow (`box-shadow: inset 3px 0 0 var(--color-selection-border)`) to prevent layout shifts. Keyboard focus (`:focus-visible`) uses an outline (`2px solid var(--color-selection-border)`) to coexist with the inset left indicator.
- **Adaptive Typography (`--app-font-size`):** The "System font size" user setting (`systemFontSize`) updates `--app-font-size` on `:root`. All semantic typography tokens (`--text-2xs` through `--text-2xl`) in Tailwind `@theme` are derived from `--app-font-size` with unitless companion line heights.
- **Root Font & Layout Invariance:** `html` font size is never dynamically altered; layout `rem` dimensions (spacing, padding, container widths, hit target heights) remain stable. App zoom (`--app-zoom`) operates independently.
- **Editor & Terminal Font Independence:** Monaco code editor (`editorFontSize`) and xterm terminal (`terminalFontSize`) maintain independent font size configurations and must never be driven by `--app-font-size`.
- **Virtualized Trees (`FileTree`):** Uniform item row heights in Arborist are computed dynamically using `getFileTreeRowHeight(systemFontSize)` from `@/lib/workbench-typography.js` to ensure content never clips across the supported 10–32px range without resetting scroll or unmounting trees.

### Kotlin Multiplatform and Android Native Client (`native/android-app`)

- **Ownership & Connection Scoping:** Mirror React/web invariants; asynchronous operations must capture `ConnectionRef = { profileId, generation }` and recheck upon resume. Never route through ambient fallback.
- **Client boundary:** No WebView, embedded browser engine, local PTY, local Git, or local AI execution in `native/android-app/`. The remote Rust backend owns PTY, Git, agent, and remote workbench operations; Android owns presentation, Keystore credential storage, and client cryptography. Embedded interactive HTML preview and rendered Mermaid diagrams remain deferred.
- **Navigation ownership:** Route the active app flow through `DamHopperMobileApp` and `AppFlowNavigation` (`PROFILE_LOGIN` → `PROJECT_LIST` → `TERMINAL`). The separate `WorkbenchScreen`/12-panel subsystem is not mounted by the current root; do not infer user-visible reachability from a component's presence in source.
- **Network security:** Release builds prohibit cleartext. Debug network config permits cleartext to any host and trusts user-installed CAs; this does not make HTTP safe. Profile Login blocks password/MFA over HTTP. REST/SSE request builders restrict bearer headers to HTTPS or loopback; the WebSocket builder restricts query tokens to HTTPS/WSS or loopback. These request-construction guards do not prove redirect safety. The panel-shell SSE client is not mounted by the current root. `--no-auth` must remain loopback-only.
- **Panel-shell contract:** When the separate workbench shell is mounted, it uses TERMINAL/Traditional presentation, a single top horizontal panel-navigation row, and zero floating action buttons (FABs) or draggable triggers.
- **Module Separation:** Kotlin Multiplatform `commonMain` (`native/android-app/shared/`) owns domain models, networking, DTOs, and Compose UI; platform adapters in `androidApp/`. Never leak Android platform types into `commonMain`.
- **Wire Projection:** Wire requests omit client-only `profileId`; backend authenticates and authorizes project/worktree paths.
- **Filesystem Wire Invariants:** File, directory, stat, read, and mutation operations pass the explicit `ProjectTargetRef`; write operations use chunked streaming with expected mtime compare-and-swap (CAS).
- **Watcher Registration & Invalidation:** Directory watcher subscriptions must register event listeners before dispatching subscription requests to prevent race windows, and reconcile snapshot/event ordering cleanly without relying on unbounded buffering.
- **Search & Replace Constraints:** Enforce literal non-regex replacement without wildcard interpolation; cap federated search at 500 aggregate matches; batch replace must re-verify match presence and use read-to-write CAS; require explicit dirty buffer checks before writing.
- **Encrypted Transfers & Envelope Parity:** Encrypted writes and uploads must assemble payloads into the server-compatible envelope format (`iv(12) || ciphertext + tag(16)`) using AES-256-GCM. Metadata JSON (`FileBlobMetadata`/`TextBlobMetadata`) must not exceed 4,096 bytes and must be separated from binary payload by a single `0x00` byte. Enforce a 100 MiB envelope limit where applicable; plaintext capacity is bounded by 100 MiB minus metadata and crypto envelope overhead. Never fall back to plaintext on encryption failure or missing cryptographic session (`encryptedRequested` must fail closed).
- **Cryptographic Session Lifecycle & Zeroization:** Derived 32-byte AES keys must be held in generation-fenced, `AutoCloseable` session containers (`CryptoSession`) that overwrite key arrays with zeroes upon closure (`keyBytes.fill(0)`). Note JVM garbage collection limitations regarding byte array zeroization. Connection and session validity must be revalidated across all asynchronous boundaries throughout multi-step transfers.
- **Chunked Transfer State Machines:** Binary chunk transfers over WebSocket must use atomic header and binary frame pairs (`sendAtomicPair`), a 64 KiB default chunk size, monotonic request IDs, and pre-registered chunk acknowledgement listeners. In-flight commit timeouts must report `UnknownOutcome` to mandate server state verification before retry.
- **Android SAF Storage Scoping:** Document storage on Android must utilize Storage Access Framework (SAF) scoped content URIs (`DocumentStorage`, `AndroidDocumentStorage`) rather than requiring broad external storage permissions. Filenames must be sanitized, and reads/writes must stream in bounded chunks rather than buffering entire files in memory.
- **Media Streaming & Cookie Isolation:** Native media streaming must follow the [Media Isolation and Encryption Architecture](./architecture/media-isolation-and-encryption.md), adapting browser cookie contracts to native HTTP/player stacks. Requests must enforce canonical UUIDv4 `mediaClientId`, namespaced session cookies (`damhopper-media-session-<uuidv4>`), fail-closed cookie verification, redirect rejection (`followRedirects(false)`, `followSslRedirects(false)`), strict same-origin checks, and closed `purpose` capability segregation (`PLAYBACK` vs `DOWNLOAD`).
- **Git Repositories, Controllers & Leased Publication Invariants:** Domain Git repositories must be partitioned by concern (`GitQueryRepository`, `GitMutationRepository`, `GitBranchWorktreeRepository`, `GitHistoryMutationRepository`, `GitPublishRepository`) under a target-bound `GitRepository` facade. All Git operations must execute within `GitOperationScope(profileId, generation, project, worktreePath)`. Worktree removal must precheck dirty editor buffers (`EditorTabsState.isDirtyTarget`) and active PTY sessions. Local history rewrites (commit message edit, contiguous squash) are permitted on inactive local branches (`isViewingLocalBranch`), whereas destructive actions (`reset`, `drop`, `undoLastCommit`) and working-tree mutations (`cherryPick`, `revert`) require a checked-out active branch (`isViewingActiveBranch`). Local rewrites must never publish automatically; publication requires explicit user confirmation via leased push (`LeasedPublishController`) using exact expected remote OID leases, aborting on stale remote state with no blind force-push fallback. Presentation in `GitPanelScreen` and `GitModalsHost` must strictly enforce zero floating action buttons (FABs).
- **Preferences & Bounds Clamping:** Local and remote preference models (`WorkbenchPreferences`, `SettingsSourceTargetState`) must strictly clamp user-configurable bounds (fonts 10..32, terminal scroll step 1..50, default 5). Stale-owner fencing must capture profile, connection generation, and edit revision, rejecting out-of-order writes if ownership shifts or the edit revision is superseded. TOML imports must enforce the 1 MiB boundary (`MAX_CONFIG_IMPORT_BYTES = 1024L * 1024L`) and verify the active connection generation before dispatch.
- **Three-Layer Ephemeral Privacy Input Gating:** The configured shortcut preference (`cognitoModeShortcut`) persists and syncs remotely, while runtime mask activation (`isMaskActive`) and the captured dismissal chord (`activationChord`) remain strictly ephemeral in memory and must never be persisted. Input isolation must be enforced across three defense-in-depth boundaries: (1) Compose overlay pointer consumption, (2) session controller dispatch (`TerminalSessionController.isInputAllowed()`, `EditorSession.isInputAllowed()`, `EditorTabsState`), and (3) platform surface dispatch (`TerminalInputController` hardware keys, IME commits, IME deletes, paste; `AndroidEditorSurface`). Activation must immediately clear focus and suppress soft keyboard (`keyboardController.hide()`, `focusManager.clearFocus(force = true)`).
- **Notification Privacy & Redaction:** Android notification channels (`AndroidNotificationSink`) must configure `Notification.VISIBILITY_PRIVATE` and attach a sanitized, generic public version (`setPublicVersion`) intended to redact confidential terminal commands or file contents on lock screens. PendingIntents must specify `FLAG_UPDATE_CURRENT or FLAG_IMMUTABLE`. Retiring a server profile must cancel all pending notifications registered under that profile.
- **Lifecycle Demand-Driven Coordination:** `LifecycleCoordinator` and `LifecycleAware` must distinguish temporary app backgrounding from destructive profile logout/retirement. App backgrounding must pause demand-driven streaming without destroying remote PTY sessions; foregrounding must re-evaluate visible interest. Profile retirement must tear down owner-specific notifications, settings states, and active controllers.
## Domain-specific invariants

### Git history changes

- A local rewrite is a separate user action from remote publication. Capture branch and HEAD, validate an exact operation range, and use compare-and-swap when updating refs.
- Squash only a unique contiguous oldest-first parent chain reaching the captured tip; reject stale snapshots and unsafe merge/range shapes.
- Publish rewritten history only with an explicit confirmation and exact expected-OID lease. Ordinary push remains fast-forward-only.
- Preserve final tree/index/working tree and required signature-loss consent. Never publish automatically after editing or squashing commits.

### Git conflict discovery, snapshots, and client mutations

- Conflict summary queries (`GET /api/git/{project}/conflicts`) return bounded unmerged index entries without eager blob or worktree file loading. Opaque v2 cursors bind the full unmerged conflict-set fingerprint and last raw-path anchor; changed sets or missing anchors fail closed with `GIT_CONFLICT_CURSOR_STALE`.
- Conflict detail snapshots (`GET /api/git/{project}/conflicts/file`) enforce pre-allocation byte bounds before allocating blob memory (5 MiB per stage, 15 MiB aggregate across stages 1/2/3) and worktree read bounds (5 MiB). Tokenization bounds line counts (50,000 lines) and line lengths (100,000 bytes). Oversized files or custom filters withhold line tokens and mark stages `unsupported`.
- Text splitting preserves line terminators losslessly (`\r\n`, `\n`, lone `\r`) without normalization or replacement characters.
- Detail reads capture before/after state fingerprints (HEAD OID, full index entries, worktree attributes); detected state drift between before and after reads returns HTTP 409 `REFRESH_REQUIRED`.
- Conflict resolution mutation requires structured precondition verification (`snapshotVersion`, `fullIndexFingerprint`); legacy resolution payloads (`{ path, content }`) fail closed with HTTP 400 `LEGACY_PAYLOAD_REJECTED`.
- **Client Git Mutation DTO Conventions:** Client Git mutation requests and responses must use fail-closed typed unions with no legacy string fallbacks (`ResolveRequest` with discriminated `action`: `reviewedText`, `indexSide`, `delete`; `OperationActionRequest` with discriminated `action`: `continue`, `abort`). Wire transports and client layers must reject untyped payload shapes or legacy fallback fields (`{ path, content }`); missing precondition tokens (`conflictId`, `snapshotVersion`, `fullIndexFingerprint` on resolve; `operationPrecondition`, `fullIndexFingerprint` on operation actions) fail closed on the client before dispatch. Responses must be evaluated against their respective domain outcome taxonomies: `ResolveOutcome` (`applied`, `stale`, `unsupported`, `busy`, `failedBeforeWrite`, `worktreeChangedStageFailed`, `outcomeUnknown`) and `OperationOutcome` (`continued`, `aborted`, `blocked`, `stale`, `failed`, `outcomeUnknown`). Blind or automatic retries on timeouts, disconnects, or uncertain outcomes (`outcomeUnknown`, `worktreeChangedStageFailed`) are strictly forbidden.
- **In-Memory Draft Capacity Fences:** Conflict draft stores must remain strictly memory-only; drafts must never be serialized or resuscitated from browser persistence (`localStorage`, `sessionStorage`, IndexedDB). Memory accounting must track accounted UTF-8 text bytes (`TextEncoder`), not JavaScript object heap overhead, across source stages, working tree, resolved text, edit history, and recovery text. Registries must enforce hard capacity fences (default 10 MiB total, 2 MiB per draft, 10 dirty drafts). Clean drafts may be evicted oldest-first under memory pressure, but dirty or recovery drafts are never silently evicted; admission fails closed when dirty drafts saturate capacity. Prospective edit growth checks must validate that proposed text mutations and history fit within limits prior to mutating draft state. Snapshot drift must mark dirty drafts as requiring operator recovery and review; automatic replay or unreviewed submission across snapshot drift is prohibited.
- **Conflict Merge Model & Tokenization Standards:**
  - *Canonical BOM-less Representation:* Model `resultText` must separate one leading UTF-8 Byte Order Mark (`\uFEFF`) at index 0 into the boolean `hasBom` flag on ingest (`createConflictMergeModel`, manual text edits, whole-file actions), leaving internal text strictly BOM-free without altering arbitrary `U+FEFF` characters elsewhere in text. Byte Order Marks must be re-applied only during final serialization (`getModelSerializedResult`) when `hasBom` is true. This prevents line-start character offset drift and marker parser desynchronization across multiple conflict regions.
  - *Lossless Line Tokenization:* `tokenizeLosslessLines` must preserve raw line terminators (`\r\n`, `\n`, lone `\r`) and missing final newlines with 100% roundtrip fidelity (`rejoinLosslessLines(tokens) === text`). Line ending classification (`detectLineEnding`) detects dominant `crlf`, `lf`, `mixed`, or `none`.
  - *Conservative Region Mapping & Downgrade Rules:* Mapping source regions to result text must fail closed. Regions are matched first against parsed Git conflict markers (Strategy 1A 1:1 alignment, Strategy 1B unique content) with non-overlapping line range verification. Non-marker content searches that produce multiple matches must flag `confidence: "ambiguous"`; unmatched regions must flag `confidence: "unmapped"`. Manual text edits via `applyManualResultTextEdit` must downgrade `ambiguous` and `unmapped` regions to `manualReview: "needs-review"`.
  - *Atomic History Transactions & Decision Snapshots:* Undo/redo history must record atomic snapshots of both text and region decision states (`beforeDecisions`/`afterDecisions`), ensuring undo/redo operations restore decision states alongside text. Identical-text decisions (such as accepting a side whose content matches the existing result text) must record history entries to allow deterministic undo/redo.
  - *Normative Invariants vs Open Implementation Defects:* Normative standards require byte accounting across all history growth and strict dirtiness tracking; current component defects—such as metadata-only history entries in `ConflictDraftRegistry` bypassing prospective byte capacity checks under a fixed 100-entry cap, typing coalescing ordering in text-changing actions, and decision-only redo dirtiness evaluation—must be tracked as open safety defects rather than permitted architectural exceptions. Furthermore, `JointHistoryAuthority` provides standalone Monaco command interception and snapshotting, but remains separate from `draft.history` pending unified wiring in downstream Phase 09 qualification.
- **Floating Conflict Resolver Surface and OS Frame Authority:**
  - *Shared Host Boundary:* The floating conflict resolver (`ConflictResolverPanel`) mounts inside `ConflictResolverApp` or as a floating modal surface within the OS desktop. Legacy workspace shell panel stack controllers (`terminal-workspace-panel.ts`, `floatingPanelStack`, `updateFloatingPanelStack`, `WorkspacePage`, `TerminalWorkspaceShell`) are deleted.
  - *OS Frame Stacking Authority:* Layering for the floating conflict resolver is governed directly by OS frame authority (`OS_RESOLVER_PANEL_TOPMOST_Z_INDEX = 30`), coordinating z-index hierarchy within the desktop canvas without legacy panel stack registries.
  - *Scoped Escape & Focus Arbitration:* Monaco widgets and context menus (`.suggest-widget.visible`, `.find-widget.visible`, `.monaco-menu-container`) must consume Escape before panel dismissal. The Escape shortcut closes or hides the floating resolver only if it is the topmost floating panel, focus is inside the panel (or document root), and no Monaco overlay is active. Unconsumed Escape events must stop propagation to prevent terminal key leakage or multiple panel closures.
  - *Responsive Narrow Mode Transitions:* When container width falls below 768px (measured via `ResizeObserver` observing the editor container), the editor must switch from multi-column grid layout to accessible tabbed pane switching (`Theirs`, `Result`, `Ours`, `Base`). Switching visible panes must preserve in-progress draft text edits and region decision state.
  - *Monaco Model Path Isolation & Open Target Gap:* Editor instances must use deterministic in-memory model URIs (`inmemory://${project}/${filePath}/${pane}`) with `keepCurrentModel: true`. Current URI paths isolate panes within a project and path, but do not encode profile ID, connection generation, or worktree path; full owner-qualified URI scoping remains an open isolation gate for multi-target workflows.
  - *Region-ID Keyed Navigation & Actions:* Conflict chunk navigation and merge actions (`onAcceptSide`, `onAcceptBoth`, `onIgnoreSide`, `onMarkReviewed`) must bind strictly to stable `region.id` keys rather than volatile line numbers or array indices.
  - *Reveal Intent Routing Standards:* Conflicted rows in `ChangedFilesList` must emit `ConflictRevealIntent` (`{ nonce, filePath, root }`) via `buildConflictRevealIntent`, calling `handleOpenConflictResolver(selection)` instead of `onSelectFile`. `openChangedFileDiff` must return early for `status === "conflicted"`, preventing editor tab creation. Multi-root and aggregate views must derive the entry's actual worktree root (`selection.gitRootId !== "." ? selection.gitRootId : undefined`).
  - *Stage Bypass Closure Standards (CUT1):* Conflicted rows must disable staging checkboxes (`disabled={isConflicted}`), popover context menus must replace staging/discard actions with "Resolve conflict…", bulk staging must filter out conflicted entries, and backend stage requests must reject unmerged conflicts fail-closed under `GitMutationCoordinator` lock. Legacy resolve requests with `{ path, content }` must fail closed with HTTP 400 `LEGACY_PAYLOAD_REJECTED`.
  - *Retirement Standards (CUT2):* Legacy `conflict-parser.ts`, `ConflictBlock`, and marker-derived resolution models must be completely eliminated. Zero production imports or references are permitted. Android Chrome read-only input coverage must be preserved through behavioral testing against `ConflictRegionNav`.
  - *Nonce Consumption Standards:* Components consuming reveal intents must track `lastConsumedNonceRef` during component mount to apply intent parameters once and avoid snapping back user selection during background query refetches (unmounting resets the ref, re-evaluating fresh reveal intents on remount).
### Agent Status

- Correlate terminal ID with PTY incarnation and fence updates with reporter epochs and leases.
- Keep semantic agent state separate from process state, workflow completion, and idle-suspend activity.
- Never infer successful completion from silence, disconnect, stale report, or turn end. Do not transmit prompts, transcript text, commands, or native session paths.
- Keep OMP on its private loopback WebSocket collector and native Codex/Claude ingress on the protected Unix socket with peer-credential verification.

See the [Agent Status contract](./architecture/agent-status.md).


### Session Changes Review

- **Immutability & Read-Only Invariant:** Strictly read-only; never mutate repository working tree files, Git index, HEAD references, or invoke Git mutation commands (`reset`, `stash`, `checkout`, `commit`).
- **Canonical Root Preflight & Sandbox Containment:** Enforce single relative root ID (default `.`) via direct `validate_project_root_preflight`. Enforce `MAX_PATH_BYTES` (4096) and `MAX_PATH_DEPTH` (64). Reject parent traversal (`..`), absolute paths, empty components, NUL bytes, and wildcards. Root containment must resolve within the server-bound launch target sandbox; never discover unrestricted external repositories.
- **Resource Limits & Capacity Fences:**
  - 32 global retained identities (`MAX_RETAINED_IDENTITIES`); max 500 tracked paths per session (`MAX_PATHS_PER_SESSION`).
  - 2 MiB regular file read limit (`MAX_FILE_RAW_BYTES`).
  - 64 MiB global accounted baseline storage cap across all sessions (`MAX_GLOBAL_STORAGE_BYTES`).
  - 2 global blocking scan permits; permits held until blocking closure exits; saturation returns HTTP 409 `busy` without queuing.
- **Origin-Qualified Status Invariants:**
  - `toolObserved`: `ready` / `incomplete` (always `notApplicable` acknowledgment; reflects observed tool edits since session first-touch, never repository-wide baseline).
  - `unavailable` / `missing`: when tracking disabled or identity unknown.
- **Safe First-Touch Capture & Tool-Event Provenance:**
  - First-touch pre-edit capture intercepts supported tool events (`write`, Hashline `edit` including `MV`/`REM`, and concrete-file `ast_edit`) with 1500 ms fail-open timeout. Arbitrary script mutations (`bash`/`eval`) are not captured here and remain tracked in Git Changes.
  - Negative proof requires verified directory hierarchy without symlink ancestors (`absentAtFirstTouch`). Unproven, permission-failed, or ignored subtrees remain `unknown`/`unproven` or `excludedAtCapture`.
  - Zero background diffing or file reads on settled turns or status polling; current file reads and line stats compute lazily only on viewer `/files`, `/refresh`, and `/files/{fileId}` queries.
- **Target-Server Session Changes Setting Pattern:**
  - Authority: Controlled by `server.sessionChangesEnabled` (`server.session_changes_enabled` in TOML) in `DamHopperConfig` on the target server (`targetOwner`), never client-side workbench preferences or localStorage.
  - Target Binding & Concurrency: `SettingsPage` resolves `targetOwner` from the selected Settings Target Server (`settingsProfileId`). Full config replacement via `useUpdateConfig` must preserve all unrelated server fields (`[key: string]: unknown`). Mutation captures action profile and generation (`actionProfileId`, `actionGeneration`) to avoid applying late state when an explicit target is switched mid-flight (default target check resolves null/generation 1). Switching targets during an in-flight toggle clears the captured target's query cache, but does not purge the newly selected target until that server is toggled or refreshed.
  - Cache Invalidation & Purge: On successful mutation, UI invalidates config queries and explicitly cancels and removes all `session-changes` queries for that target owner (`profileQueryKey(targetOwner, "session-changes")`), preventing stale state or memory leaks.
  - Honest Lifecycle Feedback: Enabling displays a notice instructing the operator to restart active OMP sessions (`Restart active OMP sessions to load the Session Changes extension`). Disabling clears this notice. Failures preserve authoritative server state and surface actionable conflict/permission errors rather than optimistically toggling UI state.
  - Trigger Gating: All review triggers (`TabBar`, `ActiveTerminalRuntimeDisplay`, OS intent router) verify `useSessionChangesEnabled(terminalOwner)` before displaying or opening, hiding/disabling when the owning server is disabled, loading, disconnected, or unavailable.
- **Lazy Diff Viewer Pattern:**
  - Viewer Boundary: Opening `SessionChangesHost` is the explicit viewer boundary. Settled turns and status polling are strictly metadata-only.
  - Initial Comparison Bootstrap: Panel mounts from metadata-only ready status (`state === "ready" | "incomplete"`). Initial `useSessionChangesFiles` requests `/files` without requiring a prior comparison revision; the backend computes comparison and returns `comparisonRevision` alongside the first page.
  - Fenced Detail Loading: Detail query `useSessionChangesFileDetail` is strictly gated (`enabled: Boolean(currentRevision && selectedFileId)`); it never mounts or fetches without a valid comparison revision.
  - Stale Revision Recovery: Stale revision errors (`refreshRequired`, `serverRestarted`) clear selected file, active revision, cursor, and accumulated files, then trigger `onRefresh` to re-fetch a coherent comparison revision without displaying mismatched or mixed-revision diffs.
  - Bounded Cursor Pagination: File list supports keyset/cursor pagination up to the session limit (500 paths display bound, current UI page size 200). `accumulatedFiles` deduplicates by `fileId` and caps at 500 rows.
- **OS Application Isolation Pattern (`SessionChangesApp`):**
  - Application Window Ownership & Lifecycle: Session Changes review is hosted as an OS window (`SessionChangesApp`), keyed by the complete 6-part process tuple (`profileId:generation:terminalId:terminalIncarnation:ompSessionId:rootId`). It coordinates visible slot exclusivity via `useResourceClaim` and tears down automatically upon server disablement, disconnect, or owner generation retirement.
  - Keyboard & Focus Isolation: `SessionChangesApp` manages focus explicitly on its container (`rootRef`) and intercepts keyboard shortcuts/Escape via `handleKeyDown` to contain keys within the review window, while OS-level input arbitration isolates global shortcuts (live PTY input isolation and focus recovery remain governed by live journey qualification).
- **Capability-Free Monaco Diff Viewer:** Monaco diff instance (`ReadonlyMonacoDiffViewer`) must set `readOnly: true`, `originalEditable: false`, and `domReadOnly: true`. Disable editing commands, drop, and paste. Model URIs must encode the full owner tuple with deferred disposal to prevent race conditions during rapid switching.
### Cognito Mode

- Keep activation ephemeral; persist only the user preference fields supported by configuration. Treat the overlay as a visual in-app mask, not authorization, content redaction, or an OS capture boundary.
- Maintain input isolation through event capture, the app-content inert/hidden boundary, and a usable keyboard dismissal path. Restore focus and listeners on deactivation/unmount.
- Current checked-in Heavy Blur CSS is `blur(16px) saturate(180%)` over `rgba(148, 163, 184, 0.12)` when backdrop-filter is available. Unsupported and reduced-transparency modes use opaque black. Do not copy older values from historical notes without checking `packages/ui/src/index.css`.

### AI Dev OS Lifecycle & Window Management

- **Single-Transaction Placement Mutations:** Window placement, focus, docking, floating, and maximization operations must execute as pure transformations via `packages/ui/src/os/window-ops.ts`, updating the Zustand store (`packages/ui/src/os/window-store.ts`) in single atomic transactions. Floating coordinates must be clamped to viewport bounds via `clampFloatBounds`.
- **Top-Level Keep-Alive Mounting & Hub Mount Merging:** Live resource hosts (`TerminalKeepAliveHost`, `MonacoKeepAliveHost`, `OsBrowserKeepAliveHost`) must mount once in `OsResourceHost` above all desktop and window render branches. `OsResourceHost` dynamically merges terminal sessions from standalone `terminals` windows with published active Hub terminal mount descriptors (`useHubTerminalMountsStore`), pruning closed Hub windows reactively while preserving persistent xterm instance continuity across project switches, sidebar toggles, and splits. App bodies supply visual mounting slots (`slotRef`), into which live DOM elements (xterm PTY instances, Monaco editor DOM nodes, and browser preview iframes) are imperatively attached or parked. Never destroy or remount a live resource during window docking, floating, maximizing, or desktop switching.
- **Single-Visible-Slot Registry Contract & Reveal Window:** The central `ResourceRegistry` (`packages/ui/src/os/resource-registry.ts`) enforces visual exclusivity via deterministic claim keys `${kind}/${profileId}/${generation}/${resourceId}[/inc:${inc}][/ep:${ep}]`. Conflicting requests from a second window must be rejected and offer a "Go to window" reveal action (`revealWindow` in `packages/ui/src/os/window-ops.ts`, atomically switching desktop, restoring, and focusing the claim holder) rather than stealing attachment or killing processes. Visual resource claims govern client-side presentation exclusivity only and do not replace backend transport, connection generation (`generation`), or PTY incarnation (`incarnation`) fencing.
- **Global Float-Over-Maximized Stacking (B2):** In the OS desktop workspace canvas (`DesktopCanvas.tsx`), when the active desktop's focused window is a floating window, the float layer container stacks at z-index 60 above the maximized plane (z-index 40, focused slot 50). When a maximized window receives focus, the float layer container drops to z-index 20 below the maximized plane. Decided limitation: `BrowserApp` iframe hosting with fixed z-index 20 in `OsResourceHost` remains outside DesktopCanvas B2 float-over-maximized stacking (V4).
- **Float File Open Mode:** The `file:open` intent supports explicit `mode: "float"`, ensuring files opened from workspace trees float above maximized Agent Hub windows with clicked-tree owner badges. Existing editor windows are reused across desktops when `ctx.generation` is undefined (live-owner) or matches the request; windows with defined generation mismatches fail closed to reveal-only mode without retargeting.
- **Presentation Input Ownership:** Owner-scoped tokens (`packages/ui/src/lib/terminal-presentation-input.ts`) must govern interactive terminal presentation (`acquireTerminalPresentation`, `releaseTerminalPresentation`, `isCurrentTerminalPresenter`, `setPresenterInputSuppression`). The internal registry maintains a `WeakMap<Terminal, TerminalPresentationState>` permanently marking terminals as `managed: true` with strictly monotonic epochs. Successor presenters must acquire fresh tokens; unmounting or transitioning predecessors must only release their own token, never muting or stealing stdin on quiet PTYs during Hub ↔ standalone handoffs (F2). Presentation input tokens arbitrate UI keyboard/focus presentation only; backend transport, connection generation, and PTY incarnation fencing remain authoritative on every mutation boundary.
- **Per-Profile Terminal Pin Retention:** Terminal pin/unpin persistence must be partitioned per profile using tab-scoped `sessionStorage` key `dam-hopper:terminal-pins:v2:<encoded-profileId>` (payload version 2) via `packages/ui/src/lib/terminal-pin-persistence.ts`. Pins survive page reloads within the same browser tab and never leave the browser tab or reach the server. Stored pins must be protected from premature pruning during inventory loading, network retries, or when a profile is disconnected; pins are only pruned against confirmed inventory sessions once the profile inventory is successfully loaded (`retainPinnedTerminalIds`). Closing a terminal tab is target-fenced and never terminates the Hub window.
- **Editor Endpoint Save Fence:** Editor buffer identity must bind to `EndpointIdentity` (`{ profileId, serverUrl }` normalized via `normalizeServerUrl`) captured at baseline read. Changing a profile's target server URL must deny saves fail-closed (`saveBlockedReason`) while preserving buffer content and undo history intact. Same-endpoint reconnects must continue saving. Only explicit user-confirmed `discardAndReload` may rebind endpoint identity. Persisted dirty tabs must include endpoint identity; legacy dirty tabs lacking identity fail closed once on save until reload (V1, V6).
- **Persistence Sanitization & Placement Invariants:** OS sessions persisted to `dam-hopper:os:v1:session` must be sanitized via `sanitizeSessionForPersistence` to include only allowlisted view attributes (`sessionId`/`cwd` for terminals, `filePath` for editor, `url` for browser). Schema corruption or parse errors must suspend autosave (`autosaveSuspended`) and preserve raw corrupt bytes (`preservedCorruptBytes`). Sessions must strictly pass `validateOsSession`: non-minimized tiled windows appear exactly once in tree and zero in float; non-minimized floating windows appear exactly once in float and zero in tree; minimized windows appear in neither; window `desktopId` matches placement; and desktop focus is valid.
- **Input Precedence:** Input arbitration must follow the 5-tier precedence model: (1) Cognito privacy blocking, (2) IME/dead/AltGr passthrough without chord interception, (3) OS global shortcut (`Ctrl+Alt+Escape`) window cycling without PTY bytes, (4) frame chrome focus, (5) app body passthrough.
- **Storage-Key vs Payload Version Separation:** Maintain unchanged `terminal-layout:v3:*` keys containing `{ version: 2, root }` payloads with `sessionIds`/`activeSessionId`. Layout mutations and wire codecs must losslessly map between `LayoutNode` and generic `TileNode<T>` (`items`/`active`) without disk migration.

### AI Dev OS Application Adapters & Deep Link Protocols

- **Adapter Composition Over Duplication:** Application adapters under `packages/ui/src/os/apps/` must wrap existing canonical organisms and page components without duplicating domain logic, state machines, or database calls. Adapters extract navigation chrome, bind the window context (`WindowContext`), and connect user actions to typed intents.
- **Exact Instancing Granularity:** Every application declared in `APP_MANIFESTS` must specify its exact instancing rule:
  - `single-instance`: Singleton across session (e.g. `settings`).
  - `profile-instance`: Deduplicated by `profileId` (e.g. `ports-tunnels`, `agent-store`).
  - `project-instance`: Deduplicated by `(profileId, projectId)` (e.g. `workflow-plans`, `project-info`; `conflict-resolver` adds `(worktreeId, gitRootId, operation)`).
  - `worktree-instance`: Deduplicated by `(profileId, projectId, worktreeId)` (e.g. `files`, `search`, `changes`, `git`).
  - `tuple-instance`: Deduplicated by full 6-part process tuple (e.g. `session-changes`).
  - `multi-instance`: Unrestricted independent window creation (e.g. `terminals`, `editor`, `browser`).
  Deduplication checks must execute through `findExistingWindowForApp` before creating a new window.
- **Deep Link Fail-Closed Validation:** Deep link parameters parsed via `parseOsDeepLink` must strictly validate profile existence in `knownProfiles`, enforce `minimumCtx: "project"`, validate line numbers as positive decimals, and verify the full owner tuple for Session Changes. Deep links synthesize typed `OsIntent` records; they must never run ambient shell commands or spawn unattended processes.
- **Single-Transport & Generation Fencing Invariant:** UI components and hooks performing server communication (`DiffViewer`, `useFileSearch`, `useSearchPanelReplace`, `usePorts`, `SessionChangesApp`) must bind strictly to the authoritative profile transport (`getBoundTransport` / `getConnectionsTransport`). When federated profiles are empty, return safe empty results without ambient fallback. Increment edit revisions (`editRevisionRef`) on model mutations, verify connection generation before and after asynchronous I/O, and reset the save UI indicator from `"saving"` to `"idle"` if user typing supersedes in-flight stat/write operations (without cancelling an already-dispatched server write). Post-write baseline pinning (`authoritativeModified`) must preserve newer local dirty edits over external refetches, while in-memory draft retention across window/tab unmounts remains an open qualification gate.
- **Search Result Binding & Mode Query Isolation:** SearchPanel matches and Replace actions must bind strictly to the active query result snapshot (`isSearchMatchingInput`, checking 200-character normalized input match and loading state). Replace actions must be disabled and matches cleared when input diverges from results. SearchApp windows must maintain isolated local query state per mode (`isolatedState={true}`) to prevent leaking into global search UI stores.
- **Intent Delivery & Once-Per-Delivery Consumption:** Intent dispatching to running or new windows must include a unique `deliveryId` in window `appState`. Apps consuming intents must ensure once-per-delivery behavior (via `deliveryId` consumption tracking or keying) to execute the intent payload once upon arrival and avoid repeating selection or tab activation on subsequent unrelated query invalidations or background refetches. Path resolution in `ChangesApp` must prioritize canonical project path matches before root-relative aliases.
- **Management Page Controlled Props & Capture-and-Recheck Ownership:** Page components (`AgentStorePage`, `SettingsPage`, `DevicesPage`) mounted inside OS windows must support controlled mode via dedicated props (`AgentStorePageProps`, `SettingsPageProps`, `DevicesPageProps`) and `noLayout`. In controlled/embedded mode, user actions (tab switches, profile selection) must not mutate global route URL search parameters or global workbench selections stores; they update window `appState` or invoke prop callbacks. Operations crossing async boundaries must follow capture-and-recheck: `{ profileId, generation }` is captured before I/O, and `getCurrentEffectiveProfileId()` confirms target currency before applying post-await mutations rather than retargeting an in-flight action.
## Git, auth, and transport security

- Derive actor identity and role from validated server authentication state; never trust request-body actor or role claims, and never treat the server's `server-token` JWT signing secret as a client bearer credential.
- Default to SQLite for unconfigured startup (when `MONGODB_URI` and `MONGODB_DATABASE` are unset) with optional `DAM_HOPPER_AUTH_SQLITE_PATH` (default `auth.db` in global config; production uses absolute local storage). Auto-select MongoDB when both `MONGODB_URI` and `MONGODB_DATABASE` are configured, enforce MongoDB with `DAM_HOPPER_LITE_MODE=false/0`, or force SQLite with `DAM_HOPPER_LITE_MODE=true/1`. Enforce one server process per local SQLite auth file, forbid network/shared filesystems, never fall back from an unreachable or failing backend, and fail startup on invalid or malformed backend configuration. Production authenticated mode requires a valid dedicated 32-byte owner-only `DAM_HOPPER_MFA_KEY_FILE`.
- DamHopper does not expose a public registration endpoint over HTTP (`POST /api/auth/register` is permanently removed). Operator accounts must be provisioned offline using `node scripts/create-admin.mjs` directly on the host machine. Unapproved login attempts return `401 ACCOUNT_DISABLED`. Mandatory MFA enrollment is performed on first login via TOTP setup.
- Use exact allowed origins for credentialed browser requests. Keep auth/session cookies, bearer credentials, tickets, and encryption material out of URLs and logs.
- Bind one-shot media/file capabilities to actor, profile client namespace, target, purpose, and revision/incarnation; revalidate after asynchronous work.
- OPAQUE/AES encrypted writes must use one captured owner transport for authentication, encryption flow, and final write. Do not downgrade stale operations to plaintext or another profile.
- Development `--no-auth` must be bound to loopback, is never SQLite lite mode, and must never be described as a production option.

## Testing and delivery

- Place tests next to small domain units; use `server/tests/` for cross-module server behavior, `packages/ui/src/**/*.test.ts(x)` for headless unit tests, `packages/ui/browser-tests/` for real-browser component integration, and `packages/ui/e2e/` for application journeys.
- Test success and denial paths, stale generations, cancellation, unavailable owners, limits, and failure cleanup where those contracts apply.
- Distinguish mocked component tests from real HTTP/browser/deployment qualification. Record platform/version limitations; do not turn prior test counts into a claim of current release qualification.
- Run repository-supported commands from `package.json` and package manifests. `pnpm test` runs server tests, `pnpm test:all` runs the repository test script, `pnpm lint` covers `apps/` and `packages/`, and `pnpm build` with `pnpm --filter @dam-hopper/ui build` provide web bundle and type checking (note that Vite builds bundle and strip types without full type-checking, whereas static type correctness relies on `tsc`).
- Terminal termination fixtures in `packages/ui/src/api/terminal-termination-fixtures.json` are authoritative per-section schemas: eligibility and state samples use `input`, endpoint samples use `body`, and epoch samples use `incomingObservation`. Construct owner-qualified inventory observations explicitly; do not infer missing owner metadata or invent fixture fields. Compile Rust test targets with `cargo check --manifest-path server/Cargo.toml --tests` in addition to the ordinary server check when changing API/PTY tests.
- **4-Tier Runner Boundaries (see [Testing guide](./testing.md)):**
  - **Tier 1 — Rust Backend Tests (`cargo test`):** Unit and integration suites against real filesystems and repositories; avoid mocks for Git CAS, PTY, and SQLite persistence.
  - **Tier 2 — Frontend Unit Tests (Vitest jsdom):** Headless execution of stores, reducers, hooks, and data utilities under `packages/ui/src/**/*.test.{ts,tsx}`.
  - **Tier 3 — Browser Component Regressions (Vitest Browser Mode):** Headless Chromium suites under `packages/ui/browser-tests/**/*.browser.{ts,tsx}` on ports 15173 and 15174 for focused DOM/xterm component verification against real browser runtimes (with legacy shell suites pruned and component fixtures migrated to OS shell adapters).
  - **Tier 4 — Application E2E Journeys (`@playwright/test`):** Full end-to-end user journeys under `packages/ui/e2e/**/*.spec.ts` against built web SPAs and production server containers with real MongoDB instances or isolated SQLite lite mode (`authBackend: "sqlite"`, starting no MongoDB container). Includes root cutover journey `packages/ui/e2e/os-cutover/os-cutover.spec.ts`.
- **Deterministic Auth Seeding:** Application E2E tests bootstrap sessions using the canonical `application_e2e_seed` tool (supporting both MongoDB and `--sqlite-path` / `DAM_HOPPER_AUTH_SQLITE_PATH`) and browser `storageState`, preventing test coupling to login UI flows. `--no-auth` must not be used for authenticated application journeys.
- **Visual Evidence Capture Policy (`capture-policy.ts`):** E2E evidence must capture the complete viewport (1440x900 default, 320px narrow dock), validate PNG IHDR dimensions, and colocate machine-readable `evidence.json` and human `review.md` records in `packages/ui/e2e/<case>/`. Visual capture is disabled by default in CI (`CI=true` / `E2E_CAPTURE=0`) for functional parity without artifact bloat. Green automation certifies behavioral assertions only and does not bypass mandatory human visual review; review ledgers across `os-cutover`, `os-recipes`, `os-lifecycle`, and `host-auto-sleep` preserve authentic `PENDING_REVIEW` status pending operator visual inspection.
- **Version Alignment (9-Location Invariant):** Repository version bumps require synchronizing 9 distinct release locations across Cargo manifests, npm manifests, installer scripts, smoke tests, and the server lockfile (`server/Cargo.lock`), managed by `scripts/bump-version.mjs` and verified by `node deploy/release/check-version-alignment.mjs`. (The obsolete 13-location Tauri/native manifests were pruned in Phase 02).
