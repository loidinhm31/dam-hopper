## Open qualification gates

- **TypeScript and JavaScript LSP semantic navigation:** Phases 01–09 complete (Phase 01 real-process spike, Phase 02 LSP framing and child owner, Phase 03 pinned tool provisioning and resource controls, Phase 04 semantic session supervisor, Phase 05 authenticated semantic WebSocket gateway, Phase 06 admin-only global hot toggle, Phase 07 shared Monaco semantic client and navigation, Phase 08 lifecycle invalidation and recovery, Phase 09 security, real-process tests, and performance qualification; qualification report `plans/260901-1000-lsp-server-integration/reports/phase-09-qualification-report.md` records all predeclared budgets satisfied with wide margins and `PASS_PORTABLE_ONLY` disposition; reviewer Cycle 1 scored 6/10; user approved on 2026-10-24). Remaining qualification gates: Phase 10 actual built web application qualification journeys and human visual review with fresh non-sensitive captures, followed by Phase 11 release documentation and cleanup. Tracked items for subsequent hygiene include W1 (semantic WS handshake auth lookup timeout wrapper under simulated WAL lock), W3 (starttime-guarded descendant reap to avoid PID recycling false positives), and M1–M5 code improvements. Implementation is in progress under [LSP server integration plan](../plans/260901-1000-lsp-server-integration/plan.md) with 236/264h planned effort accounting (89.4%). Phase 10 (Linux server + actual web qualification; native deferred) next. Runtime ships default OFF, restricted to Linux server + web client with bundled Node/TS/TSLS tuple and admin-only controls; native desktop remote qualification and Windows/Android remain deferred and nonblocking.
- **Application E2E workflow gaps (P1/P2):** While the 4-tier testing runner architecture, container runtime, and three foundational journeys are delivered, documented workflow gaps remain open for application-level Playwright coverage (see [Testing guide](./testing.md#ranked-integrated-workflow-gaps)): P1 docked/split/mobile layouts, multi-profile/project switching, persistent settings & full policy editing, terminal & workflow continuity; P2 file editing & Git mutations, media sessions & token revocation, and native desktop host & WebView2.
- **Host-resource SSE:** the implementation is documented, but deployed-proxy identification/verification, target-host CPU/RSS and soak evidence, live-browser qualification, and native C42 remain pending or blocked. Do not treat implementation completion as release qualification. See [SSE architecture](./architecture/host-resource-sse.md).
- **Windows native workbench:** Windows S13 runtime qualification is separate from the completed web/Linux shared workbench evidence.
- **Browser child WebView:** Windows v1 is documented as supported; Linux child/relay runtime behavior remains unverified. See [Native Browser Debug](./native-browser-debug-support.md).
- **Agent provider/platform coverage:** existing Linux qualification applies only to the documented OMP, Codex, and Claude versions; no broader provider-version or non-Linux runtime qualification is implied.
- **Git conflict resolver platform qualification:** Phases 01–08 complete; Phase 09 automated test suites, browser Chromium component suites, and live-daemon functional smoke testing delivered (54/54 assertions across primary and nested repositories; linked worktrees verified by integration tests). Initial production release remains blocked pending AC12 actual Linux-native host launch, fresh local captures, human visual review, and resolution of Cycle 2 review items (W2/W5 layout test depth, W6 deferral recording). Windows-native client qualification remains explicitly unqualified and separately pending (nonblocking).
- **Device login management human visual review:** Backend, frontend unit/integration, browser runner, container E2E journeys (11/11), and live runtime cutoffs (WS 4401 at 4,990 ms, SSE at 4,991 ms, media stream termination) passed with both round-2 independent code reviews approved. Release qualification remains blocked pending human visual review of narrow (320x667) and desktop (1440x900) UI checkpoints recorded in `packages/ui/e2e/device-login-management/review.md`.
